工具注册、可调用工作流与模型选择范围

版本LIVE-REVIEW-ENG-1.0。本稿中的函数、ToolSpec、工具及流程均待实施；已有voice／prelive接口由适配器调用，不重命名成假装存在的Review接口。

1 一个注册器生成全部入口

ToolSpec放policy.py／tools.py共享的registry中，每项包含name、args_model、result_model、roles、effect、capability_requirement、timeout、idempotency、handler、public_label。注册表同时生成模型schema、role allowlist、调试名称、契约检查和文档清单。Skill中提到的工具必须能从registry解析；构建时检查缺名、重名、角色错配。

模型工具函数使用LangChain ToolRuntime注入可信ReviewScope；account_id、role、grant、run等不作为模型参数。Scope Middleware检查后，普通服务仍核对象归属与引用；不能只靠提示词声称只读。

效果分三类：read_business（读事实），analysis_local（计算／缓存／草稿与报告落本次Review库），human_business（采纳关联下一场）。主／子只有前两类；human_business只在人工API控制器，不放入模型工具列表。

SDK_TOOL_POLICY与业务ToolSpec一起组成最终allowlist：主图task仅content_review／commerce_review，子图不注册task；read_file／ls／glob／grep只允许/skills、受控history及scratch虚拟空间；write_file／edit_file只允许scratch；显式SDK TodoList的write_todos只更新计划；execute／delete从FilesystemMiddleware的tools配置排除，并在dispatch兜底拒绝。仅使用StateBackend不会自动移除execute／delete的schema。构建时对最终ToolNode清单断言：每项必须匹配业务registry或SDK_TOOL_POLICY，额外工具即构建失败，不能统一放行SDK来源工具。

F01–F05同样通过ToolSpec注册为真实模型可调用工具，具有args_model、role、effect、handler和结果schema；不是仅写在Skill里的伪入口。共享handler复用原子服务，不通过再调用一次模型来“执行流程”。主图有F01–F05；内容子可选F03，经营子可选F02／F04；F05只属主。F05既能带草稿一起提交，也能传已验证draft_ref做一调交付，均走同一个finish服务与非direct完成门。

2 统一ToolResult与错误

ToolResult[T] {
  schema_version, call_id, run_id, tool_name,
  outcome: completed|partial|waiting|needs_input|blocked|failed|unknown,
  commit_state: read_only|not_committed|committed|unknown,
  data: T|null, artifact_refs: SourceRef[],
  missing: MissingItem[], next_reads: ExactReader[],
  job_ref: ReviewRef|null, retry_after_ms: int|null,
  error: {code, message, retryable, safe_details}|null,
  timing_ref, origin: new_computation|cache_reuse|human_import|legacy_unknown
}

completed只说明本次工具完成，不代表整个用户Goal完成。waiting必须有真实job_ref与可靠唤醒入口；unknown是已发请求可能生效、当前不能确认，不能等同failed。HTTP／SDK错误适配为同一语义，不能HTTP200下错误体被UI记成功。

ExactReader={tool_name,typed_args,source_ref,view_id,coverage_requirement}；模型可以直接使用，不用猜某个嵌套JSON路径。读取记录保存实际交付的范围与hash；“已读”“已理解”“已核验”“正式提交”分别记录。

错误码含义正确续办
INVALID_ARGS／MAPPING_REQUIRED明确未提交，缺字段／口径未选返回具体字段、合法枚举或确认卡，不抛整任务失败
REF_NOT_FOUND／STALE_REF引用不存在／版本变化回读当前受权快照和差异，模型重评，不能猜ID或覆盖
SCOPE_DENIED／SOURCE_HASH_MISMATCH越权或证据篡改blocked，不作为可补参数错误吞掉
METRIC_NOT_ELIGIBLE／COHORT_MISMATCH／UV_NOT_ADDITIVE数据资格或统计范围不合格给原计数／缺项，保留null，不要求模型修出一个数字
SOURCE_GAP／CURSOR_EXPIRED源端不可重放或游标已过期标缺口、给可用快照；UI补发不是原数据补齐
VERSION_CONFLICTCAS失败返回实际版本和受影响对象，保留已完成独立产物；不自动覆盖
PROVIDER_NOT_SENT／TEMPORARY_READ_FAILURE明确尚未发模型或只读临时失败同逻辑操作有限重试，累计计时与共享预算
PROVIDER_RESULT_UNKNOWN／HANDOFF_UNKNOWN已发送、未获可靠终态保存request／operation ID并对账；不能换key盲重试
OUTPUT_INVALID／REPORT_INCOMPLETE返回已收到，但结构／必要目标缺项保留安全响应与用量；有限局部纠正，不重做有效分支
BUDGET_EXHAUSTED／CANCELLED没有可用预算或任务取消停新请求；交付已有结果和明确未完项，不造完成

同一个handler由原子工具与组合flow共同调用。示例：get_metric_panel和build_module_panel遇相同cohort错误必须同code、同commit_state，不能一个抛异常另一个“自动修好”。

3 原子工具的精确计划

所有工具输入中的Ref必须完整版本化；范围默认为可信scope内，不能默认为全店历史。每次读取都有limit／continuation与覆盖说明。下面秒数为初始本地执行超时配置，待性能验收调整，不是实测速度保证。

K00–K12给主Agent，其中K09含成本模型工作，必须经同provider账本；内容子Agent仅K01、K03–K06、K09、K13；经营子Agent仅K01–K04、K06–K08、K13。分类从content子内调用不允许再无限递归委派。各角色另有本节SDK_TOOL_POLICY允许的工具，宿主shell／任意SQL／HTTP不开放。

K00不是固定首步骤。API已冻结Goal时可直接任意调查；自由对话的provisional Goal允许先用K01／只读证据了解对象，尚未冻结时成本模型分类、正式计算和交付返回TASK_ASSESSMENT_REQUIRED＋K00精确入参说明。F01可携带同一typed task_assessment并复用K00服务一次冻结再组上下文，所以不强迫多一轮。新目标改变必须显式新修订；普通重新读证据不改变Goal。

ContentAssessmentInput含subject／原文／事实／本场／政策refs、四个明确criterion_id、rating=0或0.5或1或null、各项公开reason／证据和critical_findings。模型给判断，程序只做一次必要结构／引用／枚举检查和公式计算；不让模型自填最后总分。报告可引用已存assessment；要求reanalyse_content时须本次新判断及对应attempt_ref，不得贴旧ref完成。完整四项标准见07；本机制不生成或改写直播话术。

4 五个可选工具流的内部步骤

F01 prepare_review_context

签名：(goal_ref, focus?, evidence_budget?, task_assessment?)→ReviewWorkset。既有scope已有原目标／归档；provisional Goal若带assessment先走K00同服务冻结；没有必须的数据返回needs_input，不自造绑定。

步执行动作输出与缓存
1读目标、固定归档、版本与授权；核是否取消authoritative goal／scope，不复制历史任务全文
2读场次能力、gap与实际稿件／商品清单capability summary、origin和时间精度
3读当前已完成导入、指标、分数、草稿、专题产物索引精确refs和状态，一次到位；不能靠“最新作业”漏掉另一个任务
4按focus和预算取首屏关键事实／所需正文，完整项优先delivered／not_delivered清单，精确next_reads；不声明未读内容已审核
5保存workset hash、读取覆盖与使用的实际依赖可重复复用；除显式task_assessment冻结外不改变Goal或业务事实

该flow不自动派子Agent、不强制全文扫描、不默认重跑全部指标。它解决的是“已知事实和结果在哪里”，不是替模型决定下一步调查什么。

F02 build_product_panel

签名：(archive_ref, product_ref, metric_profile, include_content=false)→ProductPanel。

  1. 核产品在本场真实快照／授权映射中；区分当前商品库新修订和本场当时版本。
  2. 获取相应官方汇总或订单cohort，映射完整性、币种、订单粒度和as_of同时交付。
  3. 只算该profile所需指标与评分；命中合法缓存即复用，origin明示。
  4. 联合实际出现次数、时长、价格／投流／库存场记以及已分类顾虑；没有分类结果不制造“0疑问”。
  5. 一次返回面板、缺项、原稿／原行／主题展开reader，可选交付本次完整需读正文。读到商品B作背景不能让主Agent把B列为用户要求的修改对象。

F03 build_module_panel

签名：(archive_ref, product_ref, module_keys[], opening_mode?, window_profile, content_budget)→ModulePanel。

  1. 从真实队列和PlaybackSegment选择发生次数；native模块与derived标签分列，长短开场分开。
  2. 计算已确认媒体播放的区间并集、定位覆盖与平台／事件时钟误差；资格不足即保留事实不评分。
  3. 用固定主窗计算纯关联与mixed；无去重明细时跨分钟UV只逐桶展示。
  4. 按确定性profile取响应指标；评论密度要求选定范围内完整分类及核准在线分母，代表评论仅作解释，不能替代完整计数。
  5. 读取／复用按所有实际依赖冻结的ContentAssessment；没有时返回pending_assessment_requirements和精确原文reader。主可在K10／F05直接提交判断，或选择内容专题在K13提交；K09仍只分类评论，F03不暗调固定审稿模型。
  6. 返回四项内容分、可用响应相对分、样本／缺项、关键原句和证据索引；不把内容87.5与经营48平均成“总体不错”。

F04 compare_compatible_history

签名：(target_metric_refs[], comparison_spec, policy_ref)→BaselineAndComparison。

  1. 冻结历史可见截止，排除当前场；按同商家／商品／定义／来源／成熟度筛选。
  2. 报价差、付费流量、时段、开场的已知条件按政策核对；未知重要条件显示不可比，不为凑数量混入。
  3. 整场至少5场、模块专项至少10次且3场；不足返回facts_only，不报无限提升。
  4. 保存中位数和全部入选／排除ref，正反向与比例上限显式映射；可比性与统计不确定性分别输出。
  5. 如选择统计比较，先核抽样／聚类单位再算；不能因为存在统计库就默认每分钟独立。多版本结果标探索，不自动改播前。

F05 package_review_delivery

签名：(goal_ref, draft_content:DraftInput或draft_ref:ReviewRef（二选一）, scorecard_refs, expected_run_generation)→DeliveryReceipt。DraftInput含K10同一content_assessments[]。

  1. 调用与K10相同的draft服务存内容；安全响应已在模型返回处归档，不在本flow重新调模型。
  2. 执行与K11相同的原Goal／数据资格／数字／引用／版本检查，局部失败返回准确missing和可续办reader。
  3. 目标满足则提交正式报告和delivery_ref，同事务更新run终态和进度；用户要求全经营但缺表时只能partial／needs_data，不能偷改Goal为互动成功。
  4. 返回实际ref、公共完整交付说明和应用终态，由02的before_model持久回执门结束；不使用return_direct，不再单独调用finish_turn写一轮计划结束。
  5. 若请求只是回答某问题／重算某分，按对应Goal类型提交AnswerArtifact／Scorecard，不强迫生成整本报告。底层终态仍只由同一个finish服务判断。

同一flow可被模型任意选用或跳过。flow不隐含“下一flow必跑”；数据依赖只决定某个工具是否具备资格。

表中一行多ID只是并列定义，不表示合成一个统计函数。实施时每个ID有独立spec、unit、允许dimension、data requirement、计算函数和反例fixture；可以批处理共用一次底层扫描，但不可只因同名字段共用不同语义公式。

6 模型任务与有限停止

系统提示词只定义目标、数据不可信边界、工具选择原则、禁止写入、证据引用和完成方式；不塞整张统计教程、所有历史问题和全量表格。Skill承担详细方法，正式索引承担当前事实，工具承担机械执行。

正常调查可追加新的问题和工具调用，重复读取本身不一刀切禁止；同tool＋参数hash＋相同依赖版本且没有新增证据时，第一次提醒已有结果与reader，连续再次无进展返回no_new_information并建议缩小范围／结束有限结果。模型给出“要读另一个view／核关键反例”就允许，不用固定路线替它规划。

异步导入／重算未完成时保存真实job＋WaitReceipt，02控制门停止本次图invocation，应用保留WAITING_JOB；协调器从持久Inbox取job完成事件后，用有界ResumeObservation续办，不以graph返回推断目标完成。JobStatus=QUEUED／RUNNING／SUCCEEDED／PARTIAL／FAILED／UNKNOWN／CANCELLED，DTO含job_ref、operation_key、scope、input_hash、result_refs、error、attempts、generation和时间。GET /review/v1/jobs/{id}给UI／恢复协调器；K01的jobs视图可供模型针对性核查，但正常等待不轮询。各flow使用同一submit_or_join_job，重复请求不启动第二份计算。用户新消息、取消和数据修订都产生独立可恢复事件，不能把旧run静默继续到新archive。
