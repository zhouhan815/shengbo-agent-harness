5 主Agent、子Agent与程序怎样分工

执行者输入自主选择可以产生的结果实际权限
主复盘Agent用户目标、固定归档修订、能力与指标索引、历史／政策引用查哪个商品／模块、是否追加证据、何时委派、是否需要对比或小实验建议Findings、报告草稿、建议候选、待补数据问题只读业务事实；写本次草稿／待确认问题；可完成本次Review，不可改直播
内容专题指定问题、同归档、精确稿件／事实／评论引用、子预算查原句、主题、反例、表达与内容四项评分结构化子报告、证据引用、未知项不可交付主报告、不可采纳或改稿；只读指定范围
经营专题指定经营问题、同归档、指标／基线／报表口径、子预算分解漏斗、核退款龄期、选择可比对照经营发现与替代解释不可自行改计分公式、目标、原单或优惠
确定性服务版本化参数与可信scope无业务语义自我规划可靠数据、计算、资格、可恢复作业、正式回执通过明确API执行；不调用模型来判断加减乘除
人工控制器登录身份、显示过的确认卡与选项选择补数据、处理歧义、采纳建议、选择下一场已确认映射／采用决定人工授权业务动作入口，不通过模型自报身份取得权限

主Agent可以一次调用两个task并行调查内容与经营；共同读取同一不可变归档，子结果各自落独立草稿。主Agent合并冲突，不让两个子Agent同时写同一报告正文。简单目标如“看本场净额达标没有”不固定委派，也不强制做评论分类。

6.1 缓存许可与真正重算分别如何证明

Goal.refresh_mode枚举：reuse_valid（默认可复用未变依赖）；recompute_metrics（指定指标／评分重新执行，原件解析可复用）；reanalyse_content（指定内容评级／评论标签重做模型判断，原件与无关统计可复用）；refresh_all（本Goal范围所有请求的分析计算重做，不代表重抓历史平台数据）。required_calculations逐项冻结对象、计算类型与义务，不能把“重新复盘”解释为改标题后返旧报告。歧义由K00给合理解释和公开说明，语义实质不清时用K12问，不靠正则静默决定授权。

每个calculate／score／classification／assessment执行或复用均产生CalculationReceipt。recompute_metrics复用原件reader不违约，但直接返回旧score违约；reanalyse_content不得复用旧assessment，主或子本次生成的四项判断带当前attempt_ref。报告完成服务逐项验证required_calculations已有符合origin的receipt，读取旧卡片不能消除义务。新依赖强制换cachekey；重复相同逻辑操作的重试仍幂等回同一次执行，不能为“重算”双扣费用。请求未要求重算则合法复用，减少无用重复。

7 缺失、资格与敏感性

公开人数字段目前verified=false，核对前只显示候选数，不计算人分钟响应分。评论主题只分析已读取／已覆盖的范围；抽样标签不能把未分类评论当无意向，也不能除全场人分钟得到伪全量密度。

情况结果
无业务报表business_outcome=undetermined；可完成interaction_only复盘；不将null变0
只有整场／商品汇总整场／商品数值与评分；不强分给每次稿件出现
分钟桶跨模块mixed；不按秒拆UV／订单；即使纯桶相邻也先核跨桶去重能力
只有接收时间且传输滞后无界只本地接收共现；平台声音延迟标定不等于事件延迟也已测好
某评分分母不足／历史不足保留事实、样本和missing_reason；不把剩余项加权重标为100
模拟样例或混入synthetic真实经营结论受限，不能声明实际达标；试验与真实档案分开
已取消后迟到结果usage和原件仍保存，run不恢复RUNNING／COMPLETED，不触发采纳

预注册评论主窗30秒、敏感性15／60；商品付款探索0–5分钟、敏感性1／3／10。对正式成交总量一单只记一次；不同探索窗不相加。Wilson只用于合法二项计数；退款金额率与相关人分钟密度不套Wilson。样本／区间与得分分开展示，分数不是因果概率。

8 一致性及迁移要求

迁移使用独立Review migration版本号，新增voice outbox／journal表前备份及验证，不改旧prelive表语义。升级只增加向后可读字段时写兼容适配；关键语义改变给新schema_version并按fixture比较，禁止默默accept any dict。

每次新归档／报表mapping／评分政策产生新引用与lineage，不在旧报告里换数据。用户删除／撤回证据后保留最小审计状态并撤销相应可访问投影及缓存；不能借旧摘要继续引用已不可访问原件。保存和清理均为普通服务管理，模型没有任意文件删除权。

6 完成路径：成功少一轮，错误仍能修正

实际SDK假模型测试发现：普通工具返回Command(goto=END)仍可能进入下一轮模型；return_direct=True会让错误结果也直接结束。最终统一采用非direct工具＋before_model持久回执门，不能在实现时随手换成上面两种写法。

finish_review(args, runtime):
    receipt = delivery_service.commit_or_reject(args, trusted_scope)
    # 非direct普通工具；错误为可读的结构化ToolMessage
    return Command(update={delivery_ref: receipt.ref,
                           messages: [ToolMessage(匹配tool_call_id的正式回执)]})

ReviewCompletionMiddleware.abefore_model(state, runtime):
    receipt = control_service.find_valid_receipt(trusted_scope, frozen_goal_hash,
                         full_dependency_fingerprint, invocation_generation)
    if receipt是合格完成回执且未取消:
        return {delivery_ref: receipt.ref, jump_to: 'end'}
    if receipt是有效WaitReceipt:
        return {wait_ref: receipt.ref, jump_to: 'end'}  # 不是COMPLETED
    return None

错误分支不填正式delivery_ref，不改run COMPLETED；模型收到错误可以补缺／修正。成功不另调一个模型写总结；finish.public_summary直接绑定正式refs作为对话交付。终态工具必须是本条AI消息唯一工具调用，批量混用返回需纠正，防止并行任务未结束就提交。

完成回执的唯一身份包含account／run／role／delegation（主为null）、完整冻结Goal hash、archive及实际dataset／metric_definition／score_policy／baseline／as_of依赖、required_calculations的执行回执与run generation。主Delivery与子SubReview分命名空间；子完成不能关主图，旧政策／旧目标／另一角色的成功不能复用为本次完成。CalculationReceipt中的new_computation／cache_reuse必须符合Goal.refresh_mode；只换标题或created_at不能算重算。

WaitReceipt={run_id, invocation_id, role, delegation_id?, goal_hash, archive_ref, generation, kind:input|job, decision_ref|job_ref, pending_tool_call_ids, status:active|consumed|invalidated}。K12和异步K02/K08/F流只在保存真实decision／job后提交等待。先收齐本条AI消息其余并行调用的结果再停，未完成的子任务引用由协调器保留；不能把一个早返回的waiting吞掉另一工具的结果。before_model查持久等待回执并jump_to=end，Runtime将invocation标suspended，ReviewRun仍WAITING_INPUT或WAITING_JOB。UI答案／作业完成写持久Inbox，单owner原子消费；核Goal及archive未变、旧wait已consumed后，同thread新invocation附有界ResumeObservation继续。没有持久唤醒事件则不自动轮询；预算耗尽／取消仍优先停止，已正式COMPLETED不能被再唤醒。

外层runtime.invoke_run必须用try/finally绑定可信ContextVar（run／role／budget／invocation），覆盖整个graph.ainvoke，包括SDK Summary直接发起的模型请求；子wrapper在该上下文内派生，K09分类同样继承。provider工厂按用途注入共享ledger，不靠只观察主模型middleware估计摘要费用。释放token不能提前到模型流尚未结束；scope缺失时provider拒绝发送，而非回落无限预算。

完成／等待门和Scope门不能互相抢先：可信合法回执先走无新副作用的控制短路；只在确实继续工具或模型发送时检查可执行租约。不能因finish已写COMPLETED而被另一个Scope前置门当“非RUNNING”误拒，导致成功变失败。实际hook组合顺序用05假模型用例锁定，不只凭列表排列推测。

本轮纯假模型探针：正常完成1次模型；先REPORT_INCOMPLETE再修正2次；参数类型非法后修正2次，均无额外第3次收尾。它只核验SDK控制机制，不代表新Review业务终态服务已实现。

若模型没有调用finish就自然输出“已完成”，aafter_model只在无tool calls且无任何合法完成／等待回执时，预算内给一次带准确missing的短系统纠正消息并jump_to=model（用对应hook_config声明）；没有对应tool_call时不得伪造ToolMessage。仍不提交则Runtime保存可用草稿并标PARTIAL／FAILED及原因，不写COMPLETED。正常成功已经由before_model止住，不会触发这条补救多付一轮。不能把这条规则扩成每份报告再请模型“全面自检”。

部分交付也必须有正式DeliveryReceipt，带outcome=partial、原Goal及未完成项、停止原因；控制门允许结束invocation，ReviewRun保持PARTIAL，UI不显示完整完成。只有必要交付全部满足才COMPLETED。原目标缺报表时可以申请等待或交有限报告，不能偷偷改成interaction_only后算完成。Provider结果未知由Runtime停止新的成本动作并标RECONCILING，先查原attempt；若无供应商查询能力则保留unknown与待决，不用换新request ID自动补调。

METRIC_NOT_ELIGIBLE／COHORT_MISMATCH／UV_NOT_ADDITIVE数据资格或统计范围不合格给原计数／缺项，保留null，不要求模型修出一个数字

VERSION_CONFLICTCAS失败返回实际版本和受影响对象，保留已完成独立产物；不自动覆盖
PROVIDER_NOT_SENT／TEMPORARY_READ_FAILURE明确尚未发模型或只读临时失败同逻辑操作有限重试，累计计时与共享预算
PROVIDER_RESULT_UNKNOWN／HANDOFF_UNKNOWN已发送、未获可靠终态保存request／operation ID并对账；不能换key盲重试
OUTPUT_INVALID／REPORT_INCOMPLETE返回已收到，但结构／必要目标缺项保留安全响应与用量；有限局部纠正，不重做有效分支
BUDGET_EXHAUSTED／CANCELLED没有可用预算或任务取消停新请求；交付已有结果和明确未完项，不造完成

同一个handler由原子工具与组合flow共同调用。示例：get_metric_panel和build_module_panel遇相同cohort错误必须同code、同commit_state，不能一个抛异常另一个“自动修好”。

6 模型任务与有限停止

系统提示词只定义目标、数据不可信边界、工具选择原则、禁止写入、证据引用和完成方式；不塞整张统计教程、所有历史问题和全量表格。Skill承担详细方法，正式索引承担当前事实，工具承担机械执行。

正常调查可追加新的问题和工具调用，重复读取本身不一刀切禁止；同tool＋参数hash＋相同依赖版本且没有新增证据时，第一次提醒已有结果与reader，连续再次无进展返回no_new_information并建议缩小范围／结束有限结果。模型给出“要读另一个view／核关键反例”就允许，不用固定路线替它规划。

异步导入／重算未完成时保存真实job＋WaitReceipt，02控制门停止本次图invocation，应用保留WAITING_JOB；协调器从持久Inbox取job完成事件后，用有界ResumeObservation续办，不以graph返回推断目标完成。JobStatus=QUEUED／RUNNING／SUCCEEDED／PARTIAL／FAILED／UNKNOWN／CANCELLED，DTO含job_ref、operation_key、scope、input_hash、result_refs、error、attempts、generation和时间。GET /review/v1/jobs/{id}给UI／恢复协调器；K01的jobs视图可供模型针对性核查，但正常等待不轮询。各flow使用同一submit_or_join_job，重复请求不启动第二份计算。用户新消息、取消和数据修订都产生独立可恢复事件，不能把旧run静默继续到新archive。

1 服务挂载与安全边界

现有声播8765接收浏览器同源请求/api/review/v1/*，桥接到既有Agent8791的/review/v1/*。Agent app启动增加ReviewRuntime生命周期，独立review DB／checkpoint、作业和trace命名空间；不向浏览器发送服务令牌，不借18791授权测试页作推理base_url。

实际Agent挂载入口是src/shengbo_prelive/api.py:create_app及其lifespan（本机75／92行附近），由src/shengbo_prelive/__main__.py启动；W4通过集成者在该app挂Review router／资源，不能假定另有http_api.py。voice的server.py由W1接点owner统一合入bridge挂载，避免多窗口各改启动生命周期。

Review初始化失败显示feature_unavailable及可重试状态，不能阻止原声播和播前可用。重型报表读取／计算off-loop；浏览器SSE断开只断展示，不能关闭共享HTTP transport或中断后台run。应用关闭按各资源owner释放引用，不让Review关闭播前资源。

2 请求与响应合同

5.3 初期目标和失败解释

  • 正确性目标：fixture预期事件集合去重后100%可核；所有不能恢复的缺口100%显式列出；R中的数值断言100%匹配；不泄密、无未经确认直播写入。
  • 调查效率目标：已就绪成果不重新付费生成；成功finish不多一次模型；人工/job等待不轮询模型；同依赖缓存命中可复用；无信息重复有界纠偏。
  • 时间优化目标：小型资料就绪到复盘交付尽量接近或低于600,000ms，同时披露质量/覆盖；这是待测优化目标，不是SLA，也不为达标取消必要事实/报告范围。
  • 源摄入可设单独本机压测profile，例如100事件/秒持续60秒，记录p50/p95写入/消费滞后、峰值队列与封存耗时；该profile是工程提议，必须记录机器和磁盘条件，不冒称真实直播流量保证。
  • 三次真实任务只能报告min/median/max、每次明细与达标次数；样本仅3次不估可靠p95或声称提速有统计显著性。若要比较旧/新方案必须同fixture、同缓存、同模型/设置、同构建范围；旧播前11分钟等不能直接当新复盘的基准。

4.1 主题分组与抽样的硬边界

  1. C01主题组依据既定政策按“场次化用户键＋商品＋主题＋同一次模块出现”合并；同用户刷屏不能制造多组，不同真实主题不因同正文模板全部误删。未知用户/未知商品保留unknown并报告，不能强行补ID以满足分母。
  2. 模块意向密度要求选定有效时间范围内的全部已归档评论完成分类，并匹配相同在线有效区间。仅取代表性50条供阅读时，不能拿这50条里的正意向除全场人分钟。当全量仍有未分类，应显示已有主题、实际覆盖和CLASSIFICATION_PARTIAL，或显式缩小到完整处理的区间。
  3. 50条是首轮人工标签抽查量，并非把统计总体缩成50条。样本不足50就全查；商品归属accuracy目标90%，意向precision目标85%，显示TP、FP、正预测数和抽样方案。零正预测precision=null；正预测不足10标尚未验证，必要时另抽分层样本，不悄改全量标签计数。
  4. 人工审核和模型自报confidence分开；不会拿confidence≥某值就替代precision。达到初轮目标也不表示全部未来场次都可靠；分类器/prompt/商品上下文变更保存新版本和复核范围。

7 分数映射：每个分段、上下限与例子

7.1 经营目标G

attainment=X/G；score=min(100,max(0,100×X/G))，G必须>0且同口径。actual_completion保留未封顶百分比、差额；净额目标不拿实付实际值去比。目标事后修改创建新GoalSnapshot，旧目标90分不被新目标静默替换成100。

输入score仍需显示
X=900元、G=1000元90完成90%，差100元；as_of净额而非利润
X=1200元、G=1000元100实际120%，超200元
合格真实X=0，G=10000真实零、原始来源与范围
G=0/缺G、X缺来源null缺项；不将无目标或缺经营等于零成绩

7.2 越高越好S↑

B>0、X≥0。r=X/B：r≤1时S=60r；r>1时S=min(100,60+80(r−1))。对应r=0/0.5/0.8/1/1.25/1.5→S=0/30/48/60/80/100。未封顶提升比例继续显示。

有上界U的率：若1.5B>U，取T=min(1.5B,U)，高于B部分用 60+40×(X−B)/(T−B) 封顶100；低于/等于B仍60X/B。B=U时历史正向分null并说明已达上限。率内部U=1，不写成100后又除一次百分号。

7.3 越低越好S↓

B>0。0≤X≤B：S=100−40X/B；X>B：S=max(0,60−60(X/B−1))。历史退款率10%时，本场0/5/10/15/20%→100/80/60/30/0。零退款观察短/样本少必须暂定；B=0不除0、不自动编无限改善分。

60只表示商家自己的可比历史持平，不表示行业及格。S↑、S↓、G与内容分均不叠加成总分；题材、流量、价格、退款龄期不同也不能用相同百分比随意比。

9 语音时间线、反应窗口与数据资格执行

  1. 原稿坐标固定到publication→queue occurrence→product/script/module/sentence→attempt/segment。确认playing区间并集是媒体播放证据，不是平台听到证据；muted/volume、本机输出与平台回听另记。
  2. 平台音频延迟至少用5个分布在开/中/末的标记形成保守区间/误差并观察漂移；这只是初始标定量。互动事件运输延迟另核，不能用推流延迟替代。
  3. 保留发生时间精度，不能将秒/分钟补零变成毫秒真值。仅接收时间且运输滞后无界，只能作接收时共现，不能通过strict模块时间资格。
  4. 本地模块[s,e)、事件可能区间[u,v]、推流延迟[d_low,d_high]、反应[0,R]，相关内容范围为 [u−d_high−R,v−d_low]。整个范围落入同一实际模块/可播segment才pure；否则mixed/unassigned。主表同事件至多一个严格归属。
  5. 评论主反应窗30秒，敏感性15/60秒；付款只在商品出现的0—5分钟探索，敏感性1/3/10分钟。每种窗口独立结果不累加订单，不把时间邻近称因果。窗口结果反转降为不稳健候选。
  6. 延迟边界宽度>5秒默认不做细句精细排名；这指不确定范围宽度，不是要求平台总推流延迟<5秒。10秒句＋30秒反应窗天然跨多句，大多数情况下句子只展示原文/播放量/邻近事件，不能强给GMV分。
  7. Q01≥98%、Q02≥98%、Q03≥99%只是进入相应整场模块分析检查，Q04/纯窗口/在线口径/分类/分母/基线仍须通过。分钟桶跨段不按秒拆订单/UV；即使多个纯桶全在同模块，UV仍不可无依据相加。

这些步骤属于普通时间线/统计工具固定内部算法。主Agent可以选择商品面板、只调查某段、改看反例或放弃无资格指标；不规定全局必须从开场到促单顺序分析，也不把所有指标/子Agent固定必跑。
