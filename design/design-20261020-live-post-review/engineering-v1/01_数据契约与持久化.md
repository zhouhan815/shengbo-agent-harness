# 数据契约、归档、报表与评分持久化

工程版本LIVE-REVIEW-ENG-1.0；以下为拟实施接口。目录前缀：Agent工程的src/shengbo_live_review/；voice前缀指ecommerce-voice-agent/app/。本稿不执行迁移或业务写入。

## 1 先收口已有草案的格式差异

| 当前差异／事实 | 本次开发唯一规则 | 代码位置／验收 |
| --- | --- | --- |
| 上级基础Schema用对象ArtifactRef，评分Schema的ref仍是演示字符串 | 正式DTO统一ReviewRef对象；旧字符串只在演示fixture适配器解析已登记ID，不按字符串猜文件路径 | shengbo_contracts/live_review.py；legacy_fixture_adapter只在verification使用；R01 |
| 上级来源名public_platform／official_merchant_export与评分样例public_interaction／authorized_business_export不一致 | 统一SourceKind为public_platform、local_player、official_merchant_export、manual_note、synthetic。显式映射旧两种别名；禁止到各函数再写兼容猜测 | contracts及migration适配器唯一转换；R01 |
| 文档LIVE-REVIEW-1.1、基础草案Schema1.0、计分政策0.1职责不同 | 新实现的wire schema明确LIVE-REVIEW-1.1；score.policy_version独立仍LIVE-SCORE-0.1；来源voice契约仍PRELIVE-2.3 | DTO导出schema后供工具、API、UI同用；既有草案保留并标superseded |
| 旧common.same_artifact_ref只接受PRELIVE-2.3 | Review有自己的same_review_ref／resolve_ref；不能把Review引用塞进PRELIVE-only比较器 | 跨服务只通过feedback适配层投影和得到真实voice recap_ref；R02 |
| 字段看似同义：人数、次数、条数、金额、订单粒度 | 每个字段有unit、grain、source_definition、nullable_reason，未知保持null | 字段映射确认后才计算；不靠LLM给未知列起一个熟悉名字 |

Ref约定：ReviewRef={kind,id,revision≥1,content_hash:'sha256:…',schema_version:'LIVE-REVIEW-1.1'}。VoiceRef保留原PRELIVE-2.3原件；voice普通RecordRef并不总含schema_version，由VoiceRefAdapter按接口的真实DTO解析，不能往原件伪添字段。跨系统引用使用SourceRef={source_system:'review'或'voice',ref:ReviewRef或VoiceRef}，判别与校验由source_system决定；任何Ref解析都再核account和授权对象，hash相等不代表有权限。content_hash只哈希规范化业务body，不包含自身ref／hash或展示时间戳，避免自引用无法稳定计算。

统一UTC带偏移ISO发生时间和received_at；存储整数毫秒便于排序，显示Asia/Shanghai。源时间为秒／分钟就保留precision与uncertainty，不通过补零制造毫秒精度。单调时钟只在同source_instance＋boot_id内算时长，不能跨重启相减。

金额全部用int minor：900元CNY存90000、currency=CNY、exponent=2；数量、父订单、SKU子单、买家UV各有独立unit。decimal解析字符串，禁止float乘100直接入账；空白、破折号、不可解析和真正0分开。

## 3 存储表、键与事务

复盘事实、草稿、任务和trace放独立review.sqlite3，WAL＋单writer短事务，读取走受限查询；checkpoints.sqlite3独立，不声称跨库同事务。大文件放内容寻址artifacts/，先临时写入＋fsync／原子rename，再提交元数据引用；崩溃遗留孤儿可审计清理，不将未落盘文件标可用。

| 表／索引 | 主键／唯一约束 | 关键字段与事务边界 |
| --- | --- | --- |
| review_sessions | PK(account_id,monitor_session_id)；同一活跃voice_session＋external room不可重复创建冲突绑定 | 状态、绑定版本、observed_start／end、collector lease；创建与session.created进度同事务 |
| source_cursors | UNIQUE(consumer_id,source_instance) | acked_seq、last_digest、gap_ref；目标归档去重写入成功后与cursor在review同事务提交 |
| ingress_events | delivery_key=(stable_outbox_owner,event_id)唯一；另建logical_event_key唯一索引（有可靠上游ID时） | logical key=account＋已确认平台场实例／本场binding＋原始method＋upstream_message_id，不含capture_id或boot_id；无上游ID则仅去重重发同一ingress，不能按文本误合并 |
| source_intervals | PK(interval_id)，索引session＋source＋start | opened／healthy／disconnected、explicit gap、原因和证据；静默不等于断连 |
| playback_journal_copy | UNIQUE(voice_source_instance,journal_seq) | 原attempt／epoch／owner、绑定与事件正文；不按同sentence去重掉第二轮播放 |
| archive_revisions | UNIQUE(session_id,revision)、UNIQUE(content_hash) | 截止游标、原件清单、缺口、定义与来源版本；封存短事务CAS current_generation |
| import_previews／datasets／mapping_revisions | blob_hash＋reader_version＋preview参数可复用；正式dataset_id不可变 | field map、单位与粒度、accepted／rejected行引用、确认记录；整份导入逻辑operation_key去重 |

| metric_results／baseline_snapshots／score_results | UNIQUE(cache_key) | 固定输入refs／范围／定义／policy／代码版本；value=null保留reason，不能缓存为0 |

| analysis_jobs／run_inbox／wait_receipts | job_id；inbox event_id唯一；wait_id＋generation CAS | job结果ref／错误／尝试／租约持久化，完成事件不依赖仅内存通知；恢复可扫未消费Inbox |

## 4 采集与播放从入口走到归档

| 序号 | 拟议函数／接点 | 实际动作 | 失败／恢复 |
| --- | --- | --- | --- |
| I1 | voice.live_review_ingress.freeze_ingress(raw, receive_clock, binding_snapshot)→FrozenIngress | 在接收／ACK入口取不可变本场坐标和clock，不等排队落盘后读取当前Room | 缺绑定进unassigned并保留原件，不猜上一场或下一场 |
| I2 | existing live_source._persist扩充同DB事务outbox | 标准事件入原表、去重统计、outbox一起提交；不改现有UI after=0语义 | 任一失败整事务回滚；不能原事件存了却outbox永失；旧未存raw不可恢复 |
| I3 | record_source_ingress(FrozenIngress)→IngressReceipt | 未知方法、system、parse_fail、connect／reconnect由同一个归档入口保存受控原件／schema与健康变化 | 队列满／磁盘错误必须产生可追溯gap或健康告警；不得把无法记录的时段继续算完整 |
| I4 | record_playback_transition(FrozenPlaybackEvent)→JournalReceipt | 在set_current／ack／人工控制的真实变化边界记录；播放器muted／volume、media状态和外部回听等级分列 | Room当前内存状态与journal不具跨库原子性；落盘失败不能假装可完整恢复。优先保持正常播放，明确缺口 |
| I5 | ingest.consume_page(source,cursor,end_cursor,scope)→ConsumeReceipt | 读可靠增量、核身份、保存原件／归档事件、去重、再提交消费cursor | 崩溃后重读同页可幂等；source seq有全局空洞时不按差值当漏了几条 |
| I6 | sessions.seal_archive(session_id, expected_generation, drain_deadline)→ArchiveRef | 取每个生产源的accepted fence及当时durable highwater；等待writer按barrier确认≤fence的入口已落盘或明确失败，再消费至durable fence并冻结manifest | 不用持续增长的latest游标等到无穷；5秒为初始排空上限。超时列accepted未durable尾缺口并封partial；fence之后或迟到数据进新修订，不改旧report |
| I7 | sessions.revise_archive(base_ref,new_source_refs,reason)→ArchiveRef | 输入新资料、迟到事件或新mapping，重算受影响窗口 | 已运行Review继续用旧修订，UI显示有更新；用户选重算建立新run／report |

共享采集连接由现有owner维护；Review acquire_subscription只取得引用计数租约，release只退订本消费者，不能调用全局disconnect切断仍被直播UI使用的连接。重复start相同逻辑操作返回同一租约／session，停止Review运行不等于停止监控；浏览器关页也不取消后台任务。

`acquire_subscription`先读active source及配置hash：同scope同配置连接直接adopt并增加Review lease；未连接才由原owner建立；已有不同配置返回SOURCE_BINDING_CONFLICT及人工选择，不能调用现有connect_source“试一下”。该函数当前会先断旧连接，直接复用它会重置原UI连接。源capture／进程boot可改变，但稳定outbox owner和已确认逻辑场次不变；同upstream事件跨capture回放只保留一条语义事件，原始投递及重复原因仍可追溯。若平台场实例未知，不跨不同monitor session猜重复。

封存的producer fence是接收时已分配的单调ingress序号集合，不要求平台上游序号连续。writer barrier返回持久highwater和失败序号区间；consumer落库与cursor同事务。producer失联不能仅凭“当前没有新消息”认为尾部齐全，要记录unknown tail；停止Review订阅不停止共享生产源。封存Manifest明确included_fence、durable_fence、unresolved_ranges，不将未接收到的上游数据量臆测为精确条数。

新增历史读取明确from_start／from_seq／from_time＋until_seq、ascending、page_limit。现有after=0返回最近200条的接口继续给UI；归档必须走新history入口。首次300条后启动消费者须补300或明确最早100缺口，不得静默只取尾200。

播放端同一句因暂停恢复有多个segment，同一轮重复播为不同attempt。只在相同owner／epoch／attempt和boot_id里合并合法媒体播放区间；ended缺失标不完整，不把排队时间或手动暂停全算内容暴露。source=obs仍不是平台取声证据。

## 5 经营报表导入的内部步骤

| 步骤 | 函数签名（拟议） | 产物与必要规则 |
| --- | --- | --- |
| U1 文件入库 | stage_report(bytes_stream, filename, principal)→BlobRef | 校扩展／magic／文件大小、内容hash；文件名只作展示，不做路径；宏和公式不执行 |
| U2 类型读取 | inspect_report(blob_ref, reader_policy)→ImportPreview | CSV按UTF-8／GB18030候选只读，XLSX只读实际单元格；保留sheet、行列坐标、合并／公式及缺失标识；首期CSV／XLSX必做 |
| U3 映射建议 | suggest_mapping(preview_ref, source_profile)→MappingDraft | 优先已确认header alias；单位、币种、时区、人数／次数、父单／子单和场次粒度单独列；必要时模型辅助只产生候选 |
| U4 人工确认 | confirm_mapping(preview_ref, mapping_hash, human)→MappingRef | 仅歧义／首次口径需要确认；已有完全同profile可复用；不能把同名列当同定义 |
| U5 规范化 | normalize_report(blob_ref, mapping_ref, session_binding)→PreparedDataset | decimal→minor、时间→UTC、订单状态枚举、SKU映射、原行定位；不合格行附拒绝码；PDF／截图仅辅助，未经核表不能当精确成交账 |
| U6 同源去重／冲突 | validate_dataset(prepared_ref)→ValidationResult | 重复上传不双算；同订单来源冲突保留两值并隔离；商品未映射保留unassigned金额，不能硬分当前讲解商品 |
| U7 正式导入 | commit_dataset(prepared_ref, expected_session_generation, operation_id)→DatasetRef | 一次逻辑操作稳定key与hash，数据集正式版本、进度和回执同事务；重复请求返回replayed |

legacy XLS先使用现有受控Office读取／另存工具经核验后接入，不能打开宏；没有可靠读取器则请用户另存CSV／XLSX。这个限制是首期报表范围，不影响已有播前多格式资料读取。公式只有缓存显示值时要记录来源／缓存状态，不默认公式语义可信；无缓存的价格／订单关键格必须补资料。

本场归属优先授权平台session／room／product定义，其次用户确认的精确限定范围；店铺当日全部渠道订单只作背景，不自动计本场。订单粒度先固定parent或SKU子单，不能混加；下单、实付、退款成功的时间与状态分开。

## 6 指标、评分与缓存的精确执行

| 函数 | 输入 | 输出／唯一规则 |
| --- | --- | --- |
| resolve_metric_inputs(spec, archive_ref, dataset_refs, scope) | 对象、定义、数据能力和维度 | 可计算的正式输入或明确missing；隐式不同队列禁止相除 |
| build_order_cohort(spec, datasets, as_of) | 固定创建区间／本场归属／订单粒度 | C内支付是C子集；P退款只含P的成功退款；cohort有可回读ref |
| calculate_metric(spec, resolved_inputs) | 正式输入 | MetricResult；完整整场收入除整场小时，不除采集在线时长 |
| build_content_timeline(archive_ref, clock_ref, window_spec) | 实际segment、偏差、精度 | pure／mixed／unassigned；跨桶UV不能相加，逐秒订单不能伪造 |
| select_comparable_baseline(spec, history_query, policy_ref) | 同商家商品、价格／投流／时段／开场／成熟度 | 排除理由和固定history_refs；整场≥5场，模块专项≥10次且≥3场，仅暂定 |
| score_target(metric_ref, goal_ref, policy_ref) | 同口径正目标与实际值 | 封顶100并保留真实完成率；无目标／无数据null |
| score_relative(metric_ref, baseline_ref, policy_ref) | 正反向定义、上限和B | B=0或无资格null；X=B60；正向1.25B80、1.5B100；比例上限修正；反向按既定分段 |
| score_content(assessment_ref, policy_ref) | 从正式assessment解析完整依赖、四项0／.5／1与证据 | 各项×25合计，未知项总分null；错价严重问题独立保留 |
| persist_content_assessments(items, scope, operation_key) | K10主或K13内容子提交的typed ContentAssessmentInput[] | 核4项ID／评分枚举、原句和真实事实依赖、权限／scope、policy；一次保存assessment refs，再调用score_content并返回score refs；不强制另请一个审稿模型 |
| score_coverage(quality_panel, profile) | 各必需覆盖率 | 最低覆盖×100；Q04延迟是额外门，不参与平均掩盖；经营汇总不强求句子资格 |
| persist_panel(results, lineage) | 所有精确ref与计算版本 | 可一次返回整张Scorecard、missing与drilldown；模型不逐指标胶水查询 |

CacheKey=canonical_hash(account＋archive_ref＋dataset_refs＋dimension＋metric_definition_revision＋cohort/as_of＋baseline／goal_ref＋score_policy_ref＋parser/classifier／prompt/model依赖＋calculation_version)。只包含真正依赖项，不把无关UI开关导致全量失效；任何实际依赖变化则不能复用旧结果。

内容审核还依赖商品事实、顾客简报、本场要求、实际稿件和审核政策；文本没变但商品事实撤回也必须失效。评论标签依赖原文、分类器／提示／可用商品上下文、商品归属规则；不能只按正文hash跨商品复用。

ScoreResult.score_basis统一枚举为target_completion、historical_higher、historical_lower、content_completion、data_coverage，对应四张卡（历史正／反向两种映射）。score.status统一available／provisional／unavailable／not_applicable；后两种score=null且reason必填。metric.status保留available／partial／unavailable／unverified，不与评分状态混用。ContentAssessment四项criterion_id固定criterion_1至criterion_4，具体含义绑定module＋rubric profile；严重问题字段统一critical_findings，不另接受severe_flags别名。所有根稿调用同一个`persist_content_assessments(items, scope, operation_key)`，防止主／子／报告各维护不同参数和字典字段。

### 6.1 缓存许可与真正重算分别如何证明

Goal.refresh_mode枚举：reuse_valid（默认可复用未变依赖）；recompute_metrics（指定指标／评分重新执行，原件解析可复用）；reanalyse_content（指定内容评级／评论标签重做模型判断，原件与无关统计可复用）；refresh_all（本Goal范围所有请求的分析计算重做，不代表重抓历史平台数据）。required_calculations逐项冻结对象、计算类型与义务，不能把“重新复盘”解释为改标题后返旧报告。歧义由K00给合理解释和公开说明，语义实质不清时用K12问，不靠正则静默决定授权。

每个calculate／score／classification／assessment执行或复用均产生CalculationReceipt。recompute_metrics复用原件reader不违约，但直接返回旧score违约；reanalyse_content不得复用旧assessment，主或子本次生成的四项判断带当前attempt_ref。报告完成服务逐项验证required_calculations已有符合origin的receipt，读取旧卡片不能消除义务。新依赖强制换cachekey；重复相同逻辑操作的重试仍幂等回同一次执行，不能为“重算”双扣费用。请求未要求重算则合法复用，减少无用重复。

## 7 缺失、资格与敏感性

公开人数字段目前verified=false，核对前只显示候选数，不计算人分钟响应分。评论主题只分析已读取／已覆盖的范围；抽样标签不能把未分类评论当无意向，也不能除全场人分钟得到伪全量密度。

| 情况 | 结果 |
| --- | --- |
| 无业务报表 | business_outcome=undetermined；可完成interaction_only复盘；不将null变0 |
| 只有整场／商品汇总 | 整场／商品数值与评分；不强分给每次稿件出现 |
| 分钟桶跨模块 | mixed；不按秒拆UV／订单；即使纯桶相邻也先核跨桶去重能力 |
| 只有接收时间且传输滞后无界 | 只本地接收共现；平台声音延迟标定不等于事件延迟也已测好 |
| 某评分分母不足／历史不足 | 保留事实、样本和missing_reason；不把剩余项加权重标为100 |
| 模拟样例或混入synthetic | 真实经营结论受限，不能声明实际达标；试验与真实档案分开 |
| 已取消后迟到结果 | usage和原件仍保存，run不恢复RUNNING／COMPLETED，不触发采纳 |

预注册评论主窗30秒、敏感性15／60；商品付款探索0–5分钟、敏感性1／3／10。对正式成交总量一单只记一次；不同探索窗不相加。Wilson只用于合法二项计数；退款金额率与相关人分钟密度不套Wilson。样本／区间与得分分开展示，分数不是因果概率。

## 8 一致性及迁移要求

迁移使用独立Review migration版本号，新增voice outbox／journal表前备份及验证，不改旧prelive表语义。升级只增加向后可读字段时写兼容适配；关键语义改变给新schema_version并按fixture比较，禁止默默accept any dict。

每次新归档／报表mapping／评分政策产生新引用与lineage，不在旧报告里换数据。用户删除／撤回证据后保留最小审计状态并撤销相应可访问投影及缓存；不能借旧摘要继续引用已不可访问原件。保存和清理均为普通服务管理，模型没有任意文件删除权。
