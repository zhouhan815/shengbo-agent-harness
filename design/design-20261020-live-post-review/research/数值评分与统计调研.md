# 数值评分与统计调研：目标达成、历史比较与小样本

日期：2026-10-20。性质：设计研究，未接入真实直播，未调用付费模型，未修改业务代码。本文对上一版“不建议评分”的结论作范围收敛：**现在可以提供明确的分数，但要让分数说明一件具体的事情；目标达成、相对历史、内容审核和数据质量分别展示。**

## 1. 推荐的四类数值

| 数值 | 具体回答什么 | 首期建议 | 不能把它解释成什么 |
|---|---|---|---|
| 经营目标完成分 | 本场完成了商家事先设定的成交目标的多少 | 0–100 分；同时显示不封顶的实际目标达成率 | 行业排名、利润、句子造成的因果成交 |
| 单项历史相对分 | 点击、转化、净额效率等比自己可比历史怎样 | 每项独立 0–100，历史中位数为 60；1.5 倍为 100 | 学校及格线、若干相互重叠漏斗指标相加后的独立总贡献 |
| 内容与模块诊断 | 这段有没有把应讲信息讲清楚；其后观察到怎样的响应 | 内容审核与响应表现分开；同模块类型/长短开场分别比较 | 沉默观众是否理解、付款那句话是否导致成交 |
| 数据质量 | 我们有多少材料能够支持上述判断 | 覆盖率、完整字段率、可对齐时长率等明确比率，必要时 0–100 | 直播本身是否卖得好 |

**拒绝把点赞、评论、点击、成交、退款、技术在线率全部合成一个“直播好坏总分”。**它会让有大量互动但没有成交的直播看起来成功，还会重复计算漏斗同一批人的贡献。经营主卡用目标完成，其他卡解释原因。

## 2. 经营主分：冻结目标，直接算达成

设商家开播前确认并冻结的本场净有效成交目标为 `G > 0`；本场按相同订单集合、币种、折扣/运费口径及售后截止时点得出的净额为 `X`。

```text
actual_achievement_pct = 100 × X / G
goal_score = min(100, max(0, actual_achievement_pct))
```

| 明确的合成示例 | 目标 | 实际已知净额 | 主分 | 同时显示 |
|---|---:|---:|---:|---|
| 例 A | 10,000 元 | 8,000 元 | 80.0 | 已完成目标 80%，差 2,000 元 |
| 例 B | 10,000 元 | 12,000 元 | 100.0 | 实际达成 120%，超 2,000 元 |
| 例 C | 未设目标 | 8,000 元 | 无 | 有实际成交，未设置目标，不能补造目标分 |
| 例 D | 10,000 元 | 尚未导入经营报表 | 无 | 成交数据缺失，不能记为 0 分 |

`X` 是同一已归属支付集合的支付额减截至时点的成功退款，不是扣掉历来所有退款。退款申请不等于成功退款。关播当晚与 7 天后可能得到不同 `X`，因此分数必须带 `as_of` 和售后年龄。**“7 天后”只是可以采用的业务观察时点，不宣称届时所有退款均成熟。**对历史比较需对齐相同观察年龄。

约束：目标事先冻结；播后改目标必须产生新的目标版本，并同时保留原目标完成率。若目标业务指标是“支付额”而非净额，应单列支付目标完成，不能不说明就用净额比较。缺少成本时不能叫盈利目标。

## 3. 漏斗单项分：可解释的双线段

先生成可比基线 `B`：默认取过去 28 天、最新至多 20 场合格历史的该项指标中位数，至少 5 场才展示“暂定历史分”。这些数字是**产品首期默认值，非抖音行业标准或统计充分性保证**。10 场以上也不意味着消除了样本不确定性。

匹配顺序：同商家、同商品/SKU 映射、近似价格及促销机制、相同统计口径/售后年龄、相近流量来源和时段。按模块时再匹配开场类型、模块、编排位置条件和有效曝光条件。放宽匹配条件时记录放宽项并降低结论强度；不能为了凑 5 场把无关商品或不同价格混在一起。当前这场不进入自己的冻结基线。

### 3.1 越高越好，例如真实点击率、同群体点击成交率、净有效成交/千观看 UV

```text
若 B > 0：
  r = X / B
  若 r <= 1：S = 60 × r
  若 r > 1： S = 60 + 80 × (r - 1)
  S = clip(S, 0, 100)
```

| 实际 / 基线 | 单项分 | 应给用户的解释 |
|---:|---:|---|
| 0 | 0 | 在数据确实完整的情况下，本项观察为 0 |
| 0.5 | 30 | 本项为历史中位数的一半 |
| 1.0 | 60 | 本项与自己的可比历史中位数持平 |
| 1.25 | 80 | 高于基线 25% |
| 1.5 | 100 | 高于基线 50%，达到试用评分上锚点 |
| 2.0 | 100 | 评分已封顶，但仍显示实际为基线 2 倍 |

例如基线点击率为 10%，本场 12.5%，则 80 分。基线看播购买率为 3%，本场 4%，则 `60 + 80 × (4/3 - 1) = 86.7` 分。**86.7 不表示模型确信提高，也不表示行业优秀。**百分点变化仍要写清楚：3%→4% 是增加 1 个百分点，相对增加约 33.3%。

比例指标的 1.5B 若超过物理上限 100%，该项不能沿用不可能达到的上锚点。应在播前配置一个可达到、严格高于 B 的上锚点 T（≤100%），再将上半段改为 `60 + 40 × (X-B)/(T-B)`。B 已为 100% 时没有正向改善空间，显示“已达上限”，不再发明相对提升分。

### 3.2 越低越好，例如同支付集合成功退款金额率

采用单独反向锚点，不把“退款减少一半”和“点击提高一半”假装成相同业务价值。

```text
若 B > 0：
  r = X / B
  若 r <= 1：S = 100 - 40 × r
  若 r > 1： S = 60 - 60 × (r - 1)
  S = clip(S, 0, 100)
```

| 退款率 / 历史退款率 | 分数 |
|---:|---:|
| 0 | 100 |
| 0.5 | 80 |
| 1 | 60 |
| 1.5 | 30 |
| 2 | 0 |

基线 10%，本场同售后年龄退款率 5%，为 80 分。假如本场只有 1 个订单还未进入通常退款期，不能只因为暂时 0 退款便显示“质量优秀”；可显示“当前 0/1，尚未成熟”，不作高质量判断。金额退款率属于金额加权比率，**不能直接把退款元数当二项成功次数套 Wilson**。

### 3.3 基线为零、没有历史或没有分母

| 边界 | 行为 |
|---|---|
| B=0，本场也为 0 | 显示持平/尚无正向事件，不给比值评分 |
| B=0，本场>0 | 显示从 0 增至具体数值，不显示无限改善；如有播前目标可转目标完成分 |
| 只有 1–4 场历史 | 可以并列原始值，不给正式历史分；若展示探索分需清晰标“基线不足”，不能伪装 5 场标准已满足 |
| 分母缺失、口径冲突 | 指标与分数均为 null，带原因，不当作 0 |
| 分母确为 0 | 比率无定义，显示不适用；不能因为无订单而算 0/0 的退款率为 0% |
| 比率越过物理边界 | 保留原值并拦截该项评分，核对 cohort/单位/来源；不靠截断掩盖数据错误 |

## 4. 比例与小样本：分数和证据强度分开

选择 Wilson 95% 区间作为首期易解释的比例不确定性方法。NIST 说明了 Wilson/二项区间；statsmodels 提供现成实现。它们支持统计计算，**不支持本文 60 分、1.5 倍、5 场这些产品锚点**。[NIST 比例区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)、[statsmodels proportion_confint](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.proportion_confint.html)

前置条件：真实分子 k 为同一人群 n 中成功的人数，`0<=k<=n`；没有把订单次数/商品件数除观看人数当二项比例；相关性假设适用。n 必须来自授权平台明确口径或可靠 cohort，不能用已观察进场通知替代。

设 `p=k/n, z=1.95996398454`：

```text
d = 1 + z²/n
center = (p + z²/(2n)) / d
half = z × sqrt[p(1-p)/n + z²/(4n²)] / d
[L,U] = [max(0,center-half), min(1,center+half)]
```

本次用纯 Python 数学公式只读核算的合成例子：

| k/n | 比例 | Wilson 95% 区间 | 为什么要显示 |
|---|---:|---:|---|
| 3/50 | 6% | 2.06%–16.22% | 3 人很容易造成看似很高的转化 |
| 30/500 | 6% | 4.23%–8.44% | 相同比例，证据精度与上一行不同 |
| 40/1000 | 4% | 2.95%–5.40% | 可以给当前比率的描述分 |
| 30/1000 | 3% | 2.11%–4.25% | 和上一行区间重叠，不能凭点分宣告确定胜出 |
| 0/50 | 0% | 0%–7.13% | 观察到 0 不意味着真实潜在转化概率为 0 |
| 1/20 | 5% | 0.89%–23.61% | 小样本高分只能暂定 |

区间解释边界：如果这就是全场完整人群，4% 是本场已知的描述比例；Wilson 区间是在假定类二项机会过程下反映波动/推广的不确定性，不是声称平台人数“测量误差”在此区间。跨循环同一观众重复曝光、群体进入冲击、同人多订单等会破坏简单独立假设。条件不符时不计算二项区间，改显示各场/各次播放分布，并保留相关性限制。

**不把 Wilson 下界直接作为得分输入。**否则同样真实表现的低流量商家天然得低分，把“证据少”和“卖得差”混为一谈。分数显示点估计；区间、样本量、证据标签与它并排。与历史之差的置信区间需要对两边的波动共同计算，不能只把本场上下界代入固定 B 就称为完整差值区间。

首期可用的数值提示规则（产品默认，不是显著性定理）：

| 条件 | 展示 |
|---|---|
| 比例分子<10 或分母<100 | 样本偏少；保留原始比率、区间及暂定分 |
| Wilson 全宽大于 `max(0.02, 点估计)` | 波动较大；不作明确优劣判断 |
| 同时满足以上之外 | 仍不是自动显著/因果成立；可做更有信息的观察比较 |
| 超过 10 个模块/版本比较 | 首期只列探索性候选，不自动挑“赢家”；若以后作正式检验，预先指定主指标/对照并处理多重比较 |

正式检验可以借助 statsmodels 的两比例比较与 `multipletests(method='fdr_bh')`，但 FDR 校正不能修复非随机混杂或虚假的独立样本。[多重比较工具](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html)

## 5. 模块响应的数量尺度

每个实际播放区间保留商品、话术修订、模块、长/短开场、队列位置、播放 attempt。暂停/恢复按确认播放区间并集算有效时长。响应窗需要先测推流延迟；没有平台延迟校准时，只能作本地时间共现分析。

首期的模块响应规则建议：同类型至少 10 次可比实际播放、来自至少 3 场直播，再展示“暂定响应相对分”；这个阈值只避免为单句一次偶然评论打分，**不保证样本独立、不证明效果显著**。不足则展示具体事件与内容审核，不强算表现分。

可以直接计算：`已观察相关有效评论条数 / 同一观察范围有效分钟数`。标签需明确是提问/误解/购买意愿/负面反馈，不以所有提问都当正向响应。若在线人数只是未核实字段，不生成“每百观众互动率”。真实在线快照定义、采样频率与缺口核实后，可辅助用在线曲线积分得到观众分钟，但那是估计曝光尺度，不是去重人数。

公开评论会受到采样、刷屏、同人多次评论和群聚效应影响。Poisson 计数率区间只有在相应假设合理时才用；不能因为库里有函数就默认所有评论计数独立。statsmodels `confint_poisson(...,method='exact-c')` 可以计算计数/暴露时间的区间；发现明显过度离散时，优先按场次分组报告波动，后续再选择合适的负二项/聚类模型。[计数率官方工具](https://www.statsmodels.org/stable/generated/statsmodels.stats.rates.confint_poisson.html)

最后一句在某分钟出现，订单也在这一分钟支付，仍然不能给这句话“成交贡献分”。分钟桶跨多个模块时原样显示混合桶；不按秒把订单均分给模块。多个滞后窗口中的同一订单不能相加。

## 6. 其他评分方式的取舍

| 方法 | 优点 | 当前风险 | 推荐位置 |
|---|---|---|---|
| 目标达成率 | 最容易解释；新商家也可用；与最终目的直接对应 | 目标容易被事后调低；不是利润；规模目标受流量影响 | 经营主卡，目标冻结 |
| 本文双线段历史分 | 用户知道持平和提高对应多少；可回算 | 锚点人为选择；0 基线/物理上限需处理；必须有可比历史 | 漏斗单项和模块响应的描述比较 |
| 经验分位数 | 不要求正态；对极值不敏感；回答超过自家多少场 | 5 场历史每档很粗；所有历史都差也一定有人高分；随历史窗移动 | 20 场以上时追加“历史位置”，不取代目标分 |
| 中位数/MAD 稳健 z 分 | 适合发现相对自己平常异常；比均值标准差耐受异常值 | 很多零/相同比率会 MAD=0；z 不是业务价值；需要用户理解额外变换 | 数据异常或趋势告警辅助，不作主分 |
| Beta-Binomial / 经验贝叶斯收缩 | 小样本极端值可以向相似群体收缩 | 先验/交换性难说明，固定商品之间未必相似，容易被当作真实订单 | 先期不需要；后续有足够同质数据再校准 |
| 任意加权 100 分 | 看起来统一 | 容易双重计算、缺失自动升分、互动替代成交、无法解释 | 不采用 |

经验分位数可用 `scipy.stats.percentileofscore(history,x,kind='mean')`，明确相同值处理。MAD 用 `scipy.stats.median_abs_deviation(...,scale='normal')`，仅是计算稳健尺度，不会自动使评分合理。[分位数文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.percentileofscore.html)、[MAD 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.median_abs_deviation.html)

历史不确定性：场次作为独立性近似单位，不能 bootstrap 秒级在线快照来制造巨大样本。合格场次充足时可按场次重抽，得到中位数/净额效率差的区间；先试 5,000 次、固定随机种子、95% 区间，这也是计算预算默认。三个场次时不输出看似精密的 cluster bootstrap 结论。SciPy `bootstrap` 实现统计量区间，但退化样本可返回 NaN；应识别全相同、极少非零、缺分母等边界。[Bootstrap 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)

Harness 中应用方式：将数据资格、指标计算、评分变成普通只读统计工具；Skill 告诉主 Agent 在什么任务读哪张卡、有哪些归因边界；Agent 选择要解释和检验的假设，不让它自由编分母、分数或显著性。中间件校验报告中的分数确实引用正式计算结果和证据，不以模型自信覆盖数据缺失。

## 8. 验收清单

| 编号 | 必须验证的例子 | 合格表现 |
|---|---|---|
| S01 | 8,000/10,000 和 12,000/10,000 | 80 分/100 分，后者仍保留 120% 实际达成 |
| S02 | 正向 X/B=0、0.5、1、1.25、1.5、2 | 0、30、60、80、100、100；函数单调、无越界 |
| S03 | 反向 X/B=0、0.5、1、1.5、2 | 100、80、60、30、0 |
| S04 | 基线 0；缺失分母；0/0；当前值>100% | 不产生无限值/假 0；非法口径被拒绝 |
| S05 | 基线 80%，理论上锚点 120% | 拦截 1.5B 默认，上锚点需改到可实现区间 |
| S06 | 3/50 和 30/500 都是 6% | 主点分一致、样本和区间不同；不惩罚低流量分数来冒充保守 |
| S07 | 只有公开评论，无经营表 | 不生成经营目标完成分，仍可做评论证据和内容诊断 |
| S08 | 当前付款来自上一场，或退款来自别的订单集 | 不被加入本场经营分 |
| S09 | 同一观众跨 20 个模块；同一订单落入两个滞后窗 | 不计作 20 个独立人；不重复累计订单 |
| S10 | 关播即时和相同场次 7 天后重算 | 保留两版 as_of，不悄悄覆盖；历史比较对齐售后年龄 |
| S11 | 不同开场、价格/活动/付费流量变化 | 排除或明确降低可比性，不凑历史数量 |
| S12 | 有 99 分但样本 1/1 | 展示暂定/样本不足，不宣布成功策略或下一场自动采用 |
