# 声播运营 Agent 统一数据与工具契约

版本 2.0　日期 2026年10月7日　规范标识 `shengbo.ops.v2`

扩展提示：[08 业务闭环与动态数据详细设计](08_业务闭环与动态数据详细设计.md) 新增原始资料候选/补问、本场活动、经营指标观测和改进补丁要求。本文及v2样例尚未定义这些扩展；A先发布版本化共享类型、工具和样例，各模块再接入，不得将未定义字段静默塞进v2后宣称兼容。原有边界和来源/时效要求继续适用。

本文件是四个研发窗口共同使用的设计合同。下面描述的 Ops 接口尚未实现。已有声播接口单独列出，不能把新设计地址当成已经可用的 API。各模块先以 UTF-8 JSON 文件交接，未来 HTTP 或进程内调用保持相同字段语义。

## 一 公共约定

所有顶层业务包含 `schema_version`、`kind`、`id`、`revision`、`created_at`。版本不支持、缺必填字段或引用不属于目标场次必须明确报错。金额用十进制字符串加 ISO 币种，不把 TWD 换成 CNY；日期时间用含时区 ISO8601。缺失值用 null 和原因，0只表示确实观测到零。

每个证据对象包含 `data_origin`：simulated、real_runtime、real_business；这是证据来源，不是整场真实性的开关。同一场可以有模拟问题和真实声音回执。source 表示具体采集渠道，occurred_at 可未知，received_at 必填。推断和计算需保留其输入证据，不伪装成原始观测。

| 标识或版本 | 语义与所有者 |
| --- | --- |
| product_id / product_revision | 商品库ID；A适配器发行资料版本。过渡可对规范化语义字段算摘要，消费者将其视为不透明字符串，不各算一套 |
| plan_id / plan_revision | 播前准备任务及不可变修订；正式版本由统筹发布 |
| room_id / session_id | 房间配置和实际开播ID；session只由声播开播产生，离线测试的模拟ID须标明来源 |
| script_id / script_revision / draft_id | 已导入稿及修订，或未导入的本地草稿；导入记录映射 |
| queue_revision | 队列结构变化时递增：开始构建、重排、替换和删除；正常播下一句不递增 |
| cursor_revision | 当前队列位置改变时递增，包括自然推进、跳句、切商品、循环回头 |
| control_revision | 人工或网关执行暂停、恢复、切换、跳句、改队列、结束等操作时递增；自然播放进度不递增 |
| epoch / attempt_id / boot_id | 当前音频代际、实际播放尝试、进程启动标识；播放器接管也可能换epoch，boot用于识别重启 |
| event_id / proposal_id / action_id | 原始输入、决策提案、一次逻辑执行；action绑定规范化参数摘要 |
| archive_id / review_id | 不可变归档和复盘任务；修订各自记录 |

商品库只有一份。快照包含原字段、事实列表和来源，是不可变历史证据。事实引用为 `{product_id, product_revision, fact_id}`，不能单凭 PRICE 或 KNOWLEDGE_1 跨商品引用。A统一生成版本，字段至少覆盖 name、price、promo_price、currency、selling_points、promotion、knowledge；规范化方法和迁移映射须写测试。用户修订资料后旧事实引用不自动变新。

## 二 核心业务包

下表字段均为首版要求；不适用项用规定的 null/空数组，不静默丢弃。附带样例见 fixtures 目录。A将本合同落实成严格类型与 JSON Schema，并负责共享版本。

### PreparationRequest 和 PreparationBundle

Request：公共元数据；room_id可null；target_start_at可null；objective含目标、优先商品、约束；catalog_snapshots数组；existing_scripts数组；adopted_improvements数组；policy与预算。

Bundle：公共元数据；plan_id、room_id、source_request_id；status为 needs_input、needs_review 或 published；objective；catalog_refs；issues；script_candidates；faq；lineup；live_policy；preflight；approvals。

- issues 每项含 issue_id、severity、field_ref、reason、required_action、blocking_scope。一个配送时间缺口可阻断相关承诺，不必阻断全部通用卖点。
- 候选稿含 draft_id、product_ref、angle、blocks、sentences、review_status。句子含 sentence_id、stage、display_text、spoken_text、kind、fact_refs；engagement可无商品断言，但不能藏未经支持的承诺。
- FAQ 含 faq_id、product_ref、question、answer_text、fact_refs、unknown_policy、review_status、content_hash。approved内容变动后必须重审；批准绑定内容hash及事实版本。
- lineup 含 product_ref、script_refs、order、must_cover_fact_refs、reason、estimated_duration和duration_basis。时长是估计或TTS实测，不能填伪精确值。
- preflight 含 scope、status、evidence_refs；status为pass、fail、not_checked。离线模块不能证明声音来源已连接。
- approvals 由可信操作入口记录操作者、对象、版本/hash、时间和结果；模型不能填写自己已获人工批准。
- 只有A导入稿件、重新核对资料并完成运行预检后才可published；离线播前默认needs_review。published表示准备包已发布，不代表已开播。

### RoomSnapshot 和 NormalizedEvent

Snapshot：公共元数据；room_id、session_id、boot_id、plan_ref可null、status；上述三个revision、epoch；current含product/script/sentence/queue/attempt引用；pending_queue数组；insertion可null；player连接与来源；capabilities。

Event：公共元数据；event_id、room_id、session_id、seq、occurred_at、received_at、event_type、source、data_origin、product_id可null、payload。seq由A按session事件流单调分配，跨运行不归零；外部输入原始ID在payload.source_event_id保留，不能冒充本地游标。

event_type包含 question、manual_action、action_accepted、action_completed、playback_started、playback_ended、playback_interrupted、runtime_error、business_update。未知类型保存但不执行。payload是数据，不授予工具权限。重连游标过期时返回gap与快照；无法重放的输入明确缺失。按类型过滤的事件子集可以有不连续seq，不能把过滤空洞误报为完整流丢失。

### Proposal 和 ActionRecord

Proposal：公共元数据；proposal_id、room_id、session_id、plan_ref；based_on含boot_id、queue_revision、control_revision、product_ref；event_refs、fact_refs；decision为no_action、ask_operator、propose_action；reason；tool和tool_args（非动作时null）；created_at、expires_at；approval_state为not_required、pending、approved、rejected；policy_revision。

模型生成提案时不能把approval_state改成approved。网关从已授权的会话策略或可信人工操作判定是否可执行。插播提案还须绑定FAQ/审核内容hash，避免批准A文字却播B文字。

ActionRecord：公共元数据；action_id、proposal_id可null、room_id、session_id、boot_id、actor；tool、tool_args、payload_hash、preconditions；status；submitted_at、accepted_at、started_at、completed_at均可null；attempt_refs；result_evidence_refs；error可null。提案不是动作；no_action不创建虚假成功动作。

执行状态为 prepared → dispatching → accepted → started → completed，另有 rejected、cancelled、failed、unknown。队列或暂停类同步动作可accepted后直接completed。提交成功只满足“已受理”，播出目标必须关联播放器证据。超过确认时限而事实不明为unknown，不等同failed，也不换ID再试。

### SessionArchive 和 ReviewBundle

Archive：公共元数据；archive_id、room_id、session_id；started_at、ended_at、sealed_at、end_reason；preparation_ref可null；catalog_snapshots、script_snapshots；events、proposals、actions、playback_attempts；business_metrics可null；completeness；evidence_index。

attempt含attempt_id、product/script/sentence/queue/action引用、started_at、ended_at、status、source、data_origin；action_id对于常规计划播放可null。状态为completed、interrupted、failed、unknown。句子重复播不按sentence_id去重，按attempt_id区分。

completeness按events、actions、playback、catalog、business分别给complete、partial或missing、时间覆盖和gaps。sealed只表示修订冻结，不说明数据完整。结束后等待回执的时长可配置，超时封存缺口；迟到证据创建新archive_revision。

Review：公共元数据；review_id、session_id、archive_ref；status为complete或partial（仅指约定复盘范围）；data_quality；computed_metrics；findings；improvement_proposals；experiment_plan；usage。finding分observation、hypothesis、evidence_refs、limitations，不用无校准的置信概率。每个改进含目标及base_revision、type、内容、理由、证据、验收方法、priority、approval_state=pending。

业务指标每项记录value、unit、formula_id、numerator、denominator、eligible_count、missing_count、source_refs、data_origins。不能计算时value=null并说明原因。业务数据缺失不妨碍流程复盘complete，但经营分析须明确不可用。

## 三 程序接口和工具契约

模块入口统一采用 `run(request, tools, emit, cancellation, budget) -> Result`；这里只规定逻辑接口，A负责Python具体类型。模块还须提供JSON文件CLI和纯离线测试。Result含status、artifact_refs、unresolved、usage；状态为completed、partial、needs_input、failed、cancelled。不能从自然语言报告推导接口状态。

| 逻辑工具 | 输入与权限 | 结果和确认 |
| --- | --- | --- |
| read_catalog / read_script | 绑定商品或稿件引用；只读 | 返回事实版本和内容，不靠模型凭记忆补齐 |
| create_draft | 播前专用，完整结构和事实引用 | 保存独立草稿；不批准、不改活跃场次 |
| read_live_state / query_events | 绑定当前room/session及游标 | Snapshot/事件窗口；缺口显式返回 |
| read_answer_history | session、商品版本和问题主题 | 返回已完成与待播回答，二者分开 |
| propose_action | 播中专用，结构化Proposal | 只登记提案；不能直接发声 |
| query_archive / read_evidence | 播后专用，归档修订和证据ID | 原始证据/程序统计及完整性 |
| submit_action / inspect_action | 网关专用，稳定action_id及参数hash | ActionRecord；检查当前版本和终态 |
| publish_preparation / seal_archive | 统筹专用，版本化产物 | 返回冻结引用；不是自由模型工具 |

读取工具临时失败可有界重试；结构错误返回invalid_input；旧版本为version_conflict；能力缺失capability_unavailable；结果不明timeout_unknown。错误对象含code、message、retryable、evidence_refs；写入是否能重试由动作状态决定，不能单凭retryable。

## 四 已有动作映射与真实效果

实际声播写入入口为 POST `/api/rooms/{room_id}/control`。A适配器是唯一调用者；B/C/D只调用被注入的逻辑工具。默认房间 `/api/control` 不用于新Agent接入。

| 逻辑动作 | 现有action参数 | 影响与限制 | 完成证据 |
| --- | --- | --- | --- |
| insert_after_sentence | insert，mode=after_sentence，text | 当前句结束后插播，然后下一句；仅一项插播，可被暂停/结束影响 | 对应插播attempt的ended |
| insert_immediate | insert，mode=immediate，text | 打断当前句，插播后原句从头重播；不表示逐字续播 | 被打断attempt记录加插播ended |
| switch_product | switch，product_id | 仅切到队列中后续已有商品，跳过中间内容；不切购物车 | 当前商品回读及版本变化 |
| reorder_pending | reorder，queue_ids | 全部待播项的完整排列；不含当前句；插播时拒绝 | 新队列结构与queue_revision |
| replace_pending | replace_pending，target_script_id、script_id | 同商品的已确认稿替换待播旧版本 | 新队列及稿件版本；再核对当前资料 |
| next / retry / next_product | 同名 | 跳过当前句、重播当前句或跳过当前商品余下内容 | 位置/attempt变化，重播完成另看ended |
| cancel_product / pause / resume / stop | 同名 | 取消商品、暂停、恢复或结束；恢复需播出来源 | 状态回读；已发出的声音不能追溯撤销 |

首版实时模型只开放句尾答疑提案；立即纠错、切商品、改队列等先在人工确认和模拟中验证。是否开放由capabilities及会话策略共同决定，模型不能自行开白名单。

## 五 竞态与恢复

网关在同一声播Room锁内检查session、boot、control、商品事实、队列及有效期，再取得当前epoch传给底层动作。检查后执行前不能留出人工操作穿插的窗口。A须使人工UI和Agent写入都经过同样的修订更新路径，旁路读取后自行POST不能实现该保证。

提案基于业务上下文，不固定数秒前的epoch。普通FAQ允许同商品自然换句；切商品或人工控制改变则作废并重读。重排须匹配queue_revision并在提交时验证完整待播集合。试验中用可控时钟定义到期，不让模型自己判断当前时间。

稳定action_id绑定完整参数hash，相同ID不同参数拒绝。摘要对象包含room_id、session_id、boot_id、tool、tool_args和冻结的preconditions，不能只hash回答文本。规范化采用UTF-8 JSON、键排序及无额外空白；精确金钱先按合同变为字符串。提交时取得的瞬时epoch另存执行观察，不在重试时偷偷改变原逻辑动作摘要。

dispatching先持久化，再执行，结果与事件保存。提交后断连先inspect_action，不能换ID重播。若重启时只知dispatching，保持unknown；本地账本不能保证内存播放与数据库外部原子提交。重启保持旧场停止，旧会话动作不自动重放。

操作、版本、事件和回执尽量在统一事务记录；实际音频由浏览器执行，仍必须承认确认窗口。迟到的旧owner/epoch/attempt回执拒绝；当前owner的ended也只证明播放器报告完成，不证明平台观众听到或OBS收音成功。

## 六 运输与变更

首版文件采用写临时文件、校验、原子重命名方式发布；只读消费者不改生产者文件。广播投影按session连续seq补齐，过期返回gap。计划、归档、报告修订不可覆盖。

每个窗口可新增自己产物的非共享字段，但改共同语义必须提出字段、理由、兼容影响和样例，由A合并合同新修订。A发布Pydantic/Schema之后，各模块导入共同类型；之前可实现本地兼容类型和mock，交付时必须通过共同契约测试。
