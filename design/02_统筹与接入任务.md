# 窗口 A 统筹 Harness 与声播接入任务

业务修订必读：[08 业务闭环与动态数据详细设计](08_业务闭环与动态数据详细设计.md)。A新增原始资料/字段候选/一次确认入库接口、本场活动与有效报价、统一指标服务和面板、动态样本及归档扩展；先冻结共享类型和mock。商品库、话术生成、音频准备、人工与Agent控制共用原服务。本文原范围之外的经营数据能力须逐项核实，不能以OBS链接代表平台数据接入。

版本 2.0　日期 2026年10月7日　实施任务包

## 一 你的目标与上下文

为三个运营 Agent 建立共同运行和执行底座。现有声音直播应用在 `D:/Codex project/ecommerce-voice-agent`，支持统一商品库、多房间配置、逐句播出及实时动作，但没有运营 Agent、完整历史归档、持久动作去重和队列版本。本任务是把这些入口做成可靠、可检验的运营工具，不重写声音系统。

先读同目录 [00 总体方案](00_整体方案与并行分工.md)、[01 统一契约](01_统一数据与工具契约.md)、[06 验收计划](06_验收与回放测试计划.md)。本任务包不依赖原聊天。实现前重新检查现有代码；若与静态核查不一致，记录差异，不照抄过时行号。

## 二 文件所有权和集成责任

统一新实现根目录为 `D:/Codex project/shengbo-ops-agent`。你拥有 `contracts/`、`ops_core/`、`adapters/`、`tests/integration/`、根依赖配置、启动入口和总交付报告。B、C、D分别拥有modules/prelive、modules/live、modules/postlive及其测试；不要替他们改实现。

你是唯一可以修改现有声播接入代码、共享UI和公共数据库结构的窗口。先备份或用Git保留原状态，只改接入需要的部分；不要覆盖用户未提交修改。其余窗口向你提交接口变更请求。测试使用独立临时数据目录，不对现用商品库进行批量写入。

## 三 需要实现的内容

### A0 公共合同与样例

将01落实为Pydantic模型、可导出的JSON Schema和契约验证器，集中管理枚举、金额、时区、引用和不透明版本。提供各模块可导入的公共类型；fixture原文件只读，迁移后的测试样例保存到自己的目录。公共版本固定为shengbo.ops.v2，禁止字段含义静默漂移。

提供ModelGateway和ReplayModel两个实现：前者封装DeepSeek调用、工具ID往返、结构化校验、超时、计量与取消；后者用于无密钥离线测试。密钥由可信后端配置加载，不写入文档、样例或日志；不能为方便把现有.env复制给每个模块。

先做最小模型探针，验证实际需要的tool_call_id往返、JSON错误纠正和超时；模型名称从配置读取，不因已能生成话术就宣布工具Agent兼容。DeepSeek的工具结果需要由应用执行并送回模型，API不会替本系统执行业务动作。[官方工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)

### A1 任务统筹和共享 Harness

实现任务注册、依赖、取消、局部预算、产物引用和持久检查点。按plan_id、session_id和review_id分别建立运行上下文；单个长聊天不承载所有阶段。程序按阶段路由到三个模块，不增加自由指挥的总Agent。

流程分两套状态，禁止混为一套：运营任务created/running/waiting_input/completed/partial/failed/cancelled；业务阶段draft/published/live/ended/archived/reviewed。开播时绑定声播真正返回的session；结束时封存，复盘任务由归档版本触发且幂等。

模型节点可用LangGraph管理有界循环和暂停；使用落盘checkpointer，不能用内存检查点宣称能跨进程恢复。副作用放在独立动作边界。LangGraph恢复确认节点可能重新执行节点前段代码，需以稳定action_id对账。[官方interrupt说明](https://docs.langchain.com/oss/python/langgraph/interrupts)

### A2 商品和准备包适配

读现有GET /api/library，将商品和稿件映射为规范快照，发行product_revision。实现完整草稿导入和draft_id到script_id映射，保留段落、朗读文本和事实引用。现有PUT稿件接口按位置继承旧引用，不能用它假装无损导入。语义事实ID如SIZE须与声播NAME/KNOWLEDGE_N等来源字段建立显式映射，保留文本和版本；映射失败阻断，不能让新ID冒充已通过旧校验。

发布前检查商品版本、草稿批准状态、房间引用、选择顺序、TTS和声音来源条件。不要把准备B场的草稿导入动作应用于正在播的A场。发布只保存选择与冻结引用，实际开播仍需运行时预检；商品资料变化使相关发布版本失效，要求新修订。播中商品资料更新立即使相关旧FAQ和提案失效；首版测试策略默认暂停正在讲该商品的播报并提示核对，不让旧价格继续由自动队列播出。其他商品变更标记待重审。此程序策略在会话配置里明确，不由模型临时决定。

### A3 声播内的原子执行边界

新增能力清单及统一网关；逻辑方法使用01的名字，实际HTTP路径由你统一确定并在交付中公布。声播现有端口保持8765；无需为B/C/D各启一个服务。

关键校验和底层action在声播同一Room锁内完成，所有人工和Agent写入都递增规定的版本。仅在另一个进程先GET状态再POST旧接口，不能保证其间无人工切换。模型只能提案；你的网关串行处理，优先人工操作，限制频率并在提交时检查session、boot、商品版本、control_revision、有效期和适用的queue_revision。

在声播执行侧持久保存动作账本和原始运行事件；Ops核心保存任务、产物和归档索引。两个存储的职责分开，跨进程同步采用ID去重和游标，不宣称分布式事务。动作账本至少保存参数hash、prepared/dispatching/accepted等状态及回执。

重复ID相同参数返回原动作记录，参数不同拒绝。dispatching后结果不明不得自动重放；重启旧场保持停止，旧boot动作不恢复播出。HTTP成功不代表音频完成，必须把insert生成的句子、attempt和action关联，记录playing/ended/interrupted。

先支持句尾插播。立即插播、重排、替换、切商品等入口可存在，但在逐项测试通过前仅模拟或人工确认。暂停/停止和取消优先于迟到模型结果；恢复声音仍遵守现有浏览器来源限制。对接公司数字人产品时另外返回受限能力清单，不能复用本地声播的全部能力。

### A4 完整归档和旧记录迁移

每条新运行事件带room/session、事件ID、稳定seq、动作和attempt关联及来源。进度事件与关键状态在执行侧一致保存。播放器与Ops断开时保留可补发日志；游标失效或输入源丢失明确gap，不能补造历史。

封存Preparation、商品、脚本、问题、提案、动作和播放证据。结束时等待迟到回执的窗口配置化；缺口照实封存，后到数据生成归档新修订。对旧/api/export仅转成partial归档：played可证明收到结束记录，开始时间未知；不得用时长倒推，不把队列当实播。脚本自带product_snapshot可作为该稿历史资料依据，当前商品库只代表当前事实，不能回填成旧场当时的资料。

### A5 监控台和测试入口

在现有房间配置/监控流程中加入Agent模式、模拟事件注入、提案、依据、批准/拒绝、执行状态和导出归档。原商品库和直播间主流程保持清楚；不再做一套重复商品库。模式为observe、manual_confirm、limited_auto，首版默认observe。

测试页面显示“模拟问题”和“真实播放器回执”来源；播出画面只放消费者需要的信息，调试信息留在监控。保持可复制的OBS窗口链接。提供紧急停止Agent按钮，停止新决策和新动作；单独保留人工停止直播按钮，二者含义不同。

## 四 独立运行与并行依赖

先用ReplayModel、FakeRoom、FakePlayer实现一条端到端路径，模块暂用合同样例替身；不等待B/C/D。FakePlayer用可控时钟发started/ended/interrupted，所有回执标simulated。共享模型和工具通过依赖注入，各模块不能访问动作执行凭据。样例的fixture_operator批准只适用于隔离模拟，不能被真实网关视为人工批准。

跨场模型并发首轮建议最多3个请求，为正在直播的决策预留1个位置，准备和复盘使用其余位置；没有直播时可回收空位。不得声称能抢占已经在远端执行的请求。记录排队等待，播中超过有效期则放弃旧提案；具体并发根据限流与时延实测调整。

公共目录优先发布最小类型、模型接口和样例测试命令；其他组之前可用本地兼容类型。共享依赖由你统一锁定，各组在自己的dependencies.md提出新增需求，避免并行改根配置。

## 五 验收门槛

| 环节 | 必须证明 | 失败出口 |
| --- | --- | --- |
| 合同 | 四模块输入输出通过同一验证器，旧版本明确拒绝/迁移 | invalid_input或version_conflict |
| 发布 | 未批准、资料变化、房间商品不匹配均不能进入正式队列 | 明确阻断项，不偷偷换商品或稿 |
| 执行 | 重复动作不重复插播；同ID不同参数拒绝；人工切换使旧提案失效 | rejected或unknown，不能伪成功 |
| 声音 | 本机来源实际发声，action→attempt→ended关联；打断和恢复语义正确 | paused/error/unknown，保留证据 |
| 归档 | 新场切换后仍保留旧场；日志超限不丢合同要求的历史 | 标记缺口、阻止无依据完整声明 |
| 故障 | 发送前/后、回执前/后重启；取消、断连、旧owner回执 | 旧动作不盲目重播，状态可解释 |

另运行现有tests/test_rooms.py、test_playback.py和test_audio_player.cjs回归，记录实际命令与结果，不只报告新增测试。OBS需本地录制核对收音；浏览器ended不足以证明OBS/抖音链路成功。完整验收采用06。
