# 14 任务成果验收与播前素材准备

合同增量 `PRELIVE-2.3`，设计稿，尚未实现。本文与[13](13_任务识别与历史上下文设计.md)的任务判断、研究历史和上下文合同配合；`TaskAssessment` 以13的唯一正式 schema 为准。本文定义可信的任务验收层与首期素材清单，不增加一个拥有自由裁决权的“验收 Agent”，不实施视频生成、素材自动发布或实时画面 hook。

## 1. 本次任务完成与整场准备完成是两个判断

“分析这个商品”“更新商品资料”“改这句活动稿”“再生成一版”和“准备整场声音”有不同的交付边界。验收必须回答：**这次用户实际要的成果，是否已经真实形成、保存、可回读，并且没有超范围修改。**

| 判断层 | 负责者 | 不能代替什么 |
| --- | --- | --- |
| 判断用户这次想做什么 | 主 Agent 提议 `TaskAssessment`；可信控制器依据原用户事件、选区和权限校验 | 模型不能自行把“更新商品”扩大成“全部改稿并开播” |
| 固化本次交付要求 | `AcceptanceCompiler` 读取原 `GoalContract`、可信用户决定、评估提议与固定规则模板 | `TaskAssessment` 自选了哪些能力，不代表这些就自动成了用户目标 |
| 验收实际成果 | `CompletionService` 与声播只读验收查询，回读业务对象、版本、hash、job回执及修改证据 | 不能相信模型总结中的“已完成”或只看 job accepted |
| 评价开放文本质量 | 可选独立语义评测调用和人工校准量表，记录样本/依据/版本 | 一次模型评分不能保证事实真实、权限正确或已经提升转化 |
| 结束本次执行 | 现有 `finish_turn` → `CompletionGuardMiddleware` → Coordinator | 不另建一套与运行状态冲突的结束机制；不代替人工批准、采用和开播 |

**用户本轮确认的默认边界：**普通 `catalog_update` 更新商品与顾客场景研究，并给出受影响话术清单；没有明确改稿指令时，不自动执行话术修改，也不以“没生成新话术”判定该任务失败。是否只更新商品某字段且不触及研究，由原指令、实际依赖变化和明确限制共同决定，13定义任务及影响判断。

## 2. 每类任务究竟验收什么

本表是验收模板，不要求每次依次执行八行。任务可以组合；可信服务按原用户目标组合要求，互相冲突的要求先澄清。

| 本次用户目标 | 必须存在的成果 | 必须检查的实质 | 本次不要求、不自动做的事 |
| --- | --- | --- | --- |
| 仅商品事实分析 | 当前输入对应的 `ProductFactsReport`；来源和逐字段状态；相似商品/冲突/缺项 | 报告已由主接受到声播、可回读；明确事实/未知区分；没有按同名覆盖商品 | 不强迫保存商品、不强迫顾客研究、生成话术、TTS或房间准备 |
| 更新商品资料，默认联动研究 | `ProductAssembly`审计、保存后的精确商品 ref、有效研究 ref或经依赖核验的复用决定、受影响话术清单 | 指定字段值符合用户要求；schema路径有处理状态；无关字段保留；研究针对本次变化更新或解释未受影响；话术清单可定位到具体版本/模块和原因 | 不自动改稿、不自动附加版本、不改顺序、不合成语音；不存在旧稿时清单明确为空并说明查找范围 |
| 仅本场配置分析/保存 | 对应 `SessionConfigReport`；用户要求保存时还需当前 `SessionDraft` ref与diff | 指定本场字段/有效期/优惠条件正确；日常商品不受污染；历史配置逐项继承/失效/未知有记录 | 仅要求分析不强制写draft；保存draft不强迫研究、改稿或TTS |
| 仅顾客场景研究 | 当前有效 `AudienceScenesReport`、历史关系/复用或更新理由、证据/假设/未知、素材建议 | 与目标商品/市场相关；不是无来源的规格“事实”；接受后可跨任务读取；搜索失败明确降级 | 不自动重写商品卖点、不自动改本场配置或话术；素材建议不等于已制作素材 |
| 修改指定话术 | 指定基准上的新 `ScriptRevision`、发生变更的模块/句、diff、计划执行回执 | **目标文字实际存在且可回读**；引用条件与当前配置一致；只改授权模块；未变ID/hash保留；生成job已完成而非受理 | 不自动新建其他variant、不自动改playlist、TTS、采用或开播；所需范围超出授权先确认 |
| 另生成一个版本 | 新 `variant_id`及实际 `ScriptRevision`、指定模块完整正文、依据/计划和生成回执 | 新variant与原稿修订关系正确；正文非空；不是只生成一个标题/版本占位；所需模块存在；旧版本保持 | 不自动进入playlist、不自动生成所有长短开场音频、不自动采用 |
| 用户排序/选择重排方式 | 用户决定凭据、原item集合与重排后 `PlaylistDraft`（服务别名Playlist）、确定性重排信息、要求编译时的 `CompiledPlaybackPlan`（早期别名PlaybackPlan）/缺项 | occurrence ID集合及数量不丢不增、每项product_id和精确script_revision_ref不偷换；只重排用户选中项；按确认方式生成顺序；长开场按原编排位置重新计算；缺开场文本显式列出 | 排序完成不等于音频或整场ready；不重写正文、不替用户增加商品/版本、不自动合成 |
| 仅准备获准声音 | 当前编译计划/requirements、有效人工文案批准、实际所需音频manifest与job完成回执 | 所需集合精确；缓存/新音频文件完整且voice匹配；未知结果不得当成功；严格维持人工批准 | 不强迫新跑事实/研究、生成视觉清单、改稿、重排、发布candidate或开播 |
| 准备完整本场并生成声音 | 有效商品/研究/draft、完整bundle和计划、实际所需脚本、素材需求清单、用户playlist、编译、有效人工文案批准、音频manifest、未采用candidate | 每个required产物可回读且依赖当前；脚本/句映射准确；批准绑定本场精确文本和voice；音频文件实际有效；candidate检查通过 | **未要求的视觉素材不齐不阻塞声音ready**；不自动采用/开播；不要求生成视频或直播效果证明 |
| 只读说明/解释 | 与本次问题匹配的回答、所引用的可读业务refs/来源和未知项 | 回答不虚构对象状态；读取权限和事实当前性可查；没有写入副作用 | 不强制存商品、报告、稿件、素材清单或candidate |

“本次只做文案，先不生成声音”的组合目标，以真实脚本及该Goal要求的清单交付 `COMPLETED`；没有语音批准或TTS不构成缺口。“准备到人工审稿”为明确终点时，可完成该交付，但前端必须写清“文案已备好、声音未生成”，不能标成整场可采用。`prepare_session`仍须读取本次明确终点和allowed_effects，不因有这个objective就一律要求完整candidate；仅整理本场配置按对应子目标验收。需要人工作出当前任务内的决定时用现有 `WAITING_USER`，不能伪造已批准。

## 3. 可信验收类型

以下为模块签名和数据约束；已有 `ArtifactRef/RecordRef/TargetRef/DependencyRef/GoalContract` 直接复用01，不另造同名基础类型。

```python
class AcceptanceRequirement(BaseModel):
    requirement_id: str
    rule_key: AcceptanceRuleKey       # 固定注册的规则，不接受eval/任意代码
    severity: Literal['blocking', 'advisory']
    target_refs: list[TargetRef]
    expected_evidence_kinds: list[str]
    expected_values: dict[str, JsonValue]
    source_goal_paths: list[str]      # 对应原Goal及可信用户事件
    when: PredicateSpec              # 固定typed条件，不能是LLM生成的Python

class GoalAcceptanceSpec(BaseModel):
    id: str
    revision: int
    run_id: str
    goal_hash: str
    task_assessment_ref: ArtifactRef | None
    user_decision_refs: list[ArtifactRef]
    requirements: list[AcceptanceRequirement]
    forbidden_effects: list[ForbiddenEffectRule]
    baseline_refs: list[RecordRef | ArtifactRef]
    policy_version: str
    content_hash: str

class AcceptanceCheckResult(BaseModel):
    requirement_id: str
    status: Literal['passed', 'failed', 'pending', 'not_applicable']
    severity: Literal['blocking', 'advisory']
    evidence_refs: list[RecordRef | ArtifactRef]
    observed_values: dict[str, JsonValue]
    explanation: str
    repair_actions: list[TypedNextAction]

class GoalAcceptanceResult(BaseModel):
    id: str
    run_id: str
    spec_ref: ArtifactRef
    observation_hash: str
    checks: list[AcceptanceCheckResult]
    forbidden_effect_violations: list[EffectViolation]
    outcome_allowed: list[RunOutcome]
    evaluated_at: datetime
    readset: list[DependencyRef]
    output_destinations: list[ArtifactDestination]
    content_hash: str
```

`expected_values`只可由可信意图/用户决定/当前业务条件构造，不能让模型填入“期待自己这次生成的内容就是正确内容”。`not_applicable`需有可核验条件，例如“没有已存在话术，依权限查询索引为空”；模型一句“不适用”不够。脚本、素材和分析正文仍在声播保存，验收结果只引用它们。

### 3.1 保存位置和边界

| 内容 | 权威与保存 | 当前性 |
| --- | --- | --- |
| 原Goal、TaskAssessment、编译后的Spec | Agent运行库不可变artifact；runs保存ref，图内只保存ref与短观察 | 用户新任务新run；原Goal不就地改；扩大授权仍走replace |
| 业务成果及其保存/受理/完成回执 | 声播业务库及outbox，按01/03 | 不能以Agent暂存报告替代已接受成果；不能以checkpoint代替业务提交 |
| `GoalAcceptanceResult` | Agent运行库不可变artifact，结果含声播观察refs/hash和本地运行观察 | 结束前复验readset；改变后结果保留为历史、失效，不改写原结果 |
| 验收执行过程 | 11的trace事件/安全原文 | 可看到用了哪个Spec、读哪些ref、哪一规则失败；不执行日志回放中的写操作 |

声播不跨库读Agent文件。现有 `read_completion_observation` 接收可信服务发送的Goal和受限typed验收请求，按固定读取规则返回业务证据。Agent侧编译器校验这些要求与原Goal一致；声播侧仍独立核验principal、scope、ref访问权，不接受任意SQL/函数名/文件路径。

## 4. 规则集合与验收算法

### 4.1 硬验收和语义评价分开

| 规则组 | 必须回读的依据 | 结果语义 |
| --- | --- | --- |
| 产物真实性 | 存在的精确ref、hash、schema、非空必要模块/句、有效receipt、job终态 | 没有实际脚本即失败；排队job只能pending |
| 原始目标覆盖 | 原Goal各项要求→成果映射；明确本次终点 | 漏掉用户明确要的研究、稿件或素材清单即失败，不可用总结掩盖 |
| 范围与保留 | 执行前基准、change_log、允许effects和模块/字段allowlist | 越权变更阻断；指定保留字段/句hash应保持 |
| 当前性与冲突 | product/draft/plan/readset、人工决定版本、scope/grant | 过期或同名身份未确认时拒绝“完成保存” |
| 业务条件 | 金额币种、优惠门槛/有效期、模块中的结构化条件引用 | 不凭模型自评宣称报价正确；自由文字中的疑似数字另标审查 |
| 研究与复盘覆盖 | 完整研究refs/证据性质、历史差异、`AudienceResearchBinding`、`ResearchResolution`及对应验证/保存回执、finding处置和实际diff | binding与所消费依赖当前；复用/增量/细化有真实证据；不把复盘建议变成商品事实；计划与实际不符须失败或明确未完成 |
| 顺序与开场 | 重排前后item ID多重集合、用户决定、seed/方式、编译输出 | 不漏项不增项；第1/6/11长开场；已应用且绑定编排实际变化才使旧批准失效；预览／取消／no-op不失效 |
| 声音ready | 当前批准、精确required集合、音频hash/文件/时长格式、manifest | 零需求空集合不能伪称整场ready；未知供应商结果不是成功 |
| 素材清单 | 已保存Checklist、建议与来源映射、已有文件完整性 | 清单应存在时缺失阻断对应任务；可选视觉缺文件仅advisory |
| 文案质量 | 语义评测样例、规则、原文、模型版本及可解释结论 | 用于改进；未校准分数不自动变成硬质量门槛 |

数字、价格、日期在结构化数据和明确槽位中的一致性可以确定性检查；任意自然语言的事实外延仍可能需要模型/人工复核。设计不宣称规则检查能证明所有自由文案语义必然真实。

### 4.2 模块和函数合同

```python
# Agent: acceptance/compiler.py
def compile_goal_acceptance(
    goal: GoalContract,
    assessment_ref: ArtifactRef | None,
    trusted_intent: VerifiedIntentEvent,
    decisions: list[VerifiedDecision],
    policy: AcceptancePolicy,
    baselines: list[RecordRef | ArtifactRef],
) -> GoalAcceptanceSpec: ...

# Agent: acceptance/service.py
async def evaluate_goal_acceptance(
    scope: RunScope, spec_ref: ArtifactRef,
) -> GoalAcceptanceResult: ...

async def require_current_acceptance(
    scope: RunScope, result_ref: ArtifactRef, requested_outcome: RunOutcome,
) -> ValidatedAcceptance: ...

# 声播：现有read_completion_observation的受限typed扩展，不新增任意读取工具
def collect_completion_evidence(
    request: CompletionObservationRequest, *, principal: Principal,
) -> CompletionObservation: ...

# 可选语义评价：既有生成/评测服务受控一次调用，不授予写权限
async def evaluate_script_quality(
    script_refs: list[ArtifactRef], rubric_ref: ArtifactRef,
    context_refs: list[ArtifactRef], *, evaluation_scope: EvaluationScope,
) -> SemanticEvaluation: ...
```

算法顺序固定：

1. 用原Goal、可信用户事件及固定模板编译Spec；TaskAssessment作为目标理解和依赖提议，不可降低原要求。若语义冲突无法确定，QuestionService先澄清，不凭低置信度决定写目标。
2. 根据Spec生成有限的证据读取计划；读取声播一致快照/精确refs，以及Agent侧已登记的分析任务、问题与监听信息。
3. 对每项要求运行固定规则，按`passed/failed/pending/not_applicable`保存证据和下一动作；拒绝缺证据的通过。
4. 检查发生过的所有修改是否落在原Goal允许范围；检查要求保留的基准，不仅检查最后一个产物。
5. 需要时运行可选语义质量评价；结果原文留存。质量建议不能覆盖硬失败或伪造外部效果。
6. 保存不可变Result及readset；用于`finish_turn`。真正发送终态前，Coordinator经RunFinalizer冻结派发、撤权收尾并复验业务证据；原Goal内可修复且尚未进入收尾时可回到读取/局部补齐，已收尾后的证据过期则以带blocker的实际结果闭合。最终复验不要求已关闭run的grant仍active；依赖RunClosureReceipt和业务证据，不把旧验收当本轮成果。

验收本身只读业务。修复通过主 Agent 调用既有typed业务工具，每次写入仍经M5/声播事务；验收服务不能悄悄修改结果使其“通过”。

### 4.3 接入现有 Harness

```text
可信用户事件 → 原Goal + 主Agent任务评估
  → AcceptanceCompiler编译/保存Spec
  → 按需调用分析/保存/生成/排序等能力
  → finish_turn请求结束
  → CompletionService读取业务证据 + evaluate_goal_acceptance
  → 缺项：返回具体blocker/合法next_actions，主Agent补齐或等待
  → 满足本次Goal：保存TurnReceipt(acceptance_result_ref)
  → M7 CompletionGuard复验回执与结果当前性
  → Coordinator发送带真实成果定位的完成事件
```

`finish_turn(outcome, summary)`对模型的签名保持不变。服务不接受模型传`passed=true`、自造Result或降低Spec。原有最多两次Guard纠正仍保留；缺成果不能无限循环自我修复。分析子Agent的M8只验证typed PREPARED报告，主最终成果验收另查ACCEPTED，不混淆两个阶段。

| 结束请求 | 服务允许条件 |
| --- | --- |
| `COMPLETED` | 本次Goal所有适用blocking要求通过，且无越界变更；成果可以只是已保存商品/研究/稿件/顺序，不强迫candidate |
| `READY_FOR_REVIEW` | 本次要求完整本场准备，且声播当前candidate实际ready_to_adopt；仍未采用、未开播 |
| `WAITING_JOBS` | 关联任务已持久受理、尚未完成且存在真实监听；不得声称稿件/音频已完成 |
| `BLOCKED` | 有可定位且不能自动完成的阻塞；保存已完成部分和缺口，不能说全部完成 |
| `WAITING_USER` | 仍来自真实QuestionService/interrupt，不由模型在finish中自报；语音批准是可信human回执 |

## 5. 首期“准备素材”的范围

首期交付的是**素材需求与准备状态**，以及用户已经拥有、已经上传或合法引用的文件。Agent分析需要展示什么、为什么、对应哪个场景/卖点、现有资料够不够。已有商品图片、上传的说明书/截图和OCR原件可以复用。没有文件时展示“建议准备/待补充”，不能用一个建议文本假装生成了图片或视频。

| 类别 | 本期内容 | 例子 |
| --- | --- | --- |
| 已有素材复用 | 关联已上传文件；检查完整性与相关商品；保留原始图/OCR定位 | 拖鞋商品主图、尺码表、足弓结构局部图 |
| 场景/效果建议 | 根据顾客顾虑说明需准备什么演示，不假设效果已被证实 | 口红：真实上嘴效果及不同光照；家具：多角度/尺寸参照；拖鞋：足弓结构、鞋底纹路和受控防滑演示 |
| 本场素材清单 | 从商品级复用需求筛选本场涉及的条目；显示文件、缺口、可选性 | 本场讲舒适与清洗时，建议准备结构图和冲洗演示；不自动把素材放进播放器 |
| 文件状态管理 | 可回读引用、来源、hash、可预览性、关联用途；更新同清单CAS | 文件损坏标invalid；没有上传标missing，不编一个下载URL |
| 后续能力 | 本期不实施，清单可保留future候选提示 | 图片生成视频、360度自动合成、口播卖点触发视频、实时画面hook |

防滑演示只能作为商家可提供的演示需求，不能据此新造防滑等级或保证湿地绝不滑倒；家具多角度不意味着仅靠一张图能真实重建360度；口红上嘴图不能在没有实际素材时声称为真实试用效果。

## 6. 素材类型、文件与存储

```python
class AssetFileRef(BaseModel):
    id: str
    blob_ref: ArtifactRef             # 现有受控业务blob；禁止任意宿主路径
    source_manifest_ref: ArtifactRef | None
    source_locator: str | None        # 原文/截图/页定位
    mime_type: str
    file_hash: str
    original_name: str
    product_ref: RecordRef | None
    source_kind: Literal['merchant_upload', 'catalog_existing', 'external_reference']
    source_url: str | None
    usage_basis: Literal['merchant_provided', 'owned', 'licensed', 'unknown']
    usage_note: str | None
    verification: Literal['verified', 'invalid', 'unavailable']
    # verified只指文件完整/可读取，不证明宣传效果或授权法律结论

class AssetRequirement(BaseModel):
    requirement_id: str
    product_ref: RecordRef | None
    purpose: str
    suggested_type: Literal['image', 'video', 'document', 'demonstration', 'other']
    requested_content: str
    scene_insight_refs: list[ArtifactRef]
    selling_point_refs: list[TargetRef]
    source_refs: list[ArtifactRef]
    target_module_keys: list[ModuleKey]
    existing_file_refs: list[AssetFileRef]
    availability: Literal['available', 'partial', 'missing', 'not_needed', 'unknown']
    priority: Literal['recommended', 'optional']
    reason: str
    user_disposition_ref: ArtifactRef | None

class AssetChecklist(BaseModel):
    id: str
    revision: int
    scope: WorkScope
    product_refs: list[RecordRef]
    preparation_ref: RecordRef | None
    requirements: list[AssetRequirement]
    source_report_refs: list[ArtifactRef]
    prior_checklist_ref: ArtifactRef | None
    readset: list[DependencyRef]
    unresolved: list[AssetGap]
    content_hash: str
```

商品级Checklist在`catalog` scope保存，可长期复用；本场Checklist在`preparation` scope引用商品级精确清单/文件与本场新增需求，不复制一份可编辑商品正本。更换商品/场景/本场主题时按消费路径失效或重绑未变需求，不删除旧文件和历史清单。商品级文件变更只有在本场明确刷新引用后进入本场；采用快照不被自动改写。

`business_artifacts`保存`asset_checklist`及修订；`business_blobs`保存实际文件或受控上传原件；可增加`asset_file_links`索引来查商品/清单/文件关系，正文仍只有上述一个业务正本。外链只作来源引用，未下载/未验证时不能标成已可播放文件；当前应用的上传入口负责文件校验与受控导入，不由模型任意下载可执行文件。

`usage_basis=unknown`如实记录，不因为缺一个来源声明就膨胀出首期审批产品。它可以产生advisory；用户明确要求“只允许已授权素材”时，可信Goal为该素材交付增加对应要求，不能把unknown报成已授权。

### 6.1 素材建议怎样进入正式清单

| 步骤 | 执行动作 | 可用上下文/工具 | 产出 |
| --- | --- | --- | --- |
| 研究时 | audience_scenes分析顾虑、场景和可视化需求；区分事实与建议 | 分配的商品/研究历史、原图索引、来源、必要搜索 | 报告`asset_suggestions`，尚不是已制作素材 |
| 主接受后 | 汇总有效建议；按用途去重；查已存在清单和文件；不把语义相似当同一文件 | `read_asset_checklist`、`read_product`、`read_source/read_blob`与accepted报告 | Checklist提议和已有/部分/缺失状态 |
| 保存时 | 验证ref归属、hash、来源、场景/卖点映射和scope；CAS保存 | `save_asset_checklist`固定命令 | 声播正式Checklist回执、变更事件 |
| 本场汇合 | 引用本场实际涉及的商品需求和文件；保留未准备项 | product checklists、研究、本场draft、已选稿 | 本场Checklist、advisory gaps；不增加TTS需求 |
| 任务验收 | 需要清单的Goal检查其真实存在和来源；文件状态逐条回读 | CompletionService、只读查询 | 清单要求通过/失败；可选视觉缺口显示advisory |

单纯用户排序或只改金额无需新跑素材分析。现有清单未受影响可直接复用；只有明确相关的变化才补齐需求。全文生成任务没有可用研究或没有任何适用视觉需求时，可以保存空清单，但必须携带查询/研究范围与“无需新增”的依据，不能用空对象绕过应有产物。

| 用例 | 输入/故障 | 可观察断言 |

确定性指标：原Goal要求映射覆盖率100%；声明完成的成果可回读率100%；精确hash/引用校验通过率100%；未授权变更0；假成功0；未变字段/模块保留100%；应有素材清单持久化率100%；素材文件存在状态误报0；模拟来源标签保留100%。

语义指标另列：场景贴合度、卖点易理解程度、多个版本区别、口语自然度、建议素材的可执行性。先用用户样例和人工复核校准量表，再记录多次真实模型结果；不在设计阶段编造“90分通过”或转化率提升结论。
