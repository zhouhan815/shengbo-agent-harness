# 11 原始运行记录与调试台设计

合同增量：`PRELIVE-2.3-observability`。本文是待实现工程设计，不代表日志、调试台或下列接口已经开发。保留既定九个自定义中间件；扩展 M9 `AuditMiddleware`，增加 SDK 回调、协调器记录和声播任务记录，不新增一个会改变业务决策的“日志 Agent”。

## 1. 交付目标与“原样”的准确含义

一次播前任务应能回答：谁接受了用户要求；主 Agent 为何派发哪些分析；子任务实际上何时并行；每次模型实际收到什么可观察输入、输出了什么；调用了什么工具、参数和结果是什么；哪些权限或版本检查拦截了动作；谁确认了哪份话术；为什么改这个模块而保留另一个；失败、重启和取消之后发生了什么。

“原样”指：**采集时保存完整的可观察应用消息和工具输入输出；展示时不让另一个模型改写，不用摘要替代原件，不因上下文压缩删除日志原件。** 普通日志不散落商家全文，全文进入受控的本机调试记录。原始记录和方便阅读的投影视图分开；投影中的标题、状态和统计可重建，不能回写原始事件。

边界固定如下：

| 可直接保存和展示 | 不作不存在的承诺 |
| --- | --- |
| 实际发送的应用层 system/messages、工具 schema 与模型参数；实际返回的公开响应；模型显式给出的决策摘要；工具参数及完整结果；异常；引用快照；检查与确认回执 | 不推测或还原供应商未公开的内部思维链；不把程序推导的解释伪装成模型原始思考；不把 SDK 对象的 `str()` 冒充 HTTP 原始响应 |
| 可观察的公开响应块保留类型和顺序，不展开供应商标为私有或不可展示的载荷 | 没有收到的 token usage、首字延迟或供应商请求 ID 显示 `unknown`，不得补造 |
| 每份正文保存编码、字节数和 SHA-256；界面可折叠、分页、下载全文 | 预览限制只是界面限制，不能先把正文截断成 200 字再保存 |
| 采集前去掉认证头、密钥、cookie、签名查询参数，写明被去除的字段路径 | 密钥不进入原始日志再事后遮盖；“原样”不包含保存凭据 |

商家原始资料与可观察请求正文属于本机敏感业务数据：默认只保存在用户电脑，拥有与商品原资料相同的本机访问控制；首期不自动上送 LangSmith 或其他云端日志平台。日志不作为模型长期记忆，不自动整段灌回 Agent。

## 3. 记录分层与数据所有权

### 3.1 四层记录

| 层 | 保存位置与责任 | 内容 |
| --- | --- | --- |
| 正式业务事实 | 声播业务库：业务对象、operation receipt、change log、同事务 outbox | 商品/话术/确认/语音任务到底是否提交成功；业务真值 |
| 运行事实 | Agent 库：run、invocation、branch task、question、调度 inbox/outbox | 谁被调度、在等待什么、恢复位置、谁已撤权；运行真值 |
| 原始可观察记录 | 各服务本机 `observability.sqlite`＋内容寻址 blob 目录 | 全量输入输出、span 生命周期和上述事实的事件副本；诊断证据 |
| 阅读投影 | 调试投影表及浏览器内查询结果 | 树、时间线、摘要统计、diff、错误聚类；可删除重建，不是业务状态机 |

每个服务一个 `source_instance_id` 和本地单调 `source_seq`。声播事件桥可把声播记录镜像到 Agent 调试索引；镜像保留原 `event_id/source/source_seq`，不能分配一个新的“原始发生顺序”。不存在跨两个 SQLite 的原子总顺序；界面按照因果连接，时间排序仅用于阅读。


## 4. 因果标识与原始事件合同

### 4.1 所有阶段使用的关联 ID

| 标识 | 意义及产生者 |
| --- | --- |
| `conversation_id`、`preparation_id` | UI会话和本场准备业务容器；全局商品操作可无 preparation |
| `run_id` | 不可变用户任务，可信入口产生；等待/恢复不换 run |
| `parent_run_id` | follow_up/replace/继承来源，独立于 SDK 回调父子关系 |
| `invocation_id`、`lease_epoch` | 本次图执行和执行者租约；同run重启产生新 invocation |
| `batch_id`、`branch_task_id`、`branch_role` | 持久并行分析单位；不把三个子任务伪装为三个普通聊天消息 |
| `span_id`、`parent_span_id`、`link_span_ids` | 一次操作的开始/结束及因果；后台任务跨调用以 links连接 |
| `sdk_run_id`、`sdk_parent_run_id` | SDK回调提供的调用ID；不得覆盖业务run_id |
| `message_id`、`tool_call_id` | 实际消息和模型工具调用ID；重放保留已有ID |
| `operation_id`、`job_id`、`vendor_request_id` | 业务命令幂等ID、后台job、可观察供应商请求标识 |
| `decision_id`、`review_ref` | 问题/审批及其精确绑定内容，不以一条“同意”通用于所有动作 |
| `event_id`、`source_seq`、`span_seq` | 去重ID、本服务持久事件顺序、同一span内的追加顺序 |
| `caused_by_event_id` | 直接原因：原用户事件、派发回执、job终态或真实用户答案 |

SDK回调和应用层工具边界可能同时看到同一工具，必须映射同一个 span：`(invocation_id, sdk_run_id)`索引到 span；工具层再关联 `tool_call_id`。业务提交使用另一个子 span，不能把工具重试与业务 receipt 当同一次请求。

`metrics`包含 provider/model、model_purpose、attempt、queue_ms、duration_ms、ttft_ms、token input/output/cache、provider reported cost或unknown、TTS字符量和音频时长。真实模型标识与服务配置快照要留下，避免切模型后无法复现。SDK摘要、普通推理、声播话术生成分别标 `model_purpose=context_compaction/agent_reasoning/script_generation`，不能把费用只归主Agent第一层。

JSON payload采用UTF-8确定性序列化保存；字符串不修改换行、标点、Unicode正文，不能用repr/default=str吞掉结构。模型消息序列化显式保留role、content blocks、message IDs、tool_calls、tool_call IDs、公开 response metadata/usage及schema版本；未知对象用版本化serializer报可诊断错误，不悄悄字符串化。二进制图片/音频保存文件hash与原文件引用，界面按需读取，不把base64复制进每一条事件。

## 5. 自动采集点：不是让模型自己“记日志”

### 5.1 必须接线的采集矩阵

| 实际执行点 | 记录内容／事件 | 接线位置 |
| --- | --- | --- |
| 接受指令、follow_up、replace、排队、授予/撤销写权 | 冻结原用户要求、目标选区、readset、队列位置、原因、回执 | IntentController/RunCoordinator事务outbox |
| 主图每次进入、等待、恢复、退出 | 输入事件、checkpoint引用、generation/lease、真实状态 | `drive_run`和恢复协调器；不是仅依赖after_agent |
| 派发分析batch | 角色、任务输入manifest、依赖、并发上限、dispatch receipt | `dispatch_analysis_batch`同事务outbox |
| 子任务领取、排队、运行、心跳租约丢失、完成 | 主子关联、真实开始结束、报告ref、失败分类 | JobSupervisor/`run_branch` |
| M1–M8允许/拒绝／特殊分支 | 中间件名、hook、检查对象版本、规则版本、reason code | 各中间件调用同一Audit接口；pass可折叠，deny必须可见 |
| 模型实际请求／返回／重试／中断 | 公开messages、tools/schema、模型参数、公开响应、usage和请求ID | M9建span；SDK `AsyncCallbackHandler`采实际模型输入输出；受控模型适配器补应用请求配置 |
| 工具请求／返回／失败 | 完整参数、完整结果、ToolMessage实际可见内容、错误与耗时 | M9与SDK工具回调去重合流；业务HTTP子span单独关联 |
| Skill发现与加载 | 角色、目录摘要hash、实际read_file路径/范围及正文hash | 工厂manifest＋read_file工具记录；不凭prompt推测已加载 |
| 动态上下文组装／SDK压缩 | observation/bundle refs、最终可见请求、压缩前后hash、摘要输入输出、压缩模型usage | ContextProjection产物记录＋模型callbacks；不改写旧payload |
| 分析报告PREPARED／ACCEPTED | 原暂存全文、输入版本、接受或拒绝理由、正式回执 | 报告提交、接受工具和声播命令outbox |
| 复盘读取与采纳 | 原文和条目ref、simulation标记、对当前目标的适用性、采纳/拒绝/待确认原因、关联模块 | 复盘解析/策划工具；记录显式结构化判断，不伪造内部思考 |
| 补问／人工确认／拒绝／过期 | 问题正文、选项、精确目标、版本、真实用户答案、恢复event | DecisionService先持久化，再恢复图 |
| 业务生成与TTS | 全量生成请求／公开结果、模块/句ref、vendor attempt、失败/未知、落库回执 | 声播JobRunner与供应商adapter；它们不经过主Agent的M9，必须单独埋点 |
| 最终成果、语音批准、候选、采用、开播 | 精确内容hash、actor、权限来源、receipt和前后版本 | 声播命令服务事务outbox；Agent不能自行写“人工已确认” |
| 浏览器断线、重连、导出 | cursor、水位、重放范围、导出人和数据hash | EventGateway/DebugAPI；UI关闭不取消任务 |

M9观察、记录，不新增决策，不接管重试。预算、权限、审批仍由既定模块控制；日志不替代数据库fence或真实执行回执。

### 5.2 SDK 回调装配与可观察范围

在 `drive_run` 和 `run_branch` 的 config 中显式注册同一 `TraceCallbackHandler`，metadata包含可信业务IDs；独立worker图不会继承主图callbacks，supervisor必须给每次调用传入。主/子图是单独调用，不能仅依赖 `subgraphs=True` 就声称子图记录齐全。

```python
config = {
    'configurable': {'thread_id': thread_id},
    'callbacks': [deps.trace_callbacks.with_scope(scope)],
    'metadata': {'run_id': scope.run_id,
                 'invocation_id': scope.invocation_id,
                 'branch_task_id': getattr(scope, 'branch_task_id', None)},
}
await compiled_graph.ainvoke(input_or_resume, config=config, context=scope)
```

本机SDK `langchain_core/callbacks/base.py`已核验 `on_chat_model_start/on_llm_new_token/on_llm_end/on_llm_error/on_chain_start/on_chain_end/on_chain_error/on_tool_start/on_tool_end/on_tool_error/on_retry` 的异步回调。签名必须保留规定位置参数及 `run_id/parent_run_id`，不使用破坏回调fallback的任意签名。

`on_chat_model_start(serialized, messages, *, run_id, parent_run_id, **kwargs)`是最终可观察模型消息的主要采集点；M9外层记录的request可能早于后续Skills/摘要变更，因此UI明确区分 `harness_request` 与 `effective_model_messages`。供应商adapter只补其公开请求参数，不能从未经允许的内部端点取数据。流式chunk按span顺序保存；末尾完整响应单独保存并校验可重组部分。没有启用流式的调用，ttft显示unknown。

LangGraph checkpoint保存用于执行恢复，trace保存用于观察；二者不同。未结束span必须显示“中断/待对账”，不能因SDK图已有checkpoint就伪造一个工具成功事件。

### 5.3 函数接口和异常语义

```python
class CaptureService:
    async def persist_payload(self, value: object, *, schema: str,
                              stage: str, policy: CapturePolicy) -> PayloadRef: ...
    # 先去凭据→显式序列化→写tmp+fsync→hash→原子重命名→登记blob。

class TraceJournal:
    async def append(self, event: NewTraceEvent, *, dedupe_key: str) -> TraceEvent: ...
    # 同SQLite事务分配source_seq并追加；相同key返回原事件，不UPDATE旧事件。
    async def begin_span(self, scope: TraceScope, kind: str,
                         input_refs: list[PayloadRef]) -> SpanHandle: ...
    async def close_span(self, handle: SpanHandle, terminal: SpanTerminal) -> None: ...
    # 以新event终结span；重复close返回一致回执，互斥terminal报冲突。

class TraceProjection:
    async def build_run_tree(self, run_id: str, watermark: Cursor) -> RunTreeDTO: ...
    async def timeline(self, query: TimelineQuery) -> Page[TraceEventSummary]: ...
    async def compare(self, left: PayloadRef, right: PayloadRef) -> DiffDTO: ...

class TraceRecovery:
    async def reconcile_open_spans(self, source_instance_id: str) -> RecoveryReport: ...
    async def mirror_business_outbox(self, cursor: Cursor) -> Cursor: ...
    # 只能追加receipt_observed/abandoned/outcome_unknown等真实证据。
```

必须区分执行异常与记录异常。尤其禁止：业务写入已成功→`audit.end`失败→包装器把它当业务失败→自动重跑写入。M9保留原result/原异常，终结日志失败写应急记录，并令协调器暂停**后续**新动作；当前工具结果按正式receipt返回或进入对账。

工具调用前的持久start写不成功，尚未执行副作用时应停止新动作，返回 `OBSERVABILITY_UNAVAILABLE`；不得静默运行且声称有完整轨迹。工具执行后的失败记录由固定大小且`fsync`的应急JSONL兜底；写应急也失败时，stderr明确告警、健康状态转不可继续写。已经提交的命令结果从业务outbox恢复，不重做命令。模型响应记录失败同样标记gap并暂停后续行动，不能说已完整采集。

## 6. 状态、并发与恢复的显示规范

### 6.1 业务run与观察span分开

run状态继续使用既定 `QUEUED/ASSESSING_INTENT/AUTHORIZING/RUNNING/WAITING_JOBS/WAITING_USER/COMPLETED/READY_FOR_REVIEW/BLOCKED/FAILED/CANCELLING/CANCELLED/SUPERSEDED`，状态来自原协调器，不增加一个UI自创的“已完成”。审批如“话术审核后才能生成语音”以真实decision和WAITING_USER展示；阻塞原因具体显示审核内容hash。

span生命周期为 `started → succeeded/failed/denied/interrupted/cancelled/outcome_unknown/abandoned`。`recovered`、`retry_scheduled`等是后续事件，不把旧failed覆盖成succeeded；重试有新的attempt/span，链接原失败。子任务“已完成但未被主Agent接受”明确显示 `PREPARED`，正式接受后显示另一条 `analysis.accepted`。不要把等待主Agent接收的时间计入子模型推理时间。

### 6.2 并发时间线

```text
主任务 R1   接受→模型规划→派发 B1→WAITING_JOBS────────→恢复→合并→话术计划
商品分支 F1              排队→运行────────→PREPARED──┐
本场分支 C1              排队→运行────→PREPARED──────┤batch终态通知
场景分支 A1              排队→运行──────────→PREPARED┘
声播文案 G1                                                     生成→提交
人工审核 H1                                                              等待→同意
声播语音 T1                                                                         合成→提交
```

时间线显示排队和真实执行两个区间，允许看到“逻辑并行但因并发上限排队”。每个区间能点入原事件；同一thread不并行invoke。跨服务event不按接收时间强制串为同一个调用栈，后台job以 `caused_by_event_id/link_span_ids` 连到发起它的工具。

重启后的新invocation显示新的行或展开节点，保留旧调用结束为unknown的事实。恢复从receipt/checkpoint得到证据时追加 `recovery.evidence_observed` 并链接旧span；不能添加一个假想的旧完成时间。cancel后已在途供应商请求也保留，晚到结果标 `late_result_after_revoke`，可缓存不代表重新挂回当前计划。

## 7. 开发者调试台：呈现形式

在声播网页增加独立的**开发调试**入口，保留日常商品/配置/对话界面。默认只本机单用户可开，前端不直接读SQLite或blob路径。标准用户SSE仍只发送业务进度，原始prompt和工具原文只通过受控debug接口按需取回。

| 区域 | 显示内容 | 用它定位的问题 |
| --- | --- | --- |
| 顶部任务概要 | run、当前状态、输入版本、SDK/模型/Skill版本、总时长、tokens、费用已知/未知、记录完整度 | 是否同一次测试；有无缺记录；是不是换过模型 |
| 左侧执行树 | 用户任务→invocation→主Agent／batch→分支→模型／工具→声播job；可按失败、确认、复盘过滤 | 主子关系和失败所在层 |
| 中部泳道时间线 | 各角色排队、运行、等待与恢复区间；关键因果连线 | 是否真正并行；等待是模型、用户还是服务 |
| 右侧原始详情 | Request/Response、完整工具参数结果、公开异常、来源IDs、payload hash、去密字段 | 结果到底从哪里来；是否参数错或工具返回错 |
| 上下文面板 | 每次模型实际可见消息、加载Skill路径/版本、输入refs、压缩前后对照 | 错是信息没给、读错版本、没加载Skill还是模型判断 |
| 业务diff面板 | 原稿/新稿逐模块/逐句差异、保留ref、版本与operation receipt | 是否越范围修改；复用模块是否真的未改 |
| 人工确认面板 | 决策问题、绑定的文本hash/版本、用户原答、接受/拒绝/过期、恢复事件 | 是否漏问；是否用旧同意给新稿生成语音 |
| 复盘影响面板 | 原复盘条目、模拟标签、采纳/不采纳理由、影响模块、计划动作、最终diff | 复盘是否实际影响下一场，是否误当商品事实 |
| 导出按钮 | 全量事件、payload、manifest、版本、最小测试输入refs、hash校验 | 给其他窗口排查，无需手动复制截断console |

原始详情默认显示JSON原文／消息正文；“人话说明”是确定性字段标签或独立的显式决策摘要。不得把后生成的LLM解释放进“原始输出”页。对20MB正文使用预览+分页；显示“预览第1页/共N字节”，并提供全量下载，不能让用户误以为预览即全量。

精确重放分成三种按钮语义：①只读播放历史时间线，不执行；②使用已保存公开响应/工具结果运行离线fixture，不接供应商、不写正式业务；③新建测试run按原输入重新推理，会产生新结果/费用，必须明确模式，不能称为确定性回放。模型随机性及上游页面变化使第三种不保证复现原字句。

## 8. 调试接口与事件合同

全部经声播统一入口代理到记录所属服务，保留 `source`；沿用本机会话鉴权、Origin与CSRF限制，新增 `developer_debug` 会话能力，仅真实用户可以启用。Agent工具不提供读全库调试日志、导出他人资料或“开debug权限”的动作。

| HTTP接口 | 返回或行为 |
| --- | --- |
| `GET /api/debug/v1/runs?scope=&status=&cursor=&limit=` | 任务概要分页，返回记录完整度与源水位 |
| `GET /api/debug/v1/runs/{run_id}/tree` | 执行树，含SDK与业务span映射、links、原事件引用 |
| `GET /api/debug/v1/runs/{run_id}/timeline?source=&after=&limit=` | cursor分页事件索引；不内嵌巨大原文 |
| `GET /api/debug/v1/events/{event_id}` | 单事件原始envelope及payload refs、去密路径 |
| `GET /api/debug/v1/payloads/{hash}?offset=&length=` | 受限字节段及total length/hash；UTF-8展示以服务器字符页防切断多字节 |
| `GET /api/debug/v1/payloads/{hash}/download` | 完整正文原文件，安全Content-Disposition，不暴露任意本地路径 |
| `GET /api/debug/v1/runs/{run_id}/events?agent_after=&voice_after=` | 专用SSE，持久双cursor；通知新增原事件引用，断线可重放 |
| `GET /api/debug/v1/diff?left_hash=&right_hash=` | 同schema文本/结构diff，只读；大对象异步返回diff job |
| `POST /api/debug/v1/runs/{run_id}/exports` | 创建导出job，显式导出范围；不自动向网络发送 |
| `GET /api/debug/v1/exports/{export_id}` | 状态、manifest及本机下载URL；参数鉴权，不接受任意文件路径 |

同hash payload的读取必须校验当前用户可达的run/业务artifact索引，不能仅凭知道hash读取任意文件。常规run时间线DTO只含安全预览；developer API返回受控全文。调试页另设展开原始输入的提示，但用户不用逐条重新授权记录。

SSE事件schema示例：

```json
{
  "type": "debug.trace.appended",
  "schema_version": "PRELIVE-2.3-trace",
  "source": "agent",
  "source_seq": 427,
  "event_id": "evt_427",
  "run_id": "run_fixture_01",
  "span_id": "span_tool_07",
  "event_type": "tool.returned",
  "payload_refs": [{"sha256": "<实际计算>", "byte_length": 26814}],
  "watermark": {"agent_after": 427, "voice_after": 105}
}
```

示例hash为占位，实际fixture必须计算。Debug SSE不能以SDK token流冒充持久事件；先落盘再发布索引。页面刷新后从水位取回，不要求重跑Agent。

## 9. 诊断包与完整性

```text
diagnostic_<run_id>_<export_id>.zip
  manifest.json              # 导出schema、时间、范围、源水位、文件hash、去密策略
  events/agent.jsonl         # 完整append-only事件；序号不重排
  events/voice.jsonl
  payloads/<sha256>.bin
  projections/run-tree.json  # 标明derived，可从events重建
  projections/timeline.json
  contracts/                # schema/工具签名/版本manifest，不含.env
  checks/integrity.json      # event去重、引用存在、hash、span缺口
  README.md                  # 原始/投影区别、模拟标签、缺失项、读取方法
```

原始资料按所选范围导出，有原图则保留来源/图页索引；默认只当前run及其实际依赖，不整库打包。上传外部诊断包是独立用户动作，本功能只在本机生成。导出前再做秘密扫描，若出现凭据模式先中止并返回准确文件/字段标识（不回显凭据值），修正采集策略；不得悄悄输出漏密包。

存储达到配额先告警并停止受影响的新写任务，不后台清理用户正在调试的run。保留策略通过用户选择按整run归档/删除，记录retention清单；删除后索引显示expired，不能声称原文仍在。关闭普通页面预览不删除原记录。

## 10. 验收用例、评价指标和故障注入

| 编号 | 场景与断言 | 指标 |
| --- | --- | --- |
| O01 | 三路分支并行，时间线出现真实重叠区间，任务完成前后可回读主子输入输出 | branch调用关联率100%；事件无孤立父引用 |
| O02 | 同名商品上传触发identity确认，保留原材料、候选差异、用户答案和恢复span | 问题到答案到resume因果链100%可追溯 |
| O03 | 文本审核→同意→TTS；拒绝或审核后改稿使旧批准失效 | 每个TTS job有有效的人工文本批准ref；失效不得生成 |
| O04 | 模拟复盘要求改活动/卖点；展示原条目→适用性→计划→diff | 采纳条目都有目标模块；不采纳有明确原因；simulation不得丢失 |
| O05 | 生成超200字工具结果与大消息，随后上下文压缩 | 原始字节hash一致、下载全量；旧正文不被摘要覆盖 |
| O06 | 模型异常、工具异常、权限拒绝、超时、取消 | 每个started span终结或明确outcome_unknown；错误不静默消失 |
| O07 | 业务提交成功后模拟Audit写失败 | 命令提交恰一次；不因日志故障重执行；outbox可补证 |
| O08 | 执行中杀进程，恢复已有checkpoint，供应商回执未知 | 新invocation链接旧span；不补造成功；未知请求不盲重发 |
| O09 | SSE断开重连、重复事件、晚到旧事件 | 双cursor无遗漏；event_id去重；原序不改 |
| O10 | 固定假的密钥/header/cookie放到测试adapter，不用真实凭据 | blob/SQLite/export秘密扫描零命中；redaction_paths准确 |
| O11 | 导出再校验全部hash；从events重建投影 | 全量引用完整率100%；树/状态与正式receipt一致 |
| O12 | SDK摘要与声播生成/TTS不走主AgentM9 | 均有独立span/usage或unknown；费用不漏算也不重复计数 |

性能初始目标：常规事件append的P95≤20ms（本机测量），可视时间线增量延迟P95≤1秒；大payload采用流式落盘，内存不随整个历史增长。性能目标需在实际设备测试，不通过便调整批量写/索引，不能降低完整正文保留。完整性指标比“页面看见成功”优先：actor/因果/版本/结果有证据才计成功。

## 11. 施工顺序

1. 实现schema、去密serializer、blob/journal、hash校验和O05/O10/O11，无模型依赖。
2. 接协调器/任务supervisor/DecisionService的同事务outbox，建立run树和重启对账，验证O01/O02/O08/O09。
3. 扩展M9＋每次主/子调用显式callbacks，验证最终请求、Skill、压缩和失败记录，不改变M1–M8业务行为。
4. 接声播业务outbox、文案/TTS adapter及review回执，验证O03/O04/O07/O12，特别验证提交后日志失败不触发重试。
5. 实现调试API与上述只读面板、全量下载和本机导出；普通对话页面不灌入原始prompt。
6. 全部用例建立固定fixture；最后再用真实模型/TTS小样本核验可观察字段，明确供应商不提供的字段，保留unknown。

本轮只补设计。实际开发时必须核对项目锁定SDK回调签名并运行探针；不能把设计文档里的采集矩阵当成已经有运行记录。

## 13. 同主模型首次意图阶段的记录

本轮phase=intent/execute属于同run/thread不同invocation；保留候选原文、真实用户事件、有限政策命中／范围答复、确定性验证、Goal首次冻结及grant回执。ASSESSING_INTENT不是用户任务完成；主图只读识别后的自然语言结束不发业务COMPLETED。摘要与模型调用费用跨phase累计；子任务只有execute时派发。

## 19. 最终复查增加的可观测事件

不增加另一套日志库，沿本册事件／安全原文存储接线。

| 边界 | 事件及原始安全字段 | 用户／开发者能验证什么 |
| --- | --- | --- |
| InstanceLock／GraphExecutionRegistry | instance.lock_acquired/rejected；graph.owner_acquired/draining/released，thread/invocation/owner refs | 同thread实际writer是否仍存活；租约过期不冒充已退出 |
| RunFinalizer | run.finalizing/grant_revocation_observed/closure_committed，requested及actual outcome、cause、closure_ref、未决项 | 失败后是否仍在后台跑；已保存成果保留；等待与终态有区别 |
| 最终模型adapter | model.window_checked/attempt_reserved/sent/settled/unknown；payload_ref/hash、purpose/parent ticket、估算器版本与usage性质 | system/tools是否计入，取消/崩溃后每次付费尝试能否解释；不记录API凭据 |
| QuestionService | question.resolved的人类或system判别、target_superseded原因、新旧目标refs | 修改不是批准；旧interrupt被安全唤醒 |
| 旧版选择/currentness | product.revision_choice_recorded/currentness_checked；pinned/head/diff/control/choice refs | 保留还是刷新是谁决定；停售/撤回为何阻塞；不因保留就重合成 |
| 经营建议/续作 | ordering.suggestion_recorded/decision_applied；continuation.projected | 商品二身份与版本区分、建议和实际授权链；已完成回执如何复用 |

关闭中的FINALIZING单独显示“收尾/对账”，不能先显示全部停止。模型结果unknown、usage未知和日志缺口分别呈现；本地trace保留请求/工具结果等可记录公开内容，不声称记录模型私有思维过程。ContinuationOption为只读投影，不因查看日志触发写入或重试。


## 20. ChatGPT授权来源的去密边界

按17保存模型来源及公开调用证据，不保存OAuth记录。CredentialManager不作为模型工具，认证头在网络发送时由后端注入；Capture/异常/SDK回调不能采集access/refresh/ID token、Cookie或原始token endpoint响应。保留安全错误码、续期阶段、模型/账户的受限标识及已知或unknown用量。记录LangChain消息→最终Responses安全载荷→工具call ID/结果→SSE终态关联，不把HTTP200或中途文字当成功。此处只是设计要求，本轮未接管授权或产生实际调用记录。
