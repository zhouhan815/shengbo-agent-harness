# 复查问题修复与循环编辑保护

日期：2026-10-16。覆盖本次用户确认的播放循环规则、Agent 执行期间编辑保护，以及上轮复查的五项问题。业务合同继续为向后兼容的 PRELIVE-2.3。

## 用户确认的规则

1. 播放清单播完，从第一项按已保存顺序继续循环，直到人工停止；不再提供单轮结束选项。
2. Agent 修改对象、字段或话术模块时，左侧对应区域禁止输入与提交；无关对象、字段或模块仍可编辑。已有草稿和原 DOM 保留。
3. 取消排空、恢复中、写入结果未知时继续保留相关锁；执行确已退出且结果已核实后解锁。纯只读解释不因为模型正在运行而上写锁。

## 实装边界

| 项目 | 实装方式 | 验证目标 |
| --- | --- | --- |
| 固定队列循环 | 本场草案、编排及直播间保存统一 infinite；实际播放器始终 loop=True；历史 once 可读，不自动重写旧稿或调用 TTS | 到队尾回到队首，顺序不变，原位置开场计数保持现行编译规则 |
| 已确认配置隔离 | start_publication 从 publication 精确 draft_ref/playlist_ref 读取绑定配置；音色不取后改的直播间默认值 | 修改默认设置不会改变已确认稿件/音频对应的播出配置 |
| 重启恢复 | 服务持有 OS 文件生命周期锁；持久记录 owner、启动操作、room 和 publication。独占锁证明旧进程退出且四项证据匹配，才将旧占用解除并标记 interrupted | 进程强制退出后可恢复；未知历史占用不盲目清空 |
| 历史未知占用 | 房间 error + recovery_required，提示核实旧播出窗口和 OBS；人工结束后解除 | 页面可见问题且结束按钮可用，不自动重播 |
| 编辑锁 | 新增 GET /api/assistant/v2/editor-locks，跨全部会话投影精确 targets；包括新建商品和替换前后 script ref。前端 1.5 秒轮询、提交前 provisional selection 锁、失败保留已知锁 | 字段/模块粒度；刷新恢复；取消排空不提前解锁；原先 disabled 控件解锁后仍 disabled |
| 草稿保护 | “请 Agent 整理资料”追加指令，保留已有未发送文字，避免重复追加同一句 | 不再覆盖聊天草稿 |
| 变更记录 | read_events 增加 scope_id/include_catalog/order，默认 asc 保持旧消费者；UI desc 最新优先并加载更旧页 | 超过 200 条仍显示最新，分页无重复，任务 scope 无越权 |
| 试听调用收据 | 人工 CSRF 入口必带 operation_id，调用前持久 attempt，成功写收据并验证本地音频存在，HTTP 取消不取消后台核实 | 同编号重发单次；成功缓存可复用；音频丢失不假报可播 |
| 试听未知保护 | 同用户同音色/文本/风格的 pending 或 unknown 即使换编号也不重复调用，返回原编号核查；重启遗留请求 unknown，不自动重发 | 不同编号并发只调用一次；结果未知后换编号仍不产生第二次调用 |

编辑锁是人机交互保护，后台继续保留精确引用、授权约束和 CAS；未将显示状态误作业务权限。没有新增模型主动调用的“锁定工具”。锁接口只返回运行编号、状态和对象定位，不返回私密上下文或凭据。
