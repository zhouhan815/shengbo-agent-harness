# 06 前端交互到后端的对接合同

此册连接用户提供的前端交互设计与本版后端。保留前端业务操作和状态语义；前端原文中的假设接口/schema不是已实现接口。后续共享合同以本册及01/03导出的 `PRELIVE-2.3` 为准，不再各维护一套不一致DTO；最终复查选择、收尾及恢复合同见[16](16_最终复查修订与待讨论事项.md)。本轮仅改设计，不实现页面。

## 1. 命名转换

| 前端文档概念/字段 | 后端字段 | 原因与行为 |
| --- | --- | --- |
| “本场” `session_id` | `preparation_id` | 开播前草案；正式开播才创建 `live_session_id` |
| `session_product_id` | `preparation_product_id` | 本场引用＋overlay，指向product_id及精确revision |
| `snapshot_id` | `publication_id` | 未采用也可以有不可变候选；采用由AdoptionReceipt独立表示 |
| `analysis_id` | accepted ArtifactRef | 声播权威研究/分析版本，区别Agent暂存 |
| `script_id` | ScriptRevision.id | 编辑可能生成新ID，同variant_id保留版本线 |
| `playlist_item_id` | `occurrence_id` | 同脚本可出现多次，不能按script_id去重 |
| 某一轮位置 | `compiled_entry_id` | 包含supercycle相位；跳播使用该原编排位置的开场 |
| 当前页面/可见内容 | `view_context` | 观察信息，不等同明确target或写权限 |
| 明确指定字段/段落 | `SelectionSnapshot` | 稳定对象ID、revision、field_path/module/block/sentence及文字hash |
| “已完成” | 运行终态＋真实业务receipt | UI不能解析聊天文字判断保存/就绪/采用 |

请求中若还使用前端旧 `session_id`，迁移适配必须明确映射为preparation_id，并在响应返回规范名；禁止把它塞入真实live_session_id。旧合同JSON文件作为输入样例保留，实施期生成新schema/examples并更新消费者，不静默同时接受两个同名不同义字段。

## 2. HTTP边界

浏览器访问声播同源服务；声播代理 `/api/assistant/v2` 到独立Agent进程，注入可信actor。Agent服务不对公网暴露、不把服务凭据发浏览器。

| 方法/路径 | 调用者/handler | 输入 | 输出 |
| --- | --- | --- | --- |
| POST `/api/prelive/v2/commands` | 编辑器→voice execute_command | discriminated command+args+版本/operation | CommandReceipt；生成任务accepted返回202 |
| POST `/api/prelive/v2/queries` | 编辑器→voice execute_query | typed query+args+scope | 完整对象/分页列表/检查快照，不产生业务写入 |
| POST `/api/assistant/v2/conversations` | 对话入口 | 可空scope、当前展示偏好 | conversation_id；不造preparation |
| POST `/api/assistant/v2/conversations/{id}/messages` | IntentController→submit_intent | 下节MessageRequest | 202 RunReceipt/若仅回答问题则AnswerReceipt |
| POST `/api/assistant/v2/materials` | MaterialService.accept_upload | multipart文件、scope、client_request_id | material/blob refs、解析task状态 |
| GET `/api/assistant/v2/runs/{id}` | RunQueryService | 真实用户会话与run_id | 可见步骤、任务、阻塞、成果、FINALIZING收尾/终态、continuation_options；不唤醒LLM |
| POST `/api/assistant/v2/runs/{id}/cancel` | RunCoordinator.cancel | operation_id、预期run版本 | cancelling/cancelled及远端撤权receipt |
| POST `/api/assistant/v2/decisions/{id}/answers` | DecisionService.answer | question_revision、answer、目标refs、operation_id | 同一可信答案receipt；必要时恢复原thread |
| GET `/api/assistant/v2/workspace` | WorkspaceProjection | scope、conversation_id | 业务snapshot＋运行snapshot＋双cursor |
| GET `/api/assistant/v2/events` | EventGateway.stream | stream_ids、voice_after、agent_after | SSE typed events；Last-Event-ID双cursor |

voice命令包括create_room/create_preparation/save_product/save_session_draft/accept_analysis_report/save_context_bundle/save_script_plan/submit_script_change/save_playlist/compile_playback_plan/prepare_required_audio/publish_preparation/adopt_snapshot/start_prepared_room/undo_mutation等，固定enum见[03](03_声播业务服务与事务.md)。这些是服务能力，不要求前端把内部Agent工具逐个渲染成按钮。

### 2.1 Principal与请求保护

首期单机单用户：服务生成本机会话cookie（HttpOnly/SameSite），业务写入检查Origin和CSRF token；仅允许配置的loopback origin。voice→agent与agent→voice用独立服务凭据，声播以principal.kind及command allowlist鉴权。`issue_grant/revoke_grant`只给可信运行控制器；`adopt_snapshot/start_prepared_room`只给human。客户端JSON中的actor_id/role不会改变身份。密钥不进SSE、页面localStorage或Agent上下文。

代理需保留request_id、流式SSE与断连语义。浏览器断开只停止展示，不等于cancelrun。重新打开网页从持久run恢复。

```json
    "origin":"explicit_selection",
    "target": {

      "object_ref":{"kind":"script","id":"script-r7","revision":7,"content_hash":"sha256:example"},
      "module_key":"campaign","block_id":"block-14",
      "field_path":null,"sentence_id":null
    },
    "selected_text_hash":"sha256:example"
  },

  "intent_mode":"follow_up",
  "related_run_id":"run-older",
  "observed_versions":[]

```

`account_id`只用于一致性检查，真实account从会话取，不能越权指定。`client_request_id`同用户范围去重；response返回run_id、状态、实际冻结target、queue_position和server_event_cursor，前端立即显示“已受理/排队”。上例hash仅示意，实施fixture用实际canonical hash。

目标冲突处理：本例明确只改block-14，但99元变化同时会影响别处旧价。后端若不能在该scope内完成一致修改，返回 `scope_conflict` 决定卡，列出必须联动的具体模块。超出旧Goal/grant的扩展采用第5节的新任务授权路径，不能仅拿一个DecisionReceipt恢复旧grant后越界写。明确目标、合法且无冲突的可逆修改直接落草案，不再弹“确认生成吗”。

## 4. 选区、续改与人工并发

```python
def freeze_selection(request, principal, reader) -> SelectionSnapshot | None:
    require_scope_access(principal, request.scope)
    if request.selection is None:
        return None
    require_same_work_scope(request.scope, request.selection.target.scope)
    require_target_access(principal, request.scope, request.selection.target.object_ref)
    target = reader.read_exact(request.selection.target.object_ref)
    require_path_exists(target, request.selection.target)
    require_selected_hash(target, request.selection)
    return immutable_copy(request.selection)

def rebind_own_chain(frozen_target, predecessor_run, changes) -> TargetRef:
    # 仅接受前驱同一修改链产出的replacement，逐边验证旧ref相等、scope未扩大
    target = frozen_target
    for edge in verified_lineage(predecessor_run):
        require_edge_scope_preserved(edge, target)
        target = replace_exact_ref(target, edge)
    require_no_external_intervening_change(target, changes)
    return target
```

| 情况 | 后端行为 | 前端展示 |
| --- | --- | --- |
| 发送后导航到另商品 | 输入已冻结，仍处理原target | 原任务目标不随页面变 |
| 同target任务未完，又普通发送 | 非当前问题答案的新follow_up排队，原run继续；不能把当前审核卡的edit_text也排成follow_up | 前后任务及“接着处理”关系；审核内修稿走原卡恢复 |
| 用户明确替换旧任务 | 先voice revoke旧写权，成功后新run可写 | stopping→superseded；未知时不显示已停止 |
| 人工改了Agent任务的目标字段 | 人工CAS成功并写失效；Agent提交时冲突 | 展示双方revision/diff与重新选择入口 |
| 本链局改生成新script_id | receipt含replacement_ref；仅替换本prep相应refs | 选区可随本链续接，item_id/顺序不丢 |
| 其他run/人工生成新script_id | 不自动绑最新稿 | TARGET_CHANGED，提示差异 |
| 用户有未保存本地编辑 | 服务不感知为已保存事实；事件不能强迫覆盖 | 保留buffer、标服务端已更新，用户决定合并 |

## 5. 用户决定：卡片与自然语言共用同一对象

```python
class DecisionCard(BaseModel):
    decision_id: str
    revision: int
    run_id: str
    kind: DecisionKind  # 唯一定义见10，包含text_audio_approval等确认类型
    target_refs: list[TargetRef]
    prompt: str
    choices: list[DecisionChoice]
    allowed_answer_schema: dict
    state: Literal['open','answered','superseded','cancelled']
```

卡片按钮和对话答复都经DecisionService：绑定decision_id+revision、验证actor和当前输入、先存答案event，再Command(resume)。同一问题重复提交返回原receipt；旧问题过期返回stale，不能把旧“同意”当新scope许可。

例外是**超出原始目标/写授权的范围扩展**：卡片展示完整新增target/changed_paths，用户选择“允许联动并继续”后，可信 `IntentController.replace_with_expanded_scope(answer_event)` 创建新的不可变GoalContract和replace run，先通过声播撤销旧run写权再授权新run。旧interrupt不以更大权限恢复；旧run记SUPERSEDED，新run引用已接受产物继续。普通事实选择、缺项回答和原grant范围内的修正仍恢复原run。后端不能让模型自行把缺项回答解释为任意范围扩展。

```python
async def replace_with_expanded_scope(answer_event: VerifiedAnswerEvent) -> RunReceipt:
    decision = await decisions.require_current_scope_conflict(answer_event.decision_id)
    expansion = validate_explicit_expansion(answer_event, decision.proposed_scope)
    goal = derive_expanded_goal(decision.original_goal, expansion)
    # 可信控制器产生新的用户授权事件；不调用旧thread的Command(resume)
    return await coordinator.submit_intent(make_replace_event(goal, answer_event))
```

`require_current_scope_conflict`返回服务端`InternalScopeConflictDecision`，保存不可变`original_goal_ref/proposed_scope/proposed_scope_hash/target_refs/decision_revision`；前端只回choice_id及decision_revision，不能提交任意“新增权限”JSON。`validate_explicit_expansion`从服务端候选读取范围并核对用户选择/hash；新goal只能等于用户明确选中的范围。原始goal和候选写入问题记录时即固定，模型不能在用户点卡后改写它。

自然语言可以回答问题，可信请求层只把它作为当前open decision的候选答案；schema明确且唯一时解析后落库，多个问题指代不清则问清。模型自由文本“用户应该会同意”永远不是DecisionReceipt。

人工直接完成缺项/排序后，voice业务事件会关闭对应已满足问题或让协调器发 `decision_satisfied_by_edit` 可信事件；必须匹配对象/字段/版本，不能随便一条保存就把所有问题当已答。

审核卡的`edit_text`是**非批准答案**。Goal/grant内的修改保存真实answer后恢复原run/thread，将用户修改原文和精确目标交给主Agent；不能排在仍WAITING_USER的原run后。超出原Goal才走上面的replace范围扩展。用户在编辑器手改使审核hash过期时，QuestionService保存10定义的typed `QuestionSystemResolution(kind='target_superseded')`并唤醒原interrupt，工具返回stale和新读取入口；这既不是`AudioApprovalReceipt`也不是虚构的用户答复。旧问题只失效不唤醒属于错误实现。

## 6. 前端操作—后端函数映射

| 前端动作/状态 | 固定后端链 | 版本与反馈 |
| --- | --- | --- |
| 商品列表/详情/新建 | read/search query；save_product命令 | revision、所有schema字段、来源处理状态 |
| 上传复杂资料 | accept_upload→parse任务→source refs→分析工具 | 原文/截图可定位、OCR状态和缺项 |
| 新建直播间/本场 | create_room→create_preparation | 真实room先存在；preparation独立id |
| 引用已有商品 | update_preparation_products命令 | preparation_product_id＋product revision；无资料副本 |
| “有新版”/新旧差异选择 | `evaluate_revision_currentness`只读结果→human-only `record_product_revision_choice` | 本场消费字段有差异时，展示具体新旧值/受影响句，由用户保留或刷新；无关改动仅提示。保留写独立choice回执，不改文本/epoch；刷新在同UoW复用既有刷新逻辑；停售/明确撤回、活动过期不可保留绕过 |
| 手改商品/草案/分析 | typed patch command→CAS/变更/outbox | local unsaved与server saved分开 |
| 点某字段让Agent改 | freeze selection→submit_intent | 稳定目标、scope、base版本、文本hash |
| 改话术段落 | patch_script命令→新module/script修订 | replacement_ref；无关块逐字保留 |
| 只更新本场配置 | save_session_draft→inspect_change_impact | 保存配置并列受影响稿，不暗中生成话术；只有原Goal含同步改稿或完整准备才继续对应模块 |
| 再生成一版 | submit_script_change指定new variant | 不自动加入playlist/TTS/采用 |
| 选稿/重复项/排序 | 截图式卡片拖拽；preview_playlist_reorder纯读预览→用户应用→save_playlist | occurrence独立ID、精确版本、CAS；状态分层；纯预览不作废批准 |
| 选择音色/试听 | save_session_draft；有缓存示例可播，新TTS须human批准后preview_audio | 试听有独立小样上限，不是整场ready；不静默换声 |
| 准备语音/重试 | compile→create_text_review→human approve_text_for_audio→prepare_required_audio / retry_failed_items | 批准绑定精确文本/voice/顺序；重试也验证批准/预算，状态逐项可见 |
| 查看Agent成果 | ArtifactDestination解析→query精确ref | 不从聊天拆URL，不自动保存本地编辑 |
| 检查本场 | publish候选（或读取已有）→create_review只读 | 缺项、diff、hash、当前readiness |
| 确认采用 | human adopt_snapshot | review_hash+room CAS；回AdoptionReceipt |
| 正式开播 | human start_prepared_room | 只能已采用且当前；生成live_session/既有OBS链接 |
| 撤销某次修改 | undo_mutation新CAS | 不倒退revision；有后续同字段变更则冲突 |

`record_product_revision_choice`不暴露为Agent工具。界面或绑定当前决定的聊天真实human事件只能选择服务端已展示的`preparation_id/pinned_product_ref/observed_head_ref/diff_hash/choice`；voice事务重新核对访问权、新head、diff和停售/撤回控制。`keep_pinned`不改变本场引用、内容epoch或音频审核hash，不因保存选择而重新生成语音；动态采用/开播检查hash包含此次选择和当前control。`refresh`才改变精确业务引用并按03/10使相关整包批准stale。选择后又有新head，旧回执不能批准未展示的新差异。完整schema从16/03生成，不接受前端任意`allow_stale=true`。

`update_preparation_products/refresh_product_reference/patch_script/preview_audio/create_room`是03业务适配的固定命令，实施时补进同一registry，不新建绕过事务的前端快捷写路径。

## 7. 成果与事件结构

```python
class ArtifactDestination(BaseModel):
    authority: Literal['voice','agent_runtime'] = 'voice'
    run_id: str | None = None      # agent_runtime的验收/计划成果必填
    scope: WorkScope
    view: Literal['product','config','analysis','script','playlist','audio','review','materials','asset_checklist','acceptance']
    object_ref: RecordRef | ArtifactRef
    module_key: ModuleKey | None
    block_id: str | None
    sentence_id: str | None

class VisibleRunStep(BaseModel):
    step_key: str
    state: Literal['queued','running','waiting','succeeded','failed','stale','skipped']
    input_refs: list[ArtifactRef]
    output_destinations: list[ArtifactDestination]
    blocker_refs: list[str]
```

对话终答由backend附加已验证的artifact destinations，不接受模型自造产品ID。步骤进度来自真实branch/business jobs回执；Todo仅辅助模型，不当用户进度真值。可见事件包括：

| 服务 | 事件 |
| --- | --- |
| Agent | run.accepted / queued / started / waiting / finalizing / completed / failed / cancelling / cancelled / superseded |
| Agent | decision.opened / answered / superseded / system_resolved、analysis_batch.progress、artifact.prepared、chat.message |
| voice | product.changed、preparation.changed、analysis.accepted、script.revised、playlist.changed、dependency.invalidated |
| voice | job.progress / item_failed / completed、audio.manifest_changed、publication.ready、snapshot.adopted、product.revision_choice_recorded |

SSE事件有event_id、源service、seq、stream_id、run/operation、对象revision；同源不保证两库全局排序。01双cursor+snapshot水位保证断线恢复；前端用对象revision避免晚到旧事件覆盖新内容。SSE不透传Deep Agents内部chain-of-thought、原始prompt、工具凭据或checkpoint。

内部`FINALIZING`显示为“收尾／对账中”，含requested_outcome、finalization_phase和已知撤权/执行者退出进展，不能先显示“全部完成／已停止”。`COMPLETED/READY_FOR_REVIEW/BLOCKED/FAILED`等最终状态只消费有`RunClosureReceipt`的权威终态事件；WAITING_USER/WAITING_JOBS保持等待语义，不因浏览器断开终结。正常完成撤销的是继续写权，不使合法已保存候选因为run关闭而消失。

## 8. 前端不需要提供的内部上下文

只需要room/preparation/target精确refs、用户文本、材料和explicit selection。后端自行取得商品全文、研究、草案、旧稿、合法动作、任务授权和恢复位置。前端不拼系统prompt、不提交“agent已经允许”的布尔值、不解析SDK消息来推断业务对象、不复制一份商品作为新正本。

前端交接不要求重新提供历史聊天。后续实现窗口读取00—06、业务基线10、实际声播源码和shared schema即可开始；凭据继续从本地服务配置读取，不从文档复制。

## 9. 联调出口

先做不依赖LLM的消费者合同：全局catalog、冻结选区、手改CAS、脚本replacement、重复playlist、双cursor重连、采用/start权限反例。再接真实Agent：新商品三路分析、只改活动、只换声、生成另版、follow_up排队、replace撤权。每条至少检查响应DTO、持久业务结果、事件和成果定位四项，不能只看页面显示了成功。

| 暂不批准/继续编辑 | QuestionService真实`edit_text/reject`答案，必要时revoke_text_approval；Goal内同run恢复，超范围replace | 无新TTS；可保存草案，不误判为取消全部资料；不能把审核内修稿排成等待自己的follow_up |
| 采用/开播 | 既有human adopt_snapshot、start_prepared_room | 与文案→语音批准分别展示，批准生成音频不代表批准开播 |
| 查看运行过程 | 本机开发调试API，详11 | 运行树/时间线/原始事件/调用详情/变更对比/导出；普通SSE不塞原始prompt与资料 |

身份重复等澄清卡沿原QuestionService/interrupt协议，答案后只恢复对应run；scope_conflict扩权仍新建replace run。审核批准由human端点形成声播权威记录，模型不能通过question答案拼一个approval。开发调试只读，点击事件定位原产物，回放日志不重放命令，重试操作另走受控业务入口。

## 11. 部分成果与“继续未完成部分”的投影

既有run GET增加`continuation_options: list[ContinuationOption]`，类型唯一来源为16§10，不另造恢复接口或数据库。每项携带`source_run_id`、mode、精确目标refs、可复用receipt refs、未满足requirement IDs、blocker refs、需要的用户输入和可空GoalDelta。前端展示“已保存什么／还差什么／下一步”，不能仅留一段聊天描述。

| 当前状态/option mode | 用户入口与可信处理 | 不得发生 |
| --- | --- | --- |
| WAITING_USER / answer_question | 补答原decision及revision；审核edit_text在原Goal内同run恢复 | 新建重复商品，或排在等待自己的前驱后 |
| WAITING_JOBS / observe_job | 打开已有job/进度，继续监听 | 重复提交同一生成请求 |
| FINALIZING / reconcile_unknown | 读取finalizer对账进度；先核实撤权、在途工作和未知结果 | 以“继续”立即重新invoke同thread或重复付费 |
| BLOCKED/FAILED/CANCELLED等终态 / resume_remaining | 用户明确继续后，可信入口重读refs/remaining requirements，冻结新Goal并发新grant；复用已保存商品、研究、稿件和缓存 | 继承已撤销grant、重复新建已保存商品、重新合成成功音频 |
| replace_scope | 用户明确选择服务端范围增量后走既有replace | 把选项文字当任意执行命令或跳过人工费用/采用/开播决定 |

option是安全建议投影，不会自己执行，也不是继续授权。点击或聊天选择带回option_id及source_run_id；可信请求层回读当前对象与剩余目标再处理，过时option返回新差异。终态后恢复不是对旧interrupt做resume。TTS/model结果unknown必须先对账；不把“继续刚才的”解释为同意再次可能重复扣费。

本册新增消费者验收：审核edit_text无需先取消就能继续；原问题因手改失效时可醒来重读；价格-only卖点/脚本hash保持；P@4/P@5保留选择不重TTS、停售仍拒绝；商品已保存而研究失败的续作沿原product_id；FINALIZING期间不显示假成功、不接受冲突新invoke。实际接口及UI测试待实施。


## 10. 恢复载荷及收尾结果补充

浏览器仍提交真实问题答案／已有业务编辑，服务端创建记录后由scheduler构造02 §9的QuestionResumeEnvelope。人类分支`{resolution_kind:'human_answer', answer_event_ref}`；系统旧目标分支`{resolution_kind:'system_resolution', system_resolution_ref}`，均拒绝额外字段。前端不得直接传actor、approved或伪造系统resolution；它们由服务器验证持久记录。QuestionSystemResolution(kind='target_superseded')是记录类型，与传输union区分。

最终运行结果投影同时包含requested_outcome和actual_outcome：原拟完成但收尾复验发现人工变更时，显示实际blocker，不沿用已失效成功。RunClosureReceipt保存二者和保留成果，continuation_options只提供下一步候选，不自动执行。
