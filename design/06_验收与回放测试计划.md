# 声播运营 Agent 验收与回放测试计划

版本 2.0　日期 2026年10月7日　状态 待实施执行

业务验收补充：[08 业务闭环与动态数据详细设计](08_业务闭环与动态数据详细设计.md) 的V01—V16加入验收，覆盖资料不足、合理生成、入库匹配、本场活动、动态口径、平台数据缺失与下一场修改。原T01—T30继续保留。v2样例通过不能替代新增共享类型和案例执行。

本计划定义怎样验收设计落地后的系统。没有运行运营Agent，所以本文的门槛是计划，不能作为当前产品的测试成绩。A负责总体测试和证据汇总，B/C/D分别负责本模块；各自的已完成、失败、待联调和未执行要分开记录。

## 一 验收层次

| 关口 | 需要交付的证据 | 可开始的下一步 |
| --- | --- | --- |
| G0 合同 | 统一类型、样例、枚举和引用验证，版本兼容结果 | 四模块并行实现 |
| G1 模块 | B/C/D离线产物、A工具与状态测试，正常和失败样本 | 假环境集成 |
| G2 假闭环 | 从准备到回放、动作、归档、复盘和采纳的完整模拟轨迹 | 真实本机联调 |
| G3 声音闭环 | 本机音频实际播放，监控和逐句状态、动作与attempt关联 | OBS本地录制 |
| G4 OBS | 本地录像有声音/画面，音源唯一，暂停/插播可观察 | 受限自动模式评估 |
| G5 受限自动 | 已审核FAQ白名单、冷却和故障案例、人工抢占 | 后续授权平台试验 |
| G6 平台 | 具备平台条件后另做实际推流、采集和业务数据核验 | 真实业务价值实验 |

G2不能证明G3；浏览器回报ended不能证明OBS或抖音收音；模拟问题不能代表真实观众。平台条件不足不阻塞G1至G4，但交付须标清未达到的层级。

## 二 固定评测数据

先用本目录fixtures作可人工算的小样本，再扩成约30个差异化功能/故障案例，每个案例保存case_id、初始状态、事件时钟、允许动作、期望终态、禁止行为、判定器和重置方式。样例是机制测试资料，商品事实和观众事件均不能当成当前真实经营数据。

提示词调试用开发集；阈值校准后冻结留出集，模型不看预期结果。开放文本每个留出任务至少重复3次观察波动，报告样本量与失败类型，不用最好一次演示代替可靠性。所有测试隔离缓存、任务、动作账本和记忆；音频缓存是否复用分组说明。

## 四 指标和判定器

硬不变量由程序和环境回读判定：错场动作、未批准内容进入自动/正式播出、未知结果盲目重放、伪造完成和经营数据、超预算后继续新动作均为零容忍。发现一例先修根因并复测，不用平均分抵消。

| 指标 | 明确口径 | 候选目标 |
| --- | --- | --- |
| 准备事实支持率 | 得到所引事实语义支持的商品断言/全部商品断言；缺引用按失败 | ≥95%；关键价格币种100% |
| 已知FAQ任务成功率 | 正确且有完成证据的回答任务/全部标注为可答的FAQ任务，未回答也进分母 | ≥95% |
| 问题完成覆盖 | 有回答完成证据的去重范围内问题主题/全部记录的范围内问题主题；另报原始问题数、合并规则与unknown | 不设脱离数据的统一阈值 |
| 动作完成率 | completed/该场已登记的目标工具动作总数；拒绝、取消、未知、待处理均单列 | 按工具分组，不混成总分 |
| 必讲点覆盖率 | 有完成播放证据的必讲事实/发布计划必讲事实 | 测试单路径100%；主动跳过另解释 |
| 复盘证据支持 | 可定位且支持关键观察的证据/全部关键观察 | 100% |
| 可执行改进率 | 具目标版本、依据、具体修改和验证方法的改进/全部改进 | ≥90% |
| 时延 | event→批结束→提案→接受→发声→完成分别测 | 批结束到提案P95≤5秒待标定 |
| 资源 | 模型、工具、重试、核查全计；费用未知时报告tokens和缺失 | 遵守配置上限 |

问题覆盖率包含未知库存等范围内问题，unknown不能被删出分母以提高数字；任务成功率则使用预先标注的可答任务集，二者不能混用。一个回答可覆盖多个同主题原始问题；等待时间按每个原始问题到首次回答started分别计算。occurred_at缺失时不能当成0等待，只能另报按received_at口径。

开放质量采用事先给定的量表，由人或独立评审核查；模型评审需校准，不单看引用ID是否存在。改进建议的价值最终要经采纳、回放或真实用户验证，本阶段不提前宣布有效。

## 五 对照实验

在相同输入、版本和总预算下依次比较：固定规则FAQ；单次模型判断；单Agent工具循环；三个阶段Agent加统筹。多阶段的结构收益主要看跨场污染、遗漏、恢复、总成本和端到端人工修改量，不能把额外花费带来的效果全归于多Agent。

演示有用但不替代评测。留出实验一次只改变一个因素，如FAQ提前、窗口大小、冷却或版本选择；记录模型/提示词/工具版本与缓存条件。不把合成点击或销量作为真实收益。真实业务实验需后续确认数据口径与可比条件。

## 六 两条完整走查

**正常路径**：准备双商品→审核FAQ和稿→发布→声播生成session→问题重复合并→查事实→句尾提案→网关重验→accepted→playing→ended→归档→复盘提前规格建议→选择采纳→下一场新修订。每步都保存来源和版本。

**故障路径**：问题触发推理→运营人工切商品→提案迟到→control/product冲突拒绝→Agent重读后不继续旧答复；另一动作dispatch后回包丢失→inspect无确定证据→unknown→不重发→归档缺口→复盘仅给有条件结论。重启不开旧声音。
