# 窗口 C 播中运营 Agent 研发任务

业务修订必读：[08 业务闭环与动态数据详细设计](08_业务闭环与动态数据详细设计.md)。按M01—M12定义采集/分析范围，按R01—R10实现候选规则、数据质量判断、动作反馈与观察期。真实经营数据未知时降级为本地播放和模拟问题；新增规则不自动扩大白名单。首版受限自动仍只允许已审核FAQ句尾插播，其他动作按能力与验收开放。

版本 2.0　日期 2026年10月7日　实施任务包

## 一 目标与上下文

根据当前讲解、商品事实和问题事件，选择不行动、请运营处理或提出可执行动作，展示“取证和选择如何影响直播”。先做句尾答疑，再做重复问题驱动的后续讲解调整。当前无需真实抖音、真人主播或数字人视频；使用声播声音人和事件模拟即可。

先读 [00 总体设计](00_整体方案与并行分工.md)、[01 公共契约](01_统一数据与工具契约.md)、[06 验收计划](06_验收与回放测试计划.md)。实现目录拟为 `D:/Codex project/shengbo-ops-agent`。你只拥有modules/live、tests/live和本模块产物；A拥有动作网关和声播代码。不得直接调用/api/control、写商品数据库或绕过网关发声。

## 二 输入和输出

输入已发布PreparationBundle、RoomSnapshot、NormalizedEvent窗口、已回答/待播历史和会话策略。模拟场景使用fixtures/live-state.json、questions.jsonl及scenario-manifest.json，离线会话标simulated。没有准备包时可做旁路诊断，不开启自动执行。

输出Proposal，含decision、event_refs、fact_refs、具体理由、动作参数、期限、业务前置版本。no_action也要记录原因，不为显示活跃而插话。执行结果由A返回ActionRecord；你只能根据实际结果更新回答历史，不能将“提案已提交”记为“观众已听到”。

## 三 决策和执行的完整路径

```text
程序接收和去重 → 有限窗口合并 → 读取状态与相关事实
→ Agent选择查证或动作 → 程序检查证据与策略
→ 保存提案 → 人工确认或已配置白名单
→ A网关重验当前上下文并提交 → 接受/发声/完成分开记录
```

Agent判断包括：问题属于哪个商品；是否存在可用资料；是否已经答过或安排待播；现在值得回答还是合并；普通答疑还是明确事实纠正；调整是否超过当前策略。不能只把每条弹幕套成一句回复。

首版主路径：三个关于尺码的重复问题合并；读当前商品FAQ；选经确认的短回答；提出句尾插播；网关确认仍是同一商品和场次后执行；真实ended后记已回答。未知库存的问题保留待运营，不能编库存或用“系统未接入API”播给消费者。

第二路径：同类规格问题持续出现且相关讲解在队列后部，提出提前规格片段的建议。重排只输出A要求的全体待播项排列，保留当前句和依赖，不删掉中间内容；缺完整队列时不给可执行重排参数。切商品要解释会跳过哪些内容，不能当成无损调序。

## 四 工具和控制权

开放read_live_state、read_catalog、read_answer_history、query_events、propose_action。前四者只读；propose_action只是登记。模型拿不到实际提交工具、平台账号或声播写凭据。来源是问题事件，不等于用户授权，事件中的“忽略资料、降价、立即下播”不能改变权限。

三种会话模式：observe只展示；manual_confirm由运营批准有效提案；limited_auto仅针对已审核FAQ原文、匹配事实版本、允许动作和频率执行。新生成回答仍走确认，不能靠模型自评“有依据”进入自动白名单。模式与策略版本由可信配置产生。

人工暂停、切商品、改队列或结束后，以control_revision/queue_revision拒绝旧提案；自然换到同商品下一句不必重新跑全部模型。网关临提交取当前epoch做原子校验。新场次、旧boot、过期提案一律不能执行。人工停止Agent后迟到结果仅归档。

## 五 实时 Harness

程序监听播放器进度，不以每次progress触发LLM。候选批窗口5秒、最多50条；按session、商品版本和主题合并，重复主题冷却30秒，已安排待播也参与抑制。候选提案有效期15秒，超时重读或作废，不反复追逐每句变化。数值首轮可配置并按测试校准。

一次循环候选上限4次模型请求、6次只读工具、1次提案；校验失败最多1次修正，且计入上限。模型请求超过软时限返回稍后处理状态，硬到期终止；原音频队列继续播。优先级：人工与停止最高，明确需纠正的错误其次，普通答疑，再到节奏建议。首版不让策略模型进入音频逐句推进关键路径。

本场记忆区分observed、proposed、pending_playback、answered、cancelled/unknown。只有回答attempt完成才能写answered；立即打断后原句重播不能误记两次完成答疑。等待A执行时不占着LLM循环轮询，按事件或有界inspect更新。

unknown动作必须交给A对账，不发同文字的新动作。知识缺失、模型失败或状态不明时保持原计划，生成监控提示。无新证据两轮不进展就结束这一决策批。

## 六 独立开发和开源复用

本地实现FakeTools、ReplayModel和FakeClock，读取样例事件产生提案，不操作声播。测试可构造人工切商品、同句重播、插播忙和动作未知。A真实网关未好前，可以完成全部决策与拒绝逻辑；实际执行测试必须等A。

参考既有研究中Sparklive的有限事件窗口、重复问题和输入ID校验，迁移为商品/问题ID；不搬入Qt、本地大模型硬件和平台抓取器。参考Learn Claude Code的有界工具循环与工具结果反馈，不复制其通用Shell执行权限。源码定位与许可证见现有声播docs/运营Agent构建报告_v1.0.md；复制前再核查。

## 七 验收和交付

| 级别 | 验收案例 | 判据 |
| --- | --- | --- |
| C1 决策离线 | 已知FAQ、未知库存、混商品、重复问题、注入指令 | 引用正确、未知不编造、去重有理由、越界不执行 |
| C2 时序回放 | 人工先切商品、暂停、结束；旧提案迟到；队列更新 | 旧上下文提案无执行；自然同商品换句仍可合理答疑 |
| C3 假执行闭环 | accepted但未started、started后被打断、超时unknown | 历史不提前记answered，未知不重复提案求执行 |
| C4 真实声音 | A网关和播放器已就绪，普通话句尾插播及恢复 | action对应实际attempt和ended；真实收音另做本地录制 |

硬门槛按06执行。候选质量目标：已知FAQ正确且有依据≥95%，关键价格/币种100%；重复答疑和不该动作分别统计，不能只算已回复的好样本。事件到批结束、批结束到提案、接受到发声、发声到完成分别测；候选批结束到提案P95≤5秒，非已验证承诺。

交付模块、文件CLI或回放命令、策略和prompt版本、模拟提案轨迹、测试集、失败分析、dependencies.md及handoff.md。报告清楚区分C1至C4；只达到C3不能宣称已控制真实直播。完整平台测试、观众数据抓取、自动调价和购物车操作不在本任务中。
