# 统一样例使用说明

这些文件用于让四个研发窗口对齐字段、时间线和算式，不是运营 Agent 代码，也不是实际业务数据。拖鞋参考用户历史资料并作了演示处理；收纳袋为构造商品。历史活动价、物流日期与库存不能直接当成当前销售承诺。

| 文件 | 使用者与用途 |
| --- | --- |
| catalog.json | B/C/A，统一商品快照及未知字段 |
| preparation-request.json | B，原始准备需求，应该自己诊断并生成草稿 |
| preparation-bundle.json | A/C/D，模拟已经发布的准备输入，绕开尚未完成的B以便独立开发 |
| live-state.json | C/A，提案时的模拟播出状态 |
| questions.jsonl | C，问题子集；非完整运行事件流 |
| archive-complete.json | D/A，覆盖模拟场次的完整流程证据，经营数据仍缺失 |
| archive-partial.json | D/A，旧快照和确认缺口形态，不应推断完整答疑 |
| golden-expectations.json | 评测器专用，不能送给待测Agent当答案 |
| scenario-manifest.json | 入口映射及需要实施的故障变体 |

正常时间线：0秒介绍价格；10和11秒出现尺码问题；11秒接受插播；12秒原句结束；20秒答案开始、24秒结束；24至44秒讲材质，25秒出现未知库存问题；44至52秒讲尺码；52至60秒讲第二商品；65秒封存。

三个原始问题合并为尺码与库存两个主题，只有尺码回答完成，覆盖为1/2。尺码两个来源问题到实际回答开始分别等10秒和9秒；平均9.5秒。三个必讲事实分别为拖鞋价格、拖鞋尺码和收纳袋材质，均有完成attempt支持。库存问题只有ask_operator，不构造库存回答或成功动作。

published、approved和人工批准记录仅模拟“批准后的输入”，actor为fixture_operator，来源为simulated。不可复制这些标记到现用直播间冒充真实批准。时间轴是机制测试，不能作为TTS实测时延或真实经营收益。

复建脚本在tools/build_fixtures.py，只写本设计目录，不联网、不访问密钥、不播放声音。A后续将合同落实成严格Schema，若迁移样例，要保存旧版本和变更映射。所有实施窗口先用模拟模式测试，不直接导入当前商品库。
