## 一 阅读入口与范围

下一步先读本文件。原23项是问题与功能的追踪编号，不是执行顺序；本文件的1、2A、2B、3、4A、4B、5、6、7、8是业务步骤。

首期帮助商家在Agent中完成开播前准备。声播提供统一商品库、配置保存、话术生成、语音、播放及人工确认界面。用户可以在Agent对话中补充要求，也可以在声播界面检查修改，不重复填写同一份资料。

| 本轮已确定 | 具体要求 |
| --- | --- |
| 并行关系 | 接收输入后，2A商品资料整理、2B本场配置整理、3顾客场景研究可以并行 |
| 4A产出 | 商品库全部配置项得到处理并保存，不能只交卖点 |
| 4B产出 | 完整上下文关联和话术执行计划，不能只有有损摘要 |
| 生成边界 | 新建时初始化所需模块；更新时明确改哪些模块、保留哪些内容 |
| 操作入口 | Agent组织准备并调用声播服务，声播界面用于人工确认和修改 |
| 决策归属 | 商品、版本、顺序、优惠力度由用户决定 |
| 播报语言 | 简体中文、普通话 |
| 声音选项 | 本机免费普通话和MiniMax可选；DeepSeek作为话术生成服务的模型来源 |

历史范围见[08需求记录](08_业务闭环与动态数据详细设计.md)。与早期顺序描述不一致时，本文件的并行关系、4A完整配置和4B完整上下文要求优先。原始需求取舍仍保留，不因记录旧方案而恢复已排除功能。

## 二 执行顺序与汇合点

| 阶段 | 依赖与执行方式 |
| --- | --- |
| 起点 | 第1步接收输入，识别基本商品身份和资料来源 |
| 三线并行 | 2A、2B、3共享材料与准备记录，允许按单商品逐步推进 |
| 第一次汇合 | 2A＋3进入4A，补齐商品库全部配置 |
| 第二次汇合 | 4A完整商品库＋3研究结果＋2B本场配置进入4B，另读取已有话术、用户决定和已绑定复盘全文/意见 |
| 顺序执行 | 4B计划交给5执行，再由6确定播放安排，6R人工审核精确话术/编排/声音并批准，7准备语音，8统一确认 |
| 局部回流 | 资料、主题、话术、顺序或音色变化，只回到受影响步骤；6发现缺少必要开场文本时回5补写 |

研究至少需要知道商品是什么，并能定位原始材料，不必等待商品库所有字段完成。价格等资料未明确时，可以先分析通用需求；依赖未知价格或未证实功能的判断保留待补。研究结论随关键事实更新而局部校准。

## 四 4A商品库完整配置要求

以下按当前声播字段组织。实施时通过实际schema核对完整字段，避免只依赖此处文字列表。

| 字段组 | 必须逐项处理的内容 | 归属规则 |
| --- | --- | --- |
| 商品身份 | 商品ID、显示编号、SKU、上下架状态 | 系统标识按声播规则生成或沿用；匹配不确定时先确认新增/更新 |
| 基础展示 | 名称、图片 | 图片引用须可读取，名称与商品一致 |
| 规格属性 | 规格名称和值、尺寸/颜色/版型等，材质、成分 | 按资料填写适用字段，不从行业惯例推成商品事实 |
| 适用与使用 | 适用人群、使用说明、限制 | 实际适用信息与营销候选人群分开；研究假设保留在研究记录 |
| 价格 | 币种、日常售价、已有默认价格信息的处理 | 本场覆盖保留在2B；不因普通话播报改变币种 |
| 卖点 | 核心卖点、说明及对应依据 | 2A事实与3需求汇合形成；按现有规范维护唯一有效字段，避免多份卖点不一致 |
| 履约售后 | 发货地、发货说明、退换政策 | 本场特殊安排由2B覆盖，不污染长期资料 |
| 保存条件 | 储存条件、保质期数值和单位等适用内容 | 不适用或未知有明确处理，不能编造 |
| 商品知识 | 知识内容、知识文档及标题、FAQ、注意事项 | 内容可读取、引用正确、关键信息不互相矛盾 |
| 促销归属 | 既有促销资料和价格信息 | 区分长期信息与本场活动；归属不清楚时与2B核对 |

完整性的含义：完整字段均经过处理。必填缺失不能标完成；可选项按规则填写或明确留空；不适用有说明。字段处理状态与来源可以保存在准备记录中，不将未支持的元数据硬写入现有商品接口。

商品记录仍只有一份。2A先形成候选，4A完成并保存；已有商品可直接复用无变化的配置。正式写入通过声播服务，Agent不直接修改数据库。

## 五 4B完整上下文与话术执行计划

### 5.1 输入完整性

| 输入 | 保留内容 | 用途 |
| --- | --- | --- |
| 完整商品库 | 所有配置字段、商品引用、对应版本和来源入口 | 商品事实、报价、知识及可复用卖点 |
| 顾客与场景研究 | 完整结论、需求、顾虑、证据、假设、未知项 | 确定本场如何切入、重点解释什么 |
| 本场配置 | 完整主题/目的、商品范围、优惠/活动、范围/条件/期限、补充知识、播报设置 | 本场定制与活动表达 |
| 已有话术 | 正文、模块、版本关系、可得使用记录 | 判断新建、修改或复用 |
| 用户决定 | 身份确认、事实修订、指定重点、换稿或保留决定 | 限定计划的执行范围 |

原始输入完整保存，计划记录明确引用，执行时能回读。按模块读取相关上下文时，不能只留下无法还原来源的压缩摘要。生成服务须同时取得计划和对应完整输入。重要精确条件应在计划中显式写明。

### 5.2 计划记录

| 每条计划必须回答 | 内容 |
| --- | --- |
| 对谁执行 | 商品引用、目标稿件/版本、基准修订 |
| 改哪一部分 | 长/短开场、商品介绍、卖点、活动、促单、转场等具体模块 |
| 做什么动作 | 新建、修改、复用，或将无效模块停用 |
| 为什么做 | 用户要求、输入变化、缺少稿件或已确认换稿 |
| 依据什么 | 商品字段、研究结果、本场配置的引用与版本 |
| 保留与联动 | 必须保留的正文、允许改动范围、受影响的关联模块 |
| 怎么生成 | 本场对象、场景、重点、表达要求、重要限制 |
| 怎么算完成 | 所需模块齐全，关键条件一致，局改范围符合计划 |

### 5.3 修改范围

| 触发变化 | 首期处理 |
| --- | --- |
| 新商品无稿 | 初始化全部所需模块；无活动时明确该模块不启用 |
| 本场活动/优惠改变 | 默认更新开场和活动；促单等引用旧条件时列为必要联动 |
| 本场主题改变 | 优先调整开场；需要改变主体重点时在计划中明确列出 |
| 商品事实改变 | 更新实际引用该事实的模块 |
| 主体用久且用户同意换稿 | 更新主体讲法，保留有效事实；使用记录未知时不假定已播一周 |
| 仅音色变化 | 话术复用，重新准备对应语音 |
| 仅顺序变化 | 主体复用，重算开场和必要衔接；缺少文本时局部补写 |

只有活动被修改，不能把主体的使用时间一并重置。首期继续复用声播基础检查，不新增独立逐句语义审查Agent。

## 七 首期验收要点

| 步骤 | 验收关注点 |
| --- | --- |
| 1 | 原始材料可定位，任务范围与用户要求一致 |
| 2A | 相似不误覆盖；冲突有来源；局部缺口不阻塞无关商品 |
| 2B | 规则与用户输入一致；过期内容不默认沿用；本场覆盖不污染商品库 |
| 3 | 事实与推测分开；关键资料改变能校准相关结论 |
| 4A | 所有配置字段有处理结果；必填无遗漏；保存回读一致 |
| 4B | 三路输入都保留；旧稿可读；模块动作、边界、依据清楚 |
| 5 | 按计划执行；精确条件一致；未要求改动的内容得到保留 |
| 6 | 用户决定货盘与顺序；商品＋版本每项计数；第1/6/11项长、其余短 |
| 7 | 按实际播放/循环需要准备音频；缓存复用；音频绑定最终修订 |
| 8 | 商品、配置、稿件、顺序、开场和音频一致；问题与准备状态可见 |

顺序重排须重算开场，不能只算第一圈却承诺持续循环。旧任务可贡献有效缓存，不能把旧计划重新激活。本地检查只验证系统行为，不声称证明成交提升。
