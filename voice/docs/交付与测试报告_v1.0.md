# 电商声音直播应用：交付与测试报告

日期：2026-10-07。位置：`D:\Codex project\ecommerce-voice-agent`。本报告更新早期方案中“尚未开发”的状态。

## 1. 交付结果

已经完成一个可以本机运行的网页应用。控制台负责商品与话术、直播配置和播中操作；独立播出窗口输出商品画面、字幕和声音。语言为简体中文、普通话。DeepSeek 负责结构化多版口播生成，声音可在本机慧慧普通话与 MiniMax 间选择。

主链路：商品资料 → 多角度稿件 → 事实提示／人工编辑 → 确认稿件 → 选择播放顺序 → 预生成声音 → 浏览器实际播放 → 监控位置和动作日志。

监控保留商品、话术版本、修订、段落和句子编号；只在播放器回报实际开始／结束后更新播放状态。合成结束不被算作已经播完。固定 `screen-read-region` 提供未来屏幕读取区域，同内容可直接从 `/api/state` 获取。

## 3. 开发中发现的问题及修复

| 问题 | 原因／影响 | 已采取的改进 |
|---|---|---|
| Windows语音线程卡住 | SAPI在后台ASGI线程的COM事件循环不稳定 | 改为独立隐藏子进程在主线程合成，45秒超时，WAV验证后缓存 |
| 上游语音路径依赖ffprobe与分词下载 | 本机没有ffmpeg，首次分词下载无法完成 | 直接读取SAPI原生WAV，使用规则分句；没有关闭下载保护或增加外部模型权重 |
| MiniMax国内地址鉴权失败 | 此Key在国内接口返回2049；不能据此断言Key本身无效 | 核对官方国际接口，真实请求成功，固定使用验证通过的地址 |
| 首次在线TTS有句间等待 | 云端请求耗时可能长于短句播放时长 | 一句预取＋增加开播前预生成；相同文本／音色／模型的轮播复用缓存 |
| 老音频事件可能错推动新队列 | 打断后旧事件仍可能到达 | 每次更换绑定新的Audio实例，检查所有者、epoch和attempt；旧回执忽略 |
| 末句插播恢复边界 | 没有下一句时容易停在准备中，循环场景也需恢复开头 | 普通场次插播后完成，循环场次回到首句；两种情况均有测试 |
| 暂停时误接受结束回执 | 可能发生暂停和ended竞争 | 只有实际playing状态才接受ended推进 |
| 暂停界面的启用声音操作 | 音频和服务端暂停状态需同步 | 明确恢复控制请求，再接受播放回执；失败时停止本地音频 |
| 编辑行包含多句话 | 一行文本可能不等于一句，定位不准确 | 重新按句末标点拆分并生成稳定句子ID |
| 生成稿解释后台实现 | 最初稿件会说“没有接入购物车”等 | 提示词改为消费者表达，未知资料放missing_information；相关实现细节有提示 |
| 提示词不足以保证简体 | 品牌／款式名会沿用源资料繁体 | 新生成的display_text与spoken_text经过OpenCC繁简转换 |
| 改音色影响播中连续性 | 配置变更不能替换已经准备的声音 | 开始场次时冻结provider／voice／model；保存音色用于下一场 |

## 4. 当前边界与后续优先级

### 开始真实测试前要做

1. 在同一电脑把播出URL放入OBS。若另一个浏览器已拥有声音输出，在OBS“交互”窗口接管。先录制30–60秒，检查声画、重复音源和场景切换行为。本次只验证了浏览器，没有控制OBS或开抖音直播。
2. 对真实播出的价格、币种、库存、物流、售后和购物链接重新确认。原截图中的配送9月21–30日没有年份，不能当作当前承诺。178／107是新台币，不因后续选择抖音而自动变成人民币。
3. 用一份自己确认过的长稿跑20–30分钟，再逐步扩到1小时，测音频残留、句间间隔、内存和缓存增长。现有25句稿件约675字，不能声称已经达到单商品6–10分钟。

### 可以继续改进的工程项

- 当前打断会立刻撤销旧播放器；已经送出的云端合成或SAPI子进程可能仍运行至完成／超时，但其结果不会成为过期播放。这会浪费少量等待和调用，后续引入可取消合成任务、优先级和更细缓存锁。
- 手工插播可包含多句话，目前作为一次插播动作显示全文；如果后续要每一句插播都精确定位，应将插播也拆成子队列。
- 事实ID存在及关键词检查不能证明每个断言都正确。后续加币种／价格抽取、规格结构化校验和人工评审案例集，规则与模型评审分别展示。
- 段落重排目前通过队列接口实现；UI主要按版本分组。后续如访谈确认确有需求，可增加段落级拖拽和插播计划可见性。
- 首版是单直播间、本机服务，无多租户权限及云端部署。要远程接入时需另行加入账户、TLS、访问控制和存储策略，不能直接把现有端口开放到公网。
- 1080×1920是推荐OBS设置。本次保存的舞台截图实际浏览器为1280×720，竖屏内容居中且未横向溢出；工具的尺寸覆盖未作用于该隐藏舞台，故1080×1920仍需OBS实机确认。

### 后续Agent验证

先做模拟评论／问题＋真实播出状态的闭环，考察决策、工具调用和恢复。尚未采集观众、留存、订单或GMV，不能用模拟值证明经营提升。
