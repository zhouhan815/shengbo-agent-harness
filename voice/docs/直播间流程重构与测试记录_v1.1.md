# 声播：直播间流程重构与测试记录

更新时间：2026-10-07（上海时间）。本记录补充并更新 v1.0 报告中的 UI 与开播流程。

## 1. 参照产品实际观察

已登录用户授权的公司测试产品，查看首页直播间列表、已有直播间配置、“商品配置 → 添加商品 → 选择商品”弹窗，以及 AI 脚本配置与右侧播放列表。只查看配置，没有保存、生成或开播公司的直播间。

样例流程为：直播间列表 → 进入单个直播间 → 分项配置 → 选择商品库商品 → 准备话术与播放列表 → 直播监控。声播保留这条主流程，剔除数字人、画布装修、图层、平台绑定、套餐与尚未实现的 AI 互动。

## 2. 现在的操作流程

商品库独立维护资料。直播间只保存 product_ids、话术选择与顺序、音色和循环配置，不复制商品的卖点、价格与知识库。多个直播间可以引用同一个商品。移除本场商品不会删除统一商品库。

新建直播间 → 从商品库选择 → 配置音色 → 生成／确认话术 → 勾选本场版本并排序 → 开始直播 → 进入监控 → 复制 OBS 播出链接。

开播自动保存配置。本机试听就在监控页面输出声音；直接 OBS 模式允许先开播，随后接入来源，无来源时显示等待。每个房间有独立的 `/live/{room_id}?output=obs` 浏览器来源地址，可重复用于该房间的后续场次。链接由 OBS 加载画面和音频，再由 OBS 推流到平台；它不是 RTMP 推流地址。

监控内预览使用 `?preview=1`，仅订阅状态，始终静音。OBS 专用来源连接后接管声音，本机播放器停止。当前商品／版本／段落／句子仍由实际播放回执驱动，不用计时器假定播放成功。

首版允许多个直播间保存配置，同一时间只播一个；同一房间重复开播会返回监控，另一房间开播会被拒绝。重启保留配置，播放状态回到未开始。

## 3. 声音问题及修复

旧版在无待播音频时使用静音 AudioContext 解锁，按钮没有明确成功反馈；后续每句话又更换 Audio 元素，先前的点击不一定授权新的元素播放。

新版整场复用一个 Audio 元素，在开播点击手势内解锁它。开播、已连接、合成中、播放中、暂停、等待来源和声音被拦截均有反馈。没有可执行对象时禁用按钮，避免空操作。

浏览器来源被拦截时显示“启用声音”，点击后恢复。另修复手势已经开始播放、恢复请求随后才完成的回执竞态，防止声音播完但状态没有推进。旧 epoch／attempt 的回调不能改变新句状态。接管保留暂停状态；新场解锁不会重播上场的商品音频。

测试过程中还发现 SQLite 上下文原先提交事务后没有显式关闭连接，已修复，避免 Windows 文件句柄占用积累。

## 4. 验证机制与结果

| 环节 | 判断标准 | 实际结果 |
|---|---|---|
| 统一商品库 | 两个房间引用同一商品，商品数不增加，引用不含商品字段副本 | 通过；实际库仍为 1 件商品、2 个直播间配置 |
| 创建与配置 | 新建后进入独立配置、选品后出现已有话术、勾选可保存 | 页面实测通过 |
| 本机开播 | 不另开播放窗口，音频 paused=false、时间推进，服务收到 playing/ended | 通过；11 句短稿完成实际回执 |
| 暂停和插播 | 暂停保持当前位置；立即插播后恢复原稿 | 页面实测通过 |
| OBS 来源协议 | 专用来源接管、本机暂停、暂停状态不被接管解除 | 浏览器加载来源页实测通过 |
| 声音拦截恢复 | 明确出现启用按钮，点击后音频实际播放并继续推进 | 浏览器实测通过 |
| 静音预览 | 监控 iframe 仅以 monitor 订阅，不成为声音 owner | 通过 |
| 直接 OBS 模式 | 无播放器也可开播，显示等待声音来源并生成链接 | 页面实测通过 |
| 多房间互斥 | 第二房间开播被拒绝，第一房间声音不中断 | 页面及自动测试通过 |
| 重启恢复 | 配置、商品引用和所选版本保留，重启后可再次开播 | 实测通过 |
| 自动回归 | 34 项 Python 测试，5 项播放器检查，3 个 JS 语法检查 | 全部通过 |

新增 Python 测试在临时 SQLite 库中运行，不改动用户商品数据。保留了测试准备的“普通话声音直播间”，可用于后续体验。

## 5. 验证边界与下一步

OBS 链接已经是能加载 WAV 声音和竖屏画面的浏览器来源页，并测试了来源接管与自动播放拦截恢复。但本次没有实际完成 OBS 混音器、录制文件或抖音推流测试，不能把浏览器测试等同于平台推流成功。下一步应在 OBS 添加浏览器来源，勾选通过 OBS 控制音频，检查电平并录制 1–2 分钟，确认无双重音源后再测试平台。

本轮没有重新调用 DeepSeek 生成或新增付费 MiniMax 合成测试；生成与云端语音沿用 v1.0 已验证的实现。当前重构主要实际验证本机语音，自动测试另确认每个房间使用各自保存的音色。

后续运营 Agent 要以 room_id 定位控制对象，调用 `/api/rooms/{room_id}/state` 和 `/api/rooms/{room_id}/control`，继续使用 expected_session_id／expected_epoch 防止跨场次或过期操作。商品资料在统一商品库维护，话术版本仍保存生成时的事实快照；资料更新后需重新生成和核对，不能让旧稿自动声称已经采用新价格。本轮没有编写运营 Agent 代码。

## 6. 回退与入口

桌面仍使用“声播”快捷方式，自动启动本地后端并打开首页。更新前代码及 SQLite 备份位于 `runtime/backups/before-room-redesign/`。运行中的旧页面需要刷新，或重新双击桌面快捷方式打开最新界面。
