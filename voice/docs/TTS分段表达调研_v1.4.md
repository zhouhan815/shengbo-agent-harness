# 声播：TTS 分段表达与唱腔问题调研 v1.4

核验日期：2026-10-07。本文区分官方接口能力、我们的设计假设与待试听结果。本次子任务没有请求付费 API，也没有听过生成音频。

## 一、先明确用户报告的问题

用户提供的“你有没有过这种小烦恼：下楼散步、倒垃圾，穿运动鞋太麻烦，穿普通拖鞋又怕走久了脚累”是失败音频对应的文本。用户随后明确：**语音在唱歌，背后有一点杂音**。这不是仅靠改一句文案就能认定解决的问题。

当前代码原先向 MiniMax 发送普通文本，以及固定 `speed=1 / pitch=0 / vol=1`；没有分段情绪，也没有自然语言语音导演提示词。可能影响听感的因素包括模型、音色、文本断句、模型本次采样，以及播放链路；这只是排查范围，尚不能认定根因。

优先保留同一失败句做对照，避免换文本后误判“问题已解决”。先下载原始 WAV 单独试听，再与网页播出对照；若仅网页有杂音，排查同时播放、声卡增益或 OBS 监听回路；若 WAV 自身已有唱腔或噪声，再比较模型、音色和参数。

## 二、官方文档核验

MiniMax HTTP `t2a_v2` 的实际控制项是 `voice_setting`。语速范围 0.5–2、音量大于0且不超过10、音高为 -12–12 的整数。情绪可选 happy、calm 等；2.8 支持常用情绪，但文档对 fluent、whisper 有版本限制，因此本实现不向2.8发送这两个值。未指定情绪时由模型根据文本自动表达。[官方 HTTP 文档](https://platform.minimax.io/docs/api-reference/speech-t2a-http)

文本可以使用换行分段、`<#秒数#>` 停顿标记，另有行内发音及 `pronunciation_dict`。停顿只能位于可发音文本之间，不能连续使用。2.8另支持笑声等语气词标签。当前 HTTP 契约没有通用自然语言 `prompt` 字段，也没有已核实的“禁止唱歌”或“去背景杂音”开关。[官方中文文档](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)

官方提供普通话系统音色列表和 Get Voice API。系统音色名称不能证明某个音色绝不会唱腔；选音色应依赖固定句试听。[官方系统音色列表](https://platform.minimax.io/docs/faq/system-voice-id)

文档的 `pitch` 是整句音高偏移，不能等同于逐词升调、降调曲线。我们在界面显示的 `direction` 是对目标听感的说明，**不会传给 MiniMax，也不会拼进被朗读文本**。真实提交的内容是文本、情绪、语速、音高和音量。没有把“热情、不唱歌”等说明伪装成模型支持的参数。

## 三、分段表达方案

下表数值是首版待试听的保守工程配置，并非官方推荐的电商最佳参数。

| 内容段落 | 目标听感 | emotion | speed | pitch | vol |
|---|---|---|---:|---:|---:|
| 招呼 welcome | 明亮、亲切，句末落稳 | happy | 1.02 | 0 | 1 |
| 引入 pain | 像聊生活问题，有提问感 | 自动 | 0.98 | 0 | 1 |
| 商品亮相 identity | 名称与定位说清楚 | 自动 | 0.98 | 0 | 1 |
| 卖点 benefit / 场景 scene | 具体、有画面感，轻重自然 | 自动 | 1.00 | 0 | 1 |
| 规格 specification | 尺码、颜色和选择建议清楚 | calm | 0.94 | 0 | 1 |
| 价格 price | 价格与币种清楚 | 自动 | 0.94 | 0 | 1 |
| 促销 promotion | 优惠重点鲜明，有感染力 | happy | 1.02 | 0 | 1 |
| 促单 cta | 下一步明确，热情但不喊叫 | happy | 1.02 | 0 | 1 |

不把所有段落都设为 happy，也不靠提升音量制造促单感。针对唱腔投诉，首版所有段落都保持音高0、音量1，先只做小幅语速差和有限情绪变化。规格、价格稍慢的目的在于数字清楚，而非把整段拖长。促单不必越快越好；优惠数字仍放到价格段，促单段只给简短清晰的动作。

**默认自动情绪也不保证没有唱腔，happy 也不保证一定更好。**如果对照试听发现 happy 加重唱腔，该段应回退自动或 calm，调整样式版本并重新生成受影响音频。不能声称一个不存在的“禁止唱歌提示词”已经解决问题。

本机普通话仍可选，但保持原默认读法，**当前适配器不支持分段情绪或升降调控制**。展示段落名称与生成状态，不用 MiniMax 的表现承诺描述本机音色。

按已有逐句 WAV 结构应用段落配置：同一段内各句共享 style，保留每句定位、打断、插播、重新生成能力。文本仍可一次生成完整版本，再以 blocks 展示，不必把文本生成拆成多个请求。现有逐句文件也意味着段落衔接自然度需试听；本轮不自动插入笑声、叹气或大量停顿标签。

## 四、三段固定试听与 A/B 方法

| 样本 | 固定测试文本 | A：原配置 | B：分段配置 |
|---|---|---|---|
| 引入投诉句 | 你有没有过这种小烦恼：下楼散步、倒垃圾，穿运动鞋太麻烦，穿普通拖鞋又怕走久了脚累。 | 自动情绪；speed1/pitch0/vol1 | pain：自动情绪；speed0.98/pitch0/vol1 |
| 卖点讲解 | 这双拖鞋采用一体成型的 EVA 材质，鞋底轻便、软弹，在家走动和日常外穿都可以按自己的需要选择。 | 自动情绪；speed1/pitch0/vol1 | benefit：自动情绪；speed1/pitch0/vol1 |
| 优惠与促单 | 活动价是一百零七新台币。喜欢这款的朋友，先选好自己的颜色和尺码，再查看商品信息下单。 | 自动情绪；speed1/pitch0/vol1 | promotion：happy；speed1.02/pitch0/vol1 |

卖点样本 A/B 参数相同，作为重复合成的稳定性对照，不能把它当作风格改进的因果证明。第一轮固定相同音色与 speech-2.8-turbo，不同时换模型和音色。若失败句仍有唱腔，再单独尝试同音色 speech-2.8-hd 或另一普通话系统音色；用哪种方案由试听决定，不以价格或名称代替判断。

每段保存请求参数、音频文件、时长和试听记录。试听者按下面量表给分，不把文件存在、WAV格式正常当成音质通过。

| 验收项 | 标准 |
|---|---|
| 唱腔 | 0=没有；1=偶发拖腔；2=明显旋律化。必须为0才通过 |
| 杂音 | 0=没有可辨杂音；1=轻微；2=影响理解。必须为0；同时记录是原始 WAV 还是播放链路 |
| 可懂度 | 1–5分，达到4分；数字、币种、尺码不能误读 |
| 情绪匹配 | 1–5分，达到4分；引入自然，促单有感染力但不喊叫 |
| 句尾与衔接 | 1–5分，达到4分；无突兀截断、过长空白、重复播放 |

若有人参与，至少2位独立试听者盲听 A/B 并记录原始打分；若只有开发者试听，应如实写“单人试听”，不能称多人测试。本子任务只提供方案与模拟接口测试，未完成真实听感验收。

## 五、实现契约与缓存

- `app.prosody.sentence_style(sentence, provider='minimax') -> dict`：只按句子的 stage 及别名选择配置，未知 stage 回退 neutral；不执行正文里的风格指令。
- `profile_catalog(provider='minimax') -> list[dict]`：提供前端段落表达说明。字段含 `profile_id/style_revision/label/direction/emotion/speed/pitch/vol/emotion_supported/capability_note`。
- `audio_key / cached_audio / render` 增加尾部可选 `style=None`，原调用不变，原缓存键不变。
- 提供 style 时，实际参数、模型、音色、文本、样式版本与说明一起参与缓存键。参数或样式版本变化后，旧音频不会误算为已生成；不删除旧文件。
- `render / cached_audio` 的响应增加 `style`，内容为过滤后、与实际请求一致的配置。没有 style 的预览继续保持旧行为。
- `speech.resolved_style` 校验参数与模型能力。只允许已确认的情绪值；2.8拒绝 fluent/whisper，未知模型不发送情绪。自然语言说明不进入 HTTP 正文。可选 `pronunciation_dict.tone` 也参与缓存。

初始样式版本 `ecommerce-stage-20261007.1`。未来变更段落默认参数需升级版本。分段样式主要解决表达配置透明及缓存正确性；它不是音质保证，也不代替投诉样本的复现和真人试听。
