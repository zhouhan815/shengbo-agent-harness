## 2. 已有素材与业务重点

样本依据：主项目 `data/samples/slippers.product.json`、`data/samples/slippers.reference-scripts.json`、`docs/样本拆解与监控规范_v0.1.md`，以及已有商品结构。样本商品是含pricing/facts/unknowns的资料分析格式，当前应用ProductInput是另一种表单格式，先做显式输入转换，不能直接假设两者字段相同。输入覆盖商品名、价格/币种、卖点、促销、知识库、图片。语言简体中文/普通话；不需要数字人视频与声音克隆。

首个商品为足弓支撑静音防滑厚底凉拖鞋，178 TWD / 活动价107 TWD。库存、促销结束时间未知；配送9月21日—9月30日缺少年份且不适合直接用于10月7日新场；不能编造主播亲穿、售后全保证、限量和绝不打滑。

输入还应允许用户给本场重点/目标，未给时采用“资料准确、说明清楚、可稳定演示”默认目标并写明，不能虚构GMV目标或观众画像。用两款明确标为演示的数据补充泛化测试，不能改用户真实商品库。

## 3. 要做的流程

1. 解析与字段检查（程序）：建立带版本与出处的事实集合，未知留空。
2. 资料诊断（模型+程序）：矛盾、过期、歧义、无法支持的承诺，输出逐条依据和待补项。
3. 策划（模型）：讲解角度、重点、顺序与必讲点，理由关联事实或明确的用户目标。
4. 内容准备：已有稿件先评估是否能复用；需要时生成多版草稿、FAQ、短回复和未知问题处理方式。版本有不同角度，不只换同义词。
5. 校验（程序+模型）：精确值与引用检查、语义支持检查、重复与遗漏检查。修订最多两轮，失败交给人处理，不能无限自改。
6. 交付：导出符合契约的PreparationBundle及可读简报。未做声播音色/来源实测的预检项写not_checked，默认needs_review。

独立的资料检查、FAQ和版本差异分析可并行；最终汇总等必要节点完成。无需每个节点另创建Agent。模型负责语义选择，日期、引用、版本、排列有效性由程序保证。

准备任务有持久检查点，以plan_id/revision绑定thread；人工确认与外部写入分开。重启后不重复计费生成同一已完成节点，重复任务返回或明确创建新修订；记录Prompt/模型版本和费用/耗时（未知则标未知）。

## 4. 必须交付的工具/输出

只读工具：读取输入商品、检索本商品事实、读取已有稿件、读取已确认SOP。变更先写独立工作草稿，不直接写主项目。

输出至少包括：准备包JSON、缺失/冲突项、讲解简报、版本草稿及事实引用、FAQ、商品/版本顺序、必讲点、预检状态。草稿ID与将来声播script_id分开；导入映射留给适配器。

不要增加无依据的“自动选爆品”“精准人群”“保证转化”能力。联网检索可作第二阶段补充，由来源核查决定能否使用，不能把别家相似商品信息当成本商品事实。

## 5. 验证与评价

先建立三款演示商品、至少20个固定案例；开发样本和保留评测样本分开。包括：资料完整、库存缺失、活动过期、货币不匹配、尺码含糊、事实冲突、无来源售后、过长卖点、旧稿事实过期、事件/资料中的越权指令。

硬门槛：关键价格/币种/尺码零错误；引用存在率100%；固定高风险反例全部检出；未知库存不编造；未确认稿不变approved；同商品至少两版可辨识角度不同；重复运行不覆盖原版。引用存在率和语义支持率分开报告。

人工评价：自然度、版本差异、FAQ实用性、缺失项解释各1–5分，附评语。任务效率以实际手工基线对比，不能预填节省百分比。记录模型失败、重试、延迟、token/费用是否可测；假模型通过与真实模型通过分开说明。
