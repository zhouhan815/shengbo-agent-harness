## 2. 可用的真实测试记录与局限

`D:\Codex project\ecommerce-voice-agent\docs\直播间重构_实际播放记录.json` 保存一次11句短稿测试场次的状态；这是声音应用的实际播放测试，不是有观众和订单的真实电商经营场次。

旧格式中played有收到的ended记录，queue是计划/队列，logs只有近期窗口，缺少完整的逐次播放开始、问题事件、动作参数/提案关联和经营指标。适配成SessionArchive时，缺失项必须标partial/missing、时间为null；不能补造开始时间或把每个队列条目都记为播完。

不能仅靠此样本测完整Agent执行成功率或转化。构造一份完整的模拟归档用于算法测试，再构造缺失/重复/乱序的反例。模拟样本逐条标data_origin；真实播放与模拟问题混合时分别标记。

## 3. 要做的流程

1. 导入与数据审计：验证契约、room/session、版本、时间、ID唯一性及覆盖范围，输出完整性报告。
2. 时间线重建：按真实记录展示播出、插播、重播、取消、人工操作和错误；循环以attempt区分，不按句子ID错误去重。
3. 确定性统计：可观测的播放次数、已完成/取消/失败/未知、缺口、问答匹配、延迟分段；每项明确分母、缺失数、公式和来源。
4. 并行诊断：内容覆盖与重复、问题答复、动作与故障。每个诊断只取必要证据，不共享无限对话。
5. 工具式查证：Agent可按ID或时间范围检索事实、事件、动作、播放尝试；结论只能引用已读取且存在的证据。
6. 输出复盘：观察、假设、建议、验证方法分开；证据不足返回unknown或要求补数据。
7. 输出下一场改进包：FAQ补充、待修订稿、顺序/策略建议和评测反例，每项有base_revision和pending状态。

可以使用分析→检索→草案→规则核查→最多两轮修订的图。阶段任务有持久检查点，以session/archive_revision/review_id定位；重复运行不默默覆写旧报告。导入后只读，避免复盘边分析边改变证据。

## 4. 内容范围

首版：内容/流程复盘、问题和动作的证据关系、可执行下一场建议。经营数据接口保留，但没有业务数据时关闭经营结论。不能把同类问题反复出现解读为真实流失或差评。

## 5. 验证与评价

至少15个固定案例：完整场次、仅旧快照、无问题事件、无经营指标、重复事件、乱序事件、循环同句、插播取消、HTTP接受但没回执、人工切商品、跨场数据混入、价格变更、缺失开始时间、后到数据、新旧话术版本。

硬门槛：统计与确定性基准一致；缺失不默认为0；循环尝试计数正确；引用存在率100%；未观测播放不宣称实际发生；没有订单不计算转化率；无依据原因不当作事实；不写主项目或覆盖批准稿。

人工评价：建议可执行性、证据支持程度、优先级合理性、报告易读性分别1–5分。记录模型不确定与失败；真实模型、假模型、纯程序统计结果分开报告。不要只给一个总体分。
