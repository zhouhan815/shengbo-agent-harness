# 样本拆解与监控规范 v0.1

日期：2026-10-07。仅分析用户提供的截图和文本，不推断公司内部实现。

## 1. 输入输出能确定的东西

两版各有 24 个可见话术卡片。第一版简体、第二版繁体，整体结构高度相似；第二版第 21 段尾部没有完整显示。卡片是讲解段落，不一定是一句话。

| 段落范围 | 第一版 | 第二版 | 我们采用的结构 |
|---|---|---|---|
| 开头 | 欢迎、痛点、个人体验、引入 | 欢迎、痛点、直接介绍商品 | 欢迎与痛点可选；不虚构个人体验 |
| 概览 | 品牌、材质、风格、颜色尺码 | 品牌、四项核心优点 | 商品身份与卖点概览 |
| 展开 | 足弓→厚底→静音防滑→清洁旅行 | 材质→足弓厚底→静音防滑→旅行规格 | 同事实，改变重点和讲解顺序 |
| 转化 | 关注→原价→活动价→售后→期限库存→下单 | 关注→原价→活动价→售后→期限库存→下单 | 优惠依据、必要条件、温和购买引导 |

这支持设计我们自己的模板，不能证明原系统使用了哪一段提示词或参数。参考输出也不能反过来成为商品事实。

## 2. 事实与表达的区别

| 样本说法 | 输入依据 | 处理 |
|---|---|---|
| 原价 178、活动价 107 新台币 | 明确提供 | 数值固定；同币种比较 |
| 足弓支撑、EVA、一体成型、厚底、静音防滑 | 商家提供的产品说明 | 可围绕这些特性讲解，不扩写绝对效果 |
| 我换过七八双、穿了半个月 | 未提供真实体验 | 删除，或用户后续补充真实体验后再使用 |
| 专柜售价、直播间专属 | 未提供销售渠道和排他性 | 只说原价和资料列明的活动价 |
| 下了直播就恢复原价 | 仅有“限时”，没有截止时间 | 不生成明确时点；正式活动状态需确认 |
| 奶白、樱花粉和大码库存紧张 | 有颜色/尺码，没有库存 | 不改名、不制造稀缺性 |
| 零风险试穿、全部售后有保障 | 没有售后条款 | 不生成保证或退换条件 |
| 绝不磨脚、站多久都不胀、不用担心滑倒 | 无证据；浴室知识条目要求小心行走 | 不写绝对承诺，浴室场景保留注意事项 |
| 尺码 36–45 都齐全 | 有 36-37 至 44-45 五组规格 | 准确列规格；不能据此判定全部有现货 |
| 早拍早发货 | 备货 2–8 个工作日 | 不保证快速发货；配送窗口另确认 |

脚型显瘦等卖点可以表达为设计意图/视觉风格，不将体验比喻当成实测结果。商品断言引用资料 ID，欢迎与转场等一般表达可以没有事实引用。

## 3. 两版的设计方向

- 版本 A：居家体验方向。场景从做家务、浴室走动开始，展开足弓、软弹和静音；浴室段保留湿地面注意事项，再讲尺码与优惠。
- 版本 B：外出与便携方向。场景从旅行携带、下楼散步开始，展开轻便、清洁和风格，再补充足弓与规格、优惠。

两版共用一份商品事实。每版都能独立讲清商品身份、相关规格、真实优惠和必要注意事项。初始不同版本至少采用不同主场景和卖点展开顺序，避免只换同义词。持续轮播时开场/转场由场次模板控制，减少重复整场欢迎。

## 4. 数据层级与标识

`商品 → 稿件 → 修订 → 段落 → 句子 → 音频 → 播放尝试`。

- 商品 ID 稳定；版本 A/B 指讲解方案，修订号指该版的具体文本快照。
- 一张卡片对应段落；按完整语义拆成若干播报句，句子单独关联音频。
- 模型输出结构和事实引用，系统分配 ID。修改后创建新修订，正在播放的批准快照不改变。
- 播放尝试有场次 ID、执行序号、音频 ID 与操作 ID。同一句因恢复再次播放，应有新的播放尝试，不能误记为首次连续完成。
- 文本、播报语言、对照译文分别存储；翻译结果也需核对商品事实。
- 稿件状态：参考原稿/测试稿/生成草稿/已批准/已废止。截图参考稿不自动成为已批准稿。

## 5. 监控台的具体显示

固定顶部：场次名、运行/暂停/停止/故障、已播时间、音色、播报语言。

左侧：商品列表，每个商品展开稿件版本与排队顺序；分别显示已完成、正在播、待播、准备中和失败。

中部：商品图片与名称、当前版本及修订号、段落阶段、当前句编号/总句数、当前句全文、音频进度；下方按段落显示完整稿件，当前句高亮，已播句淡化，待播句保持正常。

右侧：手动插播输入、模拟提问/事件、动作记录。显示请求接受、准备音频、正在插播、恢复完成等结果。开始/暂停/停止、下一商品、重排和恢复位置清楚可见。

定位示意（只是设计示意）：

> 足弓支撑凉拖鞋 · 版本 A / 修订 1 · 卖点段 · 第 8 / 30 句 · 正在播放
>
> 「鞋底采用厚底软弹设计，适合喜欢轻便居家风格的朋友。」

“准备中”不抢走当前正在播放句的高亮。插播时顶端明确显示“插播”，保留原稿恢复位置；不把插播误显示成原稿下一句。

## 6. 播放状态与同步

合成状态：未开始 → 合成中 → 音频就绪，或合成失败。

播出状态：待播 → 缓冲 → 实际播放中 → 已播放完成，或暂停/被打断/播放失败。

当前定位由浏览器音频实际进入播放状态后更新；不是由点击“开始”、服务端收单、文本生成或合成完成时更新。音频结束回执后才进入下一句，暂停保留位置。此回执证明客户端播放状态，不保证用户扬声器未静音。

紧急切换时废止旧执行序号的合成与浏览器缓存；旧序号延迟回来的事件不得推进当前高亮。需要从录音和可见状态交叉验证，不只看程序日志。

第一阶段目标：商品/版本/句子定位错配 0 次；停止或切换后旧内容不再次播放；同步误差先以 300 毫秒为验证目标，等待实测。记录首音、句间间隔和中断残留，不预设未经验证的引擎能力。

## 7. 后续屏幕区域读取

预留独立“舞台视图”：只显示商品、版本/修订、段落、句号、当前全文和播出状态，不随控制台滚动；宽度变化时仍保留定位条。

Agent 优先读取同源的只读播放状态。需要演示屏幕读取时，再对这个固定区域截图/OCR，并把识别时间、可信度和失效状态一起记录。OCR 不作为我们播放器定位的主数据源。首版先实现展示区和状态接口，实际跨应用截屏能力另阶段验证。

后续对公司产品的监测可以复用识别逻辑，但不能因为我们自己的状态接口存在，就声称已接入公司产品接口。
