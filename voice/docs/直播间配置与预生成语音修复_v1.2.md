# 声播：直播间配置与预生成语音修复

日期：2026年10月7日。范围：声播网页应用和现有桌面启动入口；未实现运营 Agent。

## 1. 修改后的使用流程

1. 设置声音：直播间名称、普通话音色、声音服务和循环设置。
2. 商品库选品：引用统一商品库中的商品，不复制一套可编辑商品资料。
3. 生成话术：设置每件商品新增1至6版；界面显示商品数、每件数量及总数量。也可只为某件新增。任务生成一版就保存一版并加入本场列表，旧文本保留。
4. 话术顺序与语音：全部在列表中的话术都是本场计划。上下移动排序；删除只移出本场。显示商品编号、第几版、文本确认状态、语音完成状态、句数。用户核对文本后确认。
5. 点击“生成语音（补齐未生成）”：扫描完整本场列表，复用有效文件，生成缺失句子。文本可以先生成语音，但未确认文本仍不能开播。
6. 固定底部的“开播并获取 OBS 链接”检查本场全部文本和语音，再跳转监控。普通话术只播放本地文件，现场插播实时生成。

本机普通话和MiniMax都遵循相同预生成流程。更换音色或模型会采用不同音频标识；切回原音色可复用原文件。编辑文本后只补齐改变的句子，未修改的句子可以复用。同一段音频的准备状态和文本审核状态独立展示。

## 2. 后台任务与真实进度

右上“后台任务”打开右侧非模态抽屉，可关闭并继续配置、查看商品或切换页面。任务在后端执行、逐步写入SQLite，页面每两秒读取进度。相同音频状态不会反复重建话术行，减少操作被轮询打断。

- 文本：每个商品版本是一个生成单元，显示等待、生成中、完成或失败。模型返回前不显示伪造的字数百分比。
- 语音：每版按完成句数显示进度，区分复用与新生成。
- 中途失败：保留已完成文本和音频、准确记录未完成项；语音任务重试只补缺失文件。
- 服务重启：未完成任务标记中断；关闭网页不会取消任务。首版不承诺自动恢复被重启中断的模型请求。
- 并发编辑：保存顺序时保留后台新加入的版本，同时尊重用户明确删除的版本，避免相互覆盖。

## 3. 本地存储与开播规则

常规语音物理存储于 `runtime/room_audio/<room_id>/<audio_hash>.wav`。数据库中保存与直播间、话术、音色关联的逐句音频清单。旧的全局试听缓存只有在生成语音时确认有效后，才复用并放入对应房间目录。

开播前检查：所有本场文本已确认、商品快照未过期、所有句子存在有效WAV文件、同一时间没有其他房间开播。缺失或损坏文件会阻止开播；直播中发现丢失文件会报错，不能悄悄在线补合成。插播拥有显式标识，才允许在播放流程里调用TTS。

修改配置用于下一场，当前场次保留其音色。运行中替换待播稿也要求新稿已确认且对应音频已准备完整。

## 4. 监控与评论区测试台

队列改为全宽紧凑卡片网格，可横向排列、自动换行，限制高度并滚动；当前版本剩余句子不另展示一张重复卡片。主要显示商品编号与版本，逐句监控仍保留。

测试台支持评论、点赞和进入直播间三类事件。事件附带房间、场次、时间和 `source=simulated`，保存在数据库并进入监控。当前不会自动回复、不会自动插播，也没有把模拟观众当作平台真实经营数据。真实评论插件以后需要独立接入；本次未连接抖音或TikTok。

OBS入口仍为开播后生成的本机浏览器来源链接，供OBS采集网页画面和声音。页面与播放器流程验证通过；未实测OBS软件采集、混音或抖音推流。

## 5. 发现并修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 旧播放流程可随播随合成普通话术 | 普通播放改为只读房间音频；测试断言播放全程不调用render |
| 草稿复选框禁用，存在、选择、确认混用 | 移除话术复选框；列表即计划，文本审核状态单列 |
| 删除后可能因重新扫描商品脚本而回来 | 本场维护显式引用列表，不自动回填全部商品话术；刷新实测保留删除；删除全部后不回退旧选择列表 |
| 预生成只有全局状态、没有逐版状态 | 增加持久化任务和逐版语音状态，抽屉显示真实完成数量 |
| 换音色或改稿后可能误认为音频有效 | 按服务、模型、音色、朗读文本和文件有效性检查 |
| 背景生成与保存顺序可能相互覆盖 | 基线列表与明确删除列表合并并发新增，专项测试通过 |
| 旧直播间首页数量与配置列表不一致 | 统一按本场顺序列表计数，现用网页验证一致 |
| 选择生成1版时真实模型未返回对应数量 | 明确JSON结构和精确数量，参考旧版本只用于变化；真实复测得到1版33句，先前失败保留在任务记录 |

## 7. 后续运营Agent接入须知

公共接口新增：`POST /api/rooms/{id}/jobs`（kind=scripts/audio）、`GET /api/jobs`、`GET /api/rooms/{id}/audio-status`、`POST /api/rooms/{id}/test-events`。声音文件通过 `/room-audio/{id}/{hash}.wav` 服务。

新版配置使用 `plan_mode=all`，`script_order`就是全部本场话术，`selected_script_ids`仅保留兼容旧调用的已确认子集。Agent不能通过提交子集跳过完整计划检查。播前输出草稿后，还须完成文本确认和全量语音准备才能开播；播中换稿也要先准备音频。模型提案、任务接受、音频生成、实际播放完成仍是不同状态。

以后可以增加任务取消、仅重试失败的文本版本、批量文本确认和更长场次压力测试；先保留当前逐版人工核对与有证据的播放验收。
